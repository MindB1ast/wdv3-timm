# Готовые TXT и финальные подписи

Эта ветка не требует WD, YOLO или SAM. Подпись — упорядоченный список имён,
с исходными UTF-8 bytes (включая BOM), digest и происхождением каждого тега.
Ручной или неизвестный модели тег не получает выдуманный score.

Чтение по умолчанию `comma_newline`: запятые и переводы строк разделяют теги,
внутренний пробел эквивалентен `_`. Для `blue eyes | smile` выберите
`literal_separator` и `input_separator=" | "`. Входной разделитель независим
от разделителя вывода в Tagging Settings. Пустой или пробельный literal separator
отклоняется: без структуры нельзя восстановить границы `blue eyes long hair`.
`escaped_parentheses=true` читает только `\(` / `\)`, не декодируя другие escapes.

Редактор принимает упорядоченный JSON-список операций:

```json
[
  {"remove": ["watermark"], "remove_regex": ["artist_.*"], "add_after": ["dataset_tag"]},
  {"replace": {"blue eyes": "yellow_eyes"}},
  {"sort": "priority", "priority": ["dataset_tag"]}
]
```

В операции удаление имеет приоритет над добавлением. `replace` буквальный,
regex исполняется только в отдельном `remove_regex`, по полному имени с `_`.
`sort` принимает preserve (default), alphabetical или priority. Порядок остальных
тегов сохраняется, дубли убираются. Редактирование создаёт новый документ в памяти,
исходный TXT меняется только при явном экспорте.

Новая dataset-ветка заканчивается Save Captions: `sub/image.png → sub/image.txt`
рядом с изображением. Для другого каталога задайте `in_place=false,target_root`.
`image_extension_txt` создаёт `image.png.txt`; explicit требует mapping.
Коллизия a.jpg/a.png → a.txt, в том числе с отличием регистра, отклоняется заранее.

Режимы существующего файла:

- error (default): conflict, файл сохраняется.
- skip: прежние bytes сохраняются.
- append: старые теги в прежнем порядке, затем отсутствующие новые.
- overwrite: подготовленная подпись заменяет прежнюю.

Для отсутствующего TXT каждый режим создаёт файл. Append без новых тегов возвращает
unchanged и сохраняет bytes, включая нестандартные пробелы/BOM/переводы строк.
Фильтрация новых предсказаний не удаляет старые теги. Чтобы отредактировать старую
подпись, загрузите её, примените Edit и экспортируйте полный документ через overwrite.
Прежние notebook, Save Result и Tag Folder сохраняют свои defaults.

План экспорта показывает path, before/after, added/removed, ожидаемый digest и
новые bytes, но не пишет TXT. Commit использует отдельный OS-lock для назначения,
проверяет digest, пишет sibling temp с fsync и атомарно заменяет файл. Создание
отсутствующего файла не заменяет конкурентно созданный TXT. Внешняя правка после
preview даёт conflict. Произвольный редактор не участвует в locks; digest проверяется
непосредственно перед публикацией.

operation_id с тем же планом возобновляет запись. Иной план с тем же id — конфликт.
Сбой после replace до подтверждения распознаётся по output digest без повторного append.
После внешней правки уже записанного TXT повтор возвращает conflict. Outcomes:
written/skipped/unchanged/conflict/failed отдельно по файлам. Общей транзакции папки нет;
продолжение файловой записи не требует inference. Evidence остаётся отдельно в `.wdv3`.
