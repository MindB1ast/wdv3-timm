# WDV3 для ComfyUI

Расширение тегирует изображения и папки моделями WD v3, дополняет результат
YOLO-областями и SAM 3.1 с текстовым промптом. Узлы находятся в категории WDV3.

## Установка

Поместите репозиторий в `ComfyUI/custom_nodes/wdv3-timm`. Установите
`requirements-comfyui.txt` Python-интерпретатором ComfyUI и перезапустите сервер.
Этот список сохраняет установленный PyTorch; notebook requirements устанавливать не нужно.
Для новых узлов требуется ComfyUI с V3 API (`comfy_api.latest`).

## Узлы и настройки

| Узел | Назначение |
| --- | --- |
| Load Tagger Model | Все 31 timm-теггера каталога WD v3 / AnimeTimm dbv4-full; repo_id, auto/CPU/CUDA; выходы wd_model и model_info |
| Tagging Settings | Общие/персонажные пороги, размер батчей изображений и областей, форматирование, исключения и добавления |
| Region Tag Rules | Пороги областей; удаление из полного изображения/областей, ручные добавления, подтверждение тегом полного изображения |
| YOLO Detector | Выбор модели, имя источника, confidence, классы; свой путь к весам; входы rules и previous_detectors |
| Load SAM 3.1 | unsloth/sam3.1, устройство, download_missing, необязательная локальная папка |
| SAM Text / Region Settings | Текстовый промпт, confidence, mask_threshold, минимальная площадь, лимит областей, bbox/mask, отступ в пикселях; rules и previous_sources |
| SAM Segment Images | SAM-маски для IMAGE-батча; выходы sam_regions и стандартный combined_mask (MASK) |
| Tag Image / Regions | Теги и JSON для IMAGE; встроенный SAM через sam_model + sources, необязательные detectors/options; выход sam_regions для просмотра |
| Image Folder | Путь, рекурсивность, начальный индекс и лимит (0 = все); только собирает пути |
| Tag Folder | Пакетная обработка папки, необязательные YOLO/SAM; сохранение TXT/JSON |
| Results Viewer | Изображение, области, выбор кадра/источника, теги, оценки; Copy tags и Download JSON |
| Save Result | Сохранение одного результата в TXT/JSON, без Results Viewer; выбор кадра из батча |
| Collect Evidence | Все исходные оценки WD, геометрия и идентичность кадров до порогов; выходы evidence и regions |
| Apply Filters | Повторная фильтрация evidence без инференса; выходы results, tags и results_json |
| Merge Results | Объединение сохранённых результатов одного изображения с проверкой конфликтов |
| Inspect | Один вход results/evidence/regions; интерактивный просмотр, IMAGE, tags и report |
| Export Report | Самостоятельный JSON/HTML/TXT-отчёт с изображениями, вырезками, масками и причинами решений |

Старый Load YOLO Detectors с JSON сохранён для существующих workflow.
В новых схемах используется YOLO Detector с обычными полями.

`options` переопределяет одноимённые настройки на Tag Image / Regions.
`remove_tags` имеет приоритет над ручным добавлением. Списки тегов принимают
запятые и переносы строк. Ручные теги имеют назначенную оценку 1.0.
Пустое поле YOLO classes означает все классы. Источники можно добавлять цепочкой
через previous_detectors / previous_sources; имена YOLO и SAM должны быть уникальны.

### Выбор теггера и входной размер

Список отсортирован по Macro F1@0.40 из ranklist, по убыванию. Модели без
оценки в этом ranklist идут далее по дате публикации, от новых к старым.
После обновления кода перезапустите сервер ComfyUI и обновите страницу:
работающий сервер сохраняет старые определения нод до перезапуска.

В `Load Tagger Model` выберите модель из каталога либо укажите полный `repo_id`:
например, `animetimm/convnextv2_huge.dbv4-full` или
`animetimm/caformer_b36.dbv4-full`. Непустой `repo_id` имеет приоритет над списком
`model`; старые workflow без этого поля продолжают использовать прежний alias.
Полный кадр, YOLO/SAM-регионы и повторное тегирование используют один профиль.
Размер не задаётся общим переключателем: Huge получает `[N,3,512,512]`,
CAFormer B36 — `[N,3,384,384]`, WD ViT — `[N,3,448,448]`.

Первый выход `wd_model` сохраняет тип `WDV3_MODEL`. Дополнительный `model_info`
содержит JSON с repo ID, revision (когда известна), `C,H,W`, цветовым порядком,
операциями preprocessing и fingerprint; его можно подключить к просмотру текста.
Нужные файлы скачиваются только при `download_missing=true`. При выключенном
скачивании полный локальный комплект работает без сети. `local_model_path`
указывает папку комплекта или файл весов в ней; выбираемый repo ID должен
соответствовать этой папке. Подробности и ограничения доступа:
[каталог моделей](tagger-models.md).

### Что делают региональные списки правил

`only_from_source` («Теги только из этого источника») закрепляет теги за источником.
Один тег можно указать у нескольких источников: в итог попадёт максимальная
разрешённая оценка из их областей. Полный кадр и остальные источники этот тег не дают,
даже если владельцы не нашли областей. Владение не добавляет тег принудительно.

`allowed_tags` («Разрешённые теги источника») — отдельный белый список. Если он
непустой, из областей этого источника принимаются только перечисленные теги,
включая ручные добавления. Пустое поле не ограничивает источник. Ratings полного
кадра не меняются. Оба поля сохраняются в workflow и pipeline-конфигах; пробелы
и подчёркивания сопоставляются одинаково. Пороги, удаления и подтверждение полным
кадром продолжают действовать; prefix/suffix не обходят владение.

`full_image_only_tags` задаёт композиционные теги, которые разрешено брать только
из полного кадра. Изначально заполнен прежним списком ограничений; очистка поля
разрешает их из этого источника. Это отдельное ограничение от владельцев и белого
списка. Пресет Full image доступен в Tagging Settings; Generic region, Person,
Face и Custom — в Region Tag Rules. Импорт сохраняет ручные оценки через запись
`tag:score`, а обычный `tag` означает назначенную оценку 1.0.

- `remove_from_full`: при наличии хотя бы одной области этого источника исключает
  перечисленные теги полного кадра из merged-результата. Регионы других источников
  не блокирует. Если областей нет, полный кадр не меняется.
- `remove_from_regions`: запрещает перечисленные теги во всех областях только
  того источника, к которому подключены эти правила. Полный кадр и соседние
  источники не меняет.
- `require_full_confirmation`: список тегов, которые разрешено добавлять из этой
  области только при наличии того же тега среди принятых тегов полного кадра.
  Остальные теги области подтверждения не требуют. Правило не сравнивает оценки,
  не проверяет принадлежность одному объекту и не восстанавливает отсечённые теги.

Например, `helmet` в require_full_confirmation: если регион принял helmet, а полный
кадр нет — региональный тег не попадёт в merged. Если оба приняли — тег разрешён.
Подтверждение использует полный кадр до исключений remove_from_full и финальных
общих remove_tags; итоговый remove_tags всё равно может удалить тег.

Чтобы брать `blue_eyes` только из источника eyes, добавьте его в remove_from_full
источника eyes и в remove_from_regions остальных источников. В eyes его не удаляйте
и не требуйте подтверждения полным кадром, если именно область должна находить
новые детали. При отсутствии областей eyes тег полного кадра остаётся разрешён:
это условная семантика remove_from_full. Для строгого назначения источников
используйте only_from_source: тогда при отсутствии областей fallback не будет.

## Этапы evidence, фильтрации и отчёта

Готовая схема `examples/comfyui_wdv3_evidence.json`:

```text
Load Image + Load Tagger Model + YOLO/SAM → Collect Evidence → Apply Filters → Inspect → Export Report
                                                ↑                 ↑
                                           источники          настройки/источники
```

Collect Evidence сохраняет все WD-оценки, включая нулевые и не прошедшие порог.
Изменение порогов, remove/add, владельцев и белого списка в Apply Filters не
запускает модели. Если те же настройки источников подключены и к Collect Evidence,
его повторный вызов использует ограниченный кэш исходных оценок WD/YOLO. Изменение
изображения, весов, confidence/classes либо геометрии требует нового сбора evidence;
Apply Filters отклоняет несовместимые параметры детекции. SAM имеет отдельный
ограниченный кэш геометрии, поэтому изменение только его теговых правил не
повторяет сегментацию. Кэши принадлежат загруженному WD-ресурсу, не переживают
перезапуск сервера и не удерживают модели на GPU. В памяти остаются до четырёх
снимков WD-кадров и до двух наборов SAM-геометрии на ресурс.

В JSON есть raw_scores, локальные decisions и итоговый список decisions по
источникам. Основные причины: below_threshold, remove_from_regions,
not_in_allowed_tags, owned_by_other_sources, requires_full_confirmation,
remove_from_full, composition_full_only, global_remove, lower_score и merged.
Исходные данные не меняются при фильтрации. Устаревшие старые JSON без raw_scores
не позволяют восстановить отсечённые оценки: требуется один новый запуск модели.

Inspect принимает ровно один типизированный вход: evidence, regions или results.
Поиск работает по тегу, источнику и причине; режимы all/accepted/rejected/raw
и страницы по 50 строк не требуют отрисовки всего вектора. Клик по строке
регионального тега выбирает область. IMAGE-выход содержит рамки; report можно
передать прямо в Export Report без браузера. Results Viewer также показывает
причины, если подключён новый results_json. Пользовательской разметки/фидбека нет.

Export Report создаёт новый каталог `wdv3-<prefix>-<идентификатор>` при каждом
выполнении. JSON включает версии, настройки, исходные оценки, принятые теги,
причины и ссылки на assets; HTML открывается самостоятельно, позволяет выбирать
кадр/область, искать и смотреть оценки; TXT содержит итоговые теги. Assets содержат
изображения оригинального размера, отдельные вырезки и доступные SAM-маски.
Теги и прочие строки отображаются как текст. Для TXT нужен результат после фильтрации
с полным кадром; экспорт геометрии или сырых evidence доступен в JSON/HTML.

Merge Results можно соединять цепочкой. Одинаковые источники дедуплицируются;
различающиеся версии одной ветви, разные изображения, WD-модели и глобальные
настройки фильтрации отклоняются. Все исходные оценки и решения сохраняются,
а merged выбирает максимальный разрешённый score с детерминированным источником.

Переносимые контейнеры имеют schema_version=1 и kind model/regions/evidence/rules/
results/report/text. Их сериализованный снимок неизменяем; чтение возвращает копию.
Идентичность кадра включает RGB-пиксели и размеры, координаты регионов — в оригинале.
Текстовые адаптеры tag_scores/class_label/text могут сохранять текст, модель,
версию, настройки, image/source/region и необязательный score; VLM prompt и параметры
генерации остаются в settings. Свободный текст не канонизируется и не получает
искусственную вероятность. Загрузчики и инференс новых VLM не входят в эту версию.

### Загрузка и ресурсы

Load Tagger Model и YOLO Detector поддерживают download_missing. При выключенной
настройке отсутствие локальных файлов вызывает ошибку без сетевого скачивания.
WD дополнительно принимает local_model_path к папке либо model.safetensors.
YOLO использует custom_model_path. auto выбирает устройство ComfyUI; явно недоступная
cuda вызывает ошибку. WD скачивает только config.json, selected_tags.csv и
model.safetensors. Результат evidence содержит идентичность модели и контрольную
сумму фактических весов; изменение файлов инвалидирует загрузчик.

Перед GPU-этапом освобождается доступная память через ComfyUI model management;
после обработки и при ошибке WD/YOLO возвращаются на CPU, SAM освобождается после
сегментации. Отмена проверяется между изображениями и группами вырезок; уже начатый
вызов модели завершается до следующей проверки. GPU-путь требует отдельной
проверки на GPU; текущая установка использует CPU. Для отключения достаточно
убрать/отключить custom node и перезапустить ComfyUI: данные и веса не мигрируются.

## Схемы

### Несколько YOLO и несколько SAM-источников

`WDV3 Multi YOLO` показывает два независимых детектора (person и face), каждый
со своим Region Tag Rules. Их выходы соединяются через **Combine YOLO Detectors**.
Входы этого узла расширяются при подключении новых источников. Одни и те же
YOLO-веса используются повторно, даже если несколько источников имеют разные
confidence/classes/правила. Веса загружаются только при тегировании.

`WDV3 Multi SAM` содержит **один Load SAM 3.1**, **один Tag Image / Regions** и
три независимых SAM Text / Region Settings:

| Источник | Промпт | Confidence | Вид / контекст |
| --- | --- | --- | --- |
| person_detail | person | 0.60 | mask, без отступа |
| person_context | person | 0.35 | bbox, отступ 32 px |
| cup | cup | 0.45 | mask, отступ 8 px |

У каждого источника свой Region Tag Rules. Выходы подключаются к
**Combine SAM Sources**, затем ко входу sources одного Tag Image / Regions. Модель создаётся
один раз на вызов сегментации; изображение кодируется один раз на SAM-батч,
после чего идут отдельные текстовые проходы для источников. Даже одинаковый
промпт может иметь несколько независимых конфигураций. В JSON и просмотрщике
результаты остаются разделены по source_name; совпадающие теги затем объединяются.
Имена должны быть уникальны во всей схеме YOLO + SAM.

Цепочки previous_detectors / previous_sources продолжают поддерживаться.

### Сохранение конфигураций

**Save Pipeline Config** сохраняет подключённые options, detectors и sources
в `user/default/wdv3/configs/<preset_name>.json`. Вход sam_model сохраняет выбор
SAM-модели, устройство, локальный путь и download_missing. Веса и изображения в файл
не попадают; сохранение не запускает сегментацию и не скачивает YOLO-веса.
При overwrite=false существующий файл защищён от перезаписи.

**Load Pipeline Config** выбирает конфиг из списка и выдаёт четыре выхода:
options → теггер, detectors → теггер, sources и sam_model → Tag Image / Regions или Tag Folder.
Отдельный SAM Loader в схеме From Config не нужен. Старые конфиги с SAM-источниками
без поля sam_model получают стандартные настройки unsloth/sam3.1 / auto / download_missing=true. После сохранения нового
пресета обновите страницу ComfyUI, чтобы обновился список конфигов.

Встроены примеры `multi_yolo`, `multi_sam` и `multi_all`. Готовые workflow
`WDV3 Save Config` и `WDV3 From Config` показывают сохранение настроек через
обычные поля узлов и последующее использование пресета. В Save Config нажмите
Run для сохранения; для обновления существующего файла явно включите overwrite.

### Минимальные схемы

- `Load Image → Tag Image / Regions → Results Viewer`; IMAGE также подключается к images просмотрщика.
- SAM: `Load SAM 3.1 → sam_model` и `SAM Text / Region Settings → sources`
  подключаются прямо к Tag Image / Regions. Его выход sam_regions подключается
  к просмотрщику для выбора и подсветки масок. Отдельная сегментация не требуется.
- SAM Segment Images оставлен для независимого получения MASK или повторного
  тегирования заранее рассчитанных sam_regions. Не подключайте одновременно
  готовые sam_regions и sam_model/sources к одному теггеру.
- Папка: `Image Folder + Load Tagger Model + Tagging Settings → Tag Folder → Results Viewer`.
  Для SAM подключите к Tag Folder sam_model и sources; отдельный SAM Segment Images не требуется.

В `Merged tags` блок `Added from regions` показывает теги, которых не было в
результате полного изображения, с названием источника и номером области.
Нажатие на тег выбирает его область на изображении. В таблицах general/character
также указан источник итоговой оценки: Full image, область или Manual rule.
Теги, для которых область только повысила оценку, не считаются новыми.
Для тегов, добавленных правилами области, источник сохраняется при новом запуске.

Results Viewer: выбор области в списке подсвечивает её на изображении и затемняет
остальное. Клик по изображению выбирает область и её теги. В перекрывающихся
областях повторный клик в одной точке переключает источники по очереди, начиная
с наименьшей области. Для SAM учитывается форма маски, если sam_regions подключён
к просмотрщику; для YOLO и папок без масок используется bbox. Стрелки ←/→
переключают области, Esc снимает выделение.

Результаты — отдельные STRING на каждое изображение, в порядке входов.
Results Viewer получает весь список и позволяет выбирать изображение и источник:
merged/full image/каждая область. preview_limit ограничивает только число
показанных кадров, а не количество обработанных файлов. Для папок превью читает
исходный файл и рисует прямоугольники; для IMAGE можно дополнительно показать SAM-маски.

## Пакетная обработка

У Tag Image / Regions свободный вход `sam_regions` скрывается при подключении
`detectors`, `sam_model` или `sources` и возвращается после их отключения.
Уже подключённый `sam_regions` остаётся видимым: загрузка workflow не обрывает связи.
Готовые SAM-области тегирует WD из входа `wd_model`, используя `rules` каждого
SAM-источника, сохранённые вместе с областями. `view_mode` и `padding_px` задают
вырезку; региональные пороги берутся из этих rules (при незаданных значениях —
из общих настроек). Общие `remove_tags`, prefix/suffix и форматирование применяются
из `options`, а без него — из полей теггера. SAM сам по себе теги не выдаёт.

Для одного результата подключите `Tag Image / Regions.results_json → Save Result.results_json`.
Дополнительно подключите `tags → tags`, чтобы TXT точно сохранял форматирование теггера.
Укажите `output_directory` и `filename` без расширения: сохраняются `<filename>.txt`
и `<filename>.json`. TXT содержит итоговые теги, JSON — полный результат с областями,
оценками и происхождением тегов. `save_txt` и `save_json` включаются независимо.
`result_index=0` выбирает первый результат; для батча можно выбрать другой индекс.
При `overwrite=false` существующий файл вызывает ошибку; смените имя либо включите
перезапись. Выходы `txt_path` и `json_path` содержат пути сохранённых файлов.

Image Folder поддерживает PNG/JPEG/WebP/BMP и разные размеры. Tag Folder
декодирует не более image_batch_size кадров одновременно; WD получает настоящие
тензорные батчи после собственного padding/resize. sam_batch_size отдельно
ограничивает визуальный SAM-батч, region_batch_size — WD-батч областей.
SAM выполняется перед WD для каждой группы. Веса SAM освобождаются после этапа,
WD возвращается на CPU. YOLO использует выбранное device (auto/cpu/cuda) и после этапа возвращается на CPU. Отмена проверяется между группами
изображений и этапами SAM.

TXT/JSON сохраняются в output_directory с относительной структурой входной папки:
`sub/image.png.txt`, `sub/image.png.json`. Исходное расширение сохраняется в имени,
поэтому image.jpg и image.png не конфликтуют. overwrite по умолчанию выключен;
существующие результаты приводят к ошибке до запуска моделей. Уже завершённые
группы сохраняются по мере обработки. Исходные изображения не изменяются.

## SAM 3.1 и загрузка

Источник — https://huggingface.co/unsloth/sam3.1 . По умолчанию download_missing
включён: первый запуск сегментации получает недостающие веса и метаданные в
`ComfyUI/models/sam3/unsloth-sam3.1`. Скачиваются `model.safetensors`, конфигурация,
процессор и токенизатор. FP8/INT8 варианты не скачиваются и этим загрузчиком не поддерживаются.
Если папка полная, сеть не используется. При download_missing=false неполная
папка вызывает понятную ошибку. Можно указать свою папку или model.safetensors.
Также поддерживается локальная папка `models/sam3` внутри расширения.

Loader и Load Pipeline Config подготавливают настройки; файлы скачиваются и веса
размещаются в памяти только на этапе сегментации.
Backend Transformers использует float32, включая CPU. CPU поддерживается, но SAM
требует нескольких гигабайт RAM и может работать долго; начните с sam_batch_size=1.
Маски и bbox используют исходное разрешение; режим mask закрашивает фон белым
перед WD, padding добавляет контекст. Текстовый промпт SAM сам по себе не добавляет тег.

WD и YOLO хранятся в `ComfyUI/models/wdv3/taggers` и `ComfyUI/models/wdv3/yolo`.
Поддерживаются существующие локальные веса в расширении и YOLO в
`ComfyUI/models/ultralytics/bbox` / `segm`. WD с локальным config.json загружается
без запроса конфигурации на Hugging Face.
