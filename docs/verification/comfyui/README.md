`audit/run_comfy_acceptance.py` отправляет четыре исходных TestTagPic в локальный
ComfyUI и выполняет WD ViT v3 + person_yolov8s-seg + face_yolov9c через
Collect Evidence → Apply Filters → Inspect → Export Report, параллельно сохраняя
один результат через Save Result. Используются локальные веса, скачивание выключено.

Все исходные 8106 general scores каждого полного кадра сохранены до порога.
`helmet` из полного кадра отклонён по порогу; из лица — белым списком.
Для второго кадра лицо отсутствует: `remove_from_full=eyelashes` у пустой face-ветви
не удаляет тег. Полный кадр даёт 0.3637557, тег остаётся в merged с provenance full.
Это отличается от владения: `only_from_source` запрещает fallback и при пустой ветви.

Доступные пользовательские иллюстрации Shinobu находятся в самом TestTagPic
(в частности, кадры 1 и 3 распознаны как `oshino_shinobu`). Дополнительного отдельного
файла с таким именем в Downloads или входах ComfyUI не найдено.
Демонстрационные TXT не используются как независимая метрика качества модели.

[acceptance.json](acceptance.json) содержит prompt IDs; отдельные
`acceptance-image-1.json` … `acceptance-image-4.json` сохраняют решения helmet/eyelashes,
число областей, итоговые теги и происхождение. Полные JSON/HTML/TXT с исходными
изображениями и вырезками создаются в `temp/comfy-full-reports/`, единичные результаты
— в `temp/comfy-full-results/`. Эти тяжёлые локальные артефакты не включаются в git.
SHA256 всех исходных файлов TestTagPic проверены до/после: изменений нет.

## GUI, API и автономность

Готовый `WDV3 Evidence` установлен в библиотеке ComfyUI: локальный WD, независимые
person/face, этапы доказательств, фильтров, инспекции и экспорта.
Проверены браузерный импорт выбранного детектора, пресеты, сохранение и восстановление
правил. Повтор GUI-графа через API даёт идентичные теги, решения и настройки:
[gui-api.json](gui-api.json). Экспорт не требует frontend callback.

Инспектор показывает исходные scores, поиск helmet, страницы и причины отклонений,
источник новых региональных тегов и выбор области. [Снимок](inspector.png).
Самостоятельный HTML открыт через локальный HTTP-сервер: поиск возвращает записи
full/face, нажатие строки оставляет записи выбранной области, ссылка ведёт к вырезке;
ошибок JavaScript нет. [Снимок](standalone-report.png).
HTML содержит данные и собственный скрипт; вместе с assets работает без расширения.
Проверка отмены реального задания: [cancellation.json](cancellation.json).

`audit/run_comfy_notebook_acceptance.py` выполняет исходные вычислительные ячейки
ManagingTags через IPython с временной копией изображения. Публичный `BatchTagging`
сохраняет tuple из списков detailed/merged. Comfy API отсутствует в notebook-окружении,
custom_nodes не зарегистрированы; TXT/JSON читаются обычными Python-инструментами.
Исходные файлы не меняются: [notebook.json](notebook.json). Поэтому отключение
custom node не препятствует notebook и чтению сохранённых файлов.

`audit/test_comfy_evidence.py` проверяет счётчиками отсутствие повторного WD/YOLO
при изменении фильтров, инвалидацию изображения/весов/геометрии, неизменяемость
контейнеров, слияние независимых ветвей, конфликты и дедупликацию, сырые оценки,
текстовые адаптеры без искусственных scores, экспорт, маски и отмену.
`audit/test_tag_policies.py` проверяет несколько владельцев, пустые ветви без fallback,
детерминированные равные оценки, whitelist, ручные добавления, композиционные ограничения
и совместимость старых конфигов. `audit/test_comfy_loaders.py` проверяет локальные
загрузчики, запрет сетевых вызовов и переиспользование моделей.
