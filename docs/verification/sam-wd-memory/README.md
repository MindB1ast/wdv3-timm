# SAM и WD: ограничение одновременной памяти

В новом падении Desktop код 0xC0000409 относился к `_safetensors_rust.pyd`. Лог подтвердил успешную загрузку WD Huge и YOLO, затем загрузка SAM прервалась строкой `memory allocation of 2097152 bytes failed`. Checkpoint SAM содержит 1468 BF16-тензоров (1680752748 байт данных); текущий backend загружает их в FP32, примерно удваивая память параметров. Вместе с оставшимся WD Huge и временными буферами загрузки это привело к native allocation failure. Переустановка библиотек не выполнялась.

## Исправление

- Постоянный расчёт исполняет независимые стадии геометрии перед WD full/crops; ключи вычислений не меняются.
- Перед реальным новым SAM-расчётом DeferredWDRuntime освобождает свои CPU-веса, а не только вызывает `.to('cpu')`. Это работает и на следующих изображениях датасета. Готовая SAM-геометрия повторно используется без запуска процесса и выгрузок.
- ComfyUI использует существующий SamWorker, как notebook: SAM получает lossless RGB PNG и возвращает проверенные маски. Временные файлы удаляются после чтения; процесс закрывается до WD. Сохраняются исходные размеры, имена источников, bbox, confidence, mask thresholds и настройки представления.
- Даже если native backend SAM аварийно прекращает работу из-за памяти, SamWorker возвращает SamWorkerError с причиной из stderr. Native abort больше не исполняется внутри процесса ComfyUI. Общесистемную нехватку памяти это не отменяет.

Настройка `low_memory_mode` в WDV3 Tagging Settings управляет освобождением WD перед SAM: включена по умолчанию, выключение оставляет WD в RAM. Процесс SAM изолирован и закрывается в обоих режимах. Переключение не меняет ключи расчёта и не инвалидирует готовый evidence.

## Проверка

254/254 регрессионных теста; проверка типов 38 файлов без ошибок и предупреждений. Проверены порядок SAM→WD, отсутствие лишних вызовов на reuse_only, освобождение и последующая ленивая загрузка WD, реальные worker-протокол/маски/батчи и внезапный выход дочернего процесса с сообщением native allocation failure. Исходные assertions обработки областей и файлов сохранены.

Реальная проверка в Python ComfyUI 3.13.12, Torch 2.12.1+cpu, safetensors 0.8.0, CPU:

1. Загрузка SAM и настоящая сегментация одного RGB-изображения: 88.335 с.
2. Закрытие SAM worker с проверкой завершения процесса.
3. Загрузка ConvNeXt V2 Huge и настоящий WD forward: 56.530 с.

Оба этапа завершились успешно в отдельном проверочном процессе. Большие модели одновременно не удерживались. Это проверка вычислений на одном изображении, не повторение пользовательского workflow целиком. Время не является общим benchmark датасета.

Воспроизведение: `audit/check_sam_wd_memory.py --inference` через Python окружения ComfyUI. Raw-результат проверки: `temp/sam-wd-inference.json`; регрессионный отчёт: `temp/sam-memory-regression.json`.

Для применения в открытом Desktop нужен Relaunch сервера. При небольшом объёме RAM разумно начинать с image_batch_size=1, region_batch_size=1 и sam_batch_size=1.
