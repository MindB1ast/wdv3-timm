# Ускорение повторной обработки тегов

Проверено на живом ComfyUI 0.43.2, CPU, тех же 108 изображениях и 54 графах по два изображения. Пороги WD областей 0.3, confidence YOLO 0.4; полный кадр 0.35/0.75. Использовано прежнее evidence, без инференса.

| Замер | До | После |
|---|---:|---:|
| Суммарное исполнение графов | 1358.086 с | 131.227 с |
| От первого старта до последнего завершения | 1432.295 с | 135.072 с |

Исполнение ускорилось в 10.35 раза. Итоговые теги совпали на 108/108 изображениях; F1 остался 74.27%. Диагностика, причины отбраковки и исходные оценки сохранены. Пакетная отправка убирает задержки клиента; её ускорение отдельно от измеренного исполнения графов.

## Изменения

- Правила источников готовятся перед обходом тегов. Дополнительный проход для regex выполняется только при наличии regex; при редактировании настроек правила готовятся заново.
- Поиск категории использует множество, а проверка наличия тега не создаёт список объяснений. Правила применяются к небольшому принятому набору перед добавлением полных scores и diagnostics.
- Удалены глубокие копии уже принадлежащих текущему этапу снимков. Внутренний JSON компактный; формат переносимых данных и пользовательских экспортов сохранён.
- Bundle передаётся как непрозрачное значение с прежним доступом по ключам, keys/items/values/get и JSON round-trip. Наследование Mapping убрано: RAM-pressure cache ComfyUI иначе рекурсивно декодировал и обходил все оценки и решения после каждой ноды. JSON не содержит тензоров; `_comfy_cache_tensors()` возвращает пустой набор.

## Проверки

248/248 регрессионных тестов; проверка типов 38 файлов без ошибок и предупреждений. Сохранены проверки golden results, regex-причин, ручных тегов, независимости снимков и масштабирования числа подготовок правил относительно размера словаря.

`audit/run_comfy_ram_sizing.py` проверяет реальный RAMPressureCache установленного ComfyUI: декодирований Bundle при сканировании памяти — 0.
