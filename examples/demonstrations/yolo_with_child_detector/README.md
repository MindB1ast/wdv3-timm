# Человек → дочерний детектор лица

Неизменённый пользовательский workflow и сохранённый результат, 2026-11-10.
Откройте workflow.json в ComfyUI. Load Image использует tag_managing1.png.

Соединения: правила лица (12) → YOLO лица (11) → child_detectors правил
человека (7) → YOLO человека (3) → Tag Image / Regions (4) → Save Result (10).
Оба источника названы person; в каскаде они различаются путём ступени.
Дочерний route=separate. У ребёнка allowed_tags_regex:
`.*_eyes`, `.*_mouth`, `.*nose` (каждый на отдельной строке).
Порог ребёнка 0.2, родителя 0.25, полного кадра 0.4.

Save Result получает только tags, save_txt=true, save_json=false, overwrite=true.
В исходном workflow папка абсолютная и принадлежит автору — перед ручным
запуском задайте свою папку, если нужно. Автоматический runner меняет только
назначение сохранения на temp проекта и использует backend из --server.

Ожидаемый текущий общий caption — expected.txt (20 тегов). Это фиксация
сохранённого результата, а не утверждение, что все распознанные теги верны.
В исходном TXT нет региональных оценок/геометрии, поэтому этот пример пока
проверяет общий текст, а не состав каждого региона или маски.

Сравнить сохранённый TXT:
`.venv/Scripts/python.exe audit/run_saved_workflow_demo.py --actual-txt <путь.txt>`

Выполнить граф через запущенный ComfyUI и сравнить:
`.venv/Scripts/python.exe audit/run_saved_workflow_demo.py --server http://127.0.0.1:<порт>`

Нужны доступное в ComfyUI изображение и модели исходного workflow.
Модели/пороги/фильтры не подменяются фиктивными. Runner не исправляет workflow
и не обновляет ожидания. Любое несовпадение завершает проверку с ошибкой.
