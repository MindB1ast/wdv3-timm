# comfyui-regional-workflows Specification

## Purpose

Позволить пользователю строить региональное WD-тегирование в ComfyUI, менять модели и фильтры и получать объяснимый результат каждого этапа без обязательного редактирования конфигурации вручную.

## Requirements

### Requirement: Устанавливаемый набор нод и готовый workflow
Расширение MUST предоставлять ноды загрузки WD, настройки YOLO/SAM-источников, тегирования кадра и регионов, правил, конфигураций и просмотра результатов. Поставляемые workflow MUST использовать штатную загрузку изображения ComfyUI либо загрузку папки и показывать независимую настройку нескольких источников без обязательного редактирования JSON.

#### Scenario: Первый запуск примера
- **WHEN** расширение установлено, модели доступны и пользователь импортирует пример и выбирает изображение
- **THEN** граф исполняется и показывает региональные и итоговые результаты без обязательного написания JSON или Python

### Requirement: Расширяемый контракт текстовых моделей
Архитектура MUST предусматривать адаптеры кастомных классификаторов и VLM наряду с WD multi-label: текст, необязательный score, происхождение, настройки и привязка full/region к YOLO/SAM-источнику. Контракт MUST позволять несколько адаптеров на область. Реализация новых текстовых загрузчиков и их инференса относится к отдельному этапу; SAM-регионы MUST поддерживаться текущим workflow.

#### Scenario: Классификатор как независимый источник
- **WHEN** в контракте описан классификатор для регионов face-детектора
- **THEN** его текстовая метка имеет собственную модель и привязку к региону без обязательного WD или словаря Danbooru

### Requirement: Переносимость текстовых свидетельств
Документированное JSON-представление текстовых свидетельств MUST сохранять исходный текст, настройки модели и привязку к кадру/региону без обязательного score. Свободный текст MUST NOT автоматически проходить Danbooru-канонизацию, разбиение на теги и merge по максимуму вероятностей. Для VLM контракт MUST предусматривать prompt и параметры генерации.

#### Scenario: Текстовая запись без уверенности
- **WHEN** запись содержит свободный текст VLM, ссылку на регион и сведения о модели, но не содержит score
- **THEN** JSON round-trip сохраняет текст, пробелы, пунктуацию и привязку без искусственной уверенности

### Requirement: Явная загрузка моделей
Загрузчики MUST позволять выбирать локальные модели и устройство, показывать сведения о модели и не требовать сети при наличии всех файлов. Отсутствующие файлы MUST вызывать понятную диагностику. Скачивание MUST происходить только при включённой настройке. Загруженная WD-модель MUST переиспользоваться несколькими ветвями графа. Выбор теггера MUST поддерживать общий каталог и полный repo ID с сохранением старых aliases; сведения MUST включать фактические `C,H,W`, цветовой порядок и источник preprocessing.

#### Scenario: Локальные веса без сети
- **WHEN** все файлы выбранной модели находятся в подключённом каталоге, а скачивание выключено
- **THEN** загрузчик работает без сетевого запроса и возвращает модель для полного кадра и регионов

#### Scenario: Явно выбран недоступный GPU
- **WHEN** пользователь выбирает `cuda`, но CUDA недоступна
- **THEN** загрузчик сообщает о недоступном устройстве, не выдавая CPU-исполнение за GPU

#### Scenario: Выбор AnimeTimm в сохранённом workflow
- **WHEN** пользователь выбирает AnimeTimm из каталога либо вводит полный repo ID и сохраняет workflow
- **THEN** после открытия восстанавливается та же модель, её входной профиль используется всеми ветвями, а сведения показывают repo ID, размер и preprocessing

#### Scenario: Старый workflow
- **WHEN** открывается workflow с прежним alias без нового поля repo ID
- **THEN** сохраняются прежнее назначение модели и подключение выхода `WDV3_MODEL`

### Requirement: Изображение и геометрия областей
Ноды MUST принимать IMAGE-батч, сохранять порядок кадров и привязку каждого результата и региона к своему изображению. Области MUST сохранять имя источника, идентификатор региона и bbox в координатах оригинала; SAM-результат MUST сохранять маску и оценку сегментации. Вырезки MUST формироваться из входных пикселей без предварительного уменьшения всего изображения.

#### Scenario: Несколько входных изображений
- **WHEN** пользователь передаёт IMAGE-батч из нескольких кадров
- **THEN** теггер возвращает отдельные теги и JSON для каждого кадра в исходном порядке, а просмотрщик позволяет выбирать кадр

#### Scenario: Регионы разных размеров
- **WHEN** детектор находит несколько областей разных размеров
- **THEN** система сохраняет отдельные вырезки и координаты каждой без растягивания до общего размера ради хранения

#### Scenario: Областей нет
- **WHEN** детектор не находит объектов при заданных параметрах
- **THEN** он возвращает валидный пустой результат, доступный для просмотра и дальнейшего объединения

### Requirement: Свидетельства до фильтрации
Тегирование MUST предоставлять оценки до пользовательских порогов отдельно по полному кадру, источнику, региону и категории тега. Применение фильтров MUST сохранять исходные оценки и причины принятия или отклонения. Просмотр результата фильтра MUST NOT подменять исходные предсказания.

#### Scenario: Тег ниже порога
- **WHEN** `helmet` получил оценку ниже заданного порога
- **THEN** инспектор позволяет найти исходную оценку и причину отклонения, хотя тег отсутствует в итоговом caption

### Requirement: Удобная настройка фильтров
Пользователь MUST иметь возможность менять пороги и списки удаления, добавления, подтверждения полным кадром и композиционных ограничений через подписанные поля и пресеты. Теги с пробелами и подчёркиваниями MUST сопоставляться канонически. Ошибочные значения MUST диагностироваться до применения. Ручное добавление MUST отличаться от предсказания модели.

#### Scenario: Исключение ошибочного шлема
- **WHEN** пользователь добавляет `helmet` в удаляемые теги регионов лица
- **THEN** новый результат отклоняет этот источник тега с указанием правила и сохраняет исходную вероятность

#### Scenario: Неоднозначный конфликт ручных правил
- **WHEN** один тег одновременно указан в remove и add той же ветви
- **THEN** remove имеет приоритет и конфликт отображается в диагностике

### Requirement: Сохранение и перенос правил
Все действующие настройки MUST восстанавливаться из workflow. UI MUST поддерживать импорт правил выбранного детектора из существующего `detectors.json` и экспорт пресета. Импорт MUST показывать перенесённые значения и параметры детекции, требующие отдельного назначения, без скрытого изменения других нод.

#### Scenario: Повторное открытие workflow
- **WHEN** пользователь сохраняет граф с изменёнными фильтрами и открывает его снова
- **THEN** значения и поведение восстанавливаются без зависимости от прежнего состояния браузера

### Requirement: Исключительный источник тегов
Региональные правила MUST позволять закреплять general/character-теги за одним или несколькими именованными источниками YOLO/SAM. Такие теги MUST приниматься только из областей перечисленных владельцев, без полного кадра и других источников. Повтор тега у разных владельцев MUST быть допустим. При отсутствии принятого тега у всех владельцев итог MUST исключать тег без fallback; остальные теги MUST сохранять обычные правила.

#### Scenario: Глаза не обнаружены
- **WHEN** теги глаз назначены исключительно ветви глаз и областей нет
- **THEN** итог не принимает теги глаз из полного кадра или других региональных ветвей и объясняет это политикой источников

#### Scenario: Несколько владельцев одного тега
- **WHEN** blue_eyes закреплён за eyes и face и оба источника приняли его
- **THEN** конфигурация валидна, тег появляется один раз с максимальной разрешённой оценкой и её источником, независимо от порядка подключения владельцев

#### Scenario: Один из владельцев не принял тег
- **WHEN** eyes не нашёл областей либо не принял blue_eyes, а второй владелец face принял его
- **THEN** merged может принять тег от face, но не из полного кадра или источников вне списка владельцев

#### Scenario: Пороги и удаления владельца сохраняют силу
- **WHEN** тег закреплён за eyes, но не прошёл порог либо удалён его правилами
- **THEN** владение не добавляет тег принудительно и не разрешает его из других источников

#### Scenario: Владение относится ко всему источнику
- **WHEN** eyes нашёл несколько областей, а blue_eyes указан в списке владения eyes
- **THEN** тег разрешён из любой принятой области eyes; владение не выбирает отдельный экземпляр области

#### Scenario: Ручные добавления не обходят владельцев
- **WHEN** тег закреплён за eyes, но добавлен ручным правилом другого источника либо общим prefix/suffix
- **THEN** такое добавление не обходит ограничение владельцев, а общие удаления продолжают иметь приоритет

### Requirement: Повторная фильтрация без инференса
При неизменных изображении, моделях и параметрах детекции изменение порогов или фильтров MUST повторно использовать оценки в текущем графе без повторного запуска WD/YOLO. Изменение изображения, модели или параметров детекции MUST обновлять соответствующие свидетельства, не используя несовместимый кэш.

#### Scenario: Понижение порога
- **WHEN** пользователь понижает порог и повторяет выполнение без других изменений
- **THEN** ранее отсечённые оценки становятся доступны для принятия без повторного инференса

### Requirement: Объединение нескольких ветвей
Объединение MUST поддерживать полный кадр и несколько именованных ветвей одного изображения и давать одинаковый результат при перестановке ветвей. Список исключений полного кадра MUST суммироваться по непустым ветвям. Повтор одинаковой ветви MUST NOT дублировать теги; конфликтующие данные одного источника и разные изображения MUST отклоняться.

#### Scenario: Пустое лицо не удаляет ресницы
- **WHEN** лицо не обнаружено, его правила содержат удаление `eyelashes` из полного кадра и исключительное владение этим тегом не задано
- **THEN** это правило не удаляет тег полного изображения

#### Scenario: Перестановка человека и лица
- **WHEN** пользователь меняет порядок соединения непустых ветвей человека и лица
- **THEN** итоговый набор тегов и применённые правила остаются теми же

### Requirement: Композиция и согласованность текста
Региональные композиционные ограничения MUST препятствовать переносу локальных `1girl` или `close-up` в глобальное описание при соответствующем правиле. Итоговые текст и словари MUST строиться из одного принятого набора general/character. Ratings MUST сохраняться отдельно из полного кадра. Экспорт глобального caption MUST требовать результат полного кадра.

#### Scenario: Лицо выглядит крупным планом
- **WHEN** область лица предсказывает `close-up`, а правило разрешает этот тег лишь для полного кадра
- **THEN** результат не добавляет региональный `close-up`, и инспектор показывает причину

#### Scenario: Персонаж определён только полным кадром
- **WHEN** персонажный тег принят с полного кадра и не исключён правилами
- **THEN** он присутствует и в итоговом словаре character, и в caption/taglist

### Requirement: Инспекция каждого этапа
Инспектор MUST показывать результат детекции, исходного тегирования, фильтрации и объединения: рамки, вырезки, источник, score, категорию и причины решений. Для итогового результата MUST показываться добавленные и удалённые относительно полного кадра теги. Поиск и выбор региона MUST позволять рассматривать подробности без обязательного экспорта отчёта.

#### Scenario: Разбор ошибочного тега
- **WHEN** пользователь выбирает `helmet` в итоговом результате
- **THEN** он видит регион лица, его вырезку, исходную оценку и правила, допустившие тег

### Requirement: Явный экспорт результата
Нода экспорта MUST сохранять выбранные JSON/HTML/TXT в output ComfyUI без записи рядом с исходником и перезаписи существующих файлов. JSON MUST включать настройки и происхождение; HTML MUST включать просмотр областей; TXT MUST содержать итоговый caption. HTML MUST безопасно отображать теги как текст.

#### Scenario: Повторный экспорт
- **WHEN** пользователь дважды выполняет граф с экспортом
- **THEN** создаются отдельные результаты, а исходные изображения и TXT остаются неизменными

### Requirement: Исполнение без интерактивного браузера
Вычислительные ноды, инспектор и экспорт MUST исполняться через API ComfyUI без обязательных frontend-callback. Сериализованные настройки MUST давать тот же вычислительный результат, что и интерактивный workflow.

#### Scenario: API-запуск сохранённого графа
- **WHEN** тот же граф и значения входов отправлены через API
- **THEN** возвращаются согласованные теги и машиночитаемый отчёт без ожидания действий браузера

### Requirement: Совместимость установки и notebook-сценария
Расширение MUST документировать проверенные версии ComfyUI и окружения и устанавливать только необходимые дополнительные зависимости без принудительной замены PyTorch ComfyUI. Существующий вызов `BatchTagging` и структура его возвращаемого результата MUST сохраняться. Исправления фильтрации MUST быть описаны как изменения корректности, а не скрыты как точное воспроизведение старых ошибок.

#### Scenario: Установка рядом с существующим ComfyUI
- **WHEN** пользователь устанавливает зависимости расширения по инструкции
- **THEN** установка не требует применения полного notebook requirements поверх ComfyUI, а инструкция содержит проверенный smoke-сценарий

### Requirement: Независимые настройки нескольких источников
Workflow MUST поддерживать несколько YOLO-детекторов и несколько SAM-источников с независимыми именами, порогами, правилами и настройками областей. Одинаковые веса MUST переиспользоваться. Имена MUST быть уникальны среди YOLO и SAM; конфликт MUST вызывать понятную ошибку. Пустой список YOLO classes MUST означать все классы.

#### Scenario: Одинаковый SAM-промпт с разным контекстом
- **WHEN** пользователь подключает два источника с промптом `person`, но разными confidence, bbox/mask, отступами и правилами
- **THEN** один workflow сохраняет оба источника раздельно и применяет правила каждого независимо

#### Scenario: Несколько YOLO с общими весами
- **WHEN** два именованных YOLO-источника используют одни веса с разными classes или confidence
- **THEN** результаты остаются раздельными, а веса не загружаются повторно для каждого источника

### Requirement: SAM внутри тегирования
`Tag Image / Regions` и `Tag Folder` MUST выполнять SAM при подключённых sam_model и sources без обязательной отдельной сегментации. IMAGE-теггер MUST также принимать готовые sam_regions и отдавать области просмотрщику. Одновременное подключение готовых областей и встроенного SAM MUST отклоняться. Отдельная сегментация MUST оставаться доступной для получения MASK и повторного использования областей.

#### Scenario: Прямое подключение SAM к теггеру
- **WHEN** модель SAM и текстовые источники подключены прямо к `Tag Image / Regions`
- **THEN** теггер получает области и теги, а его sam_regions позволяет просмотрщику показывать маски

#### Scenario: Несовместимые способы получения областей
- **WHEN** теггер получает sam_regions одновременно с sam_model или sources
- **THEN** выполнение сообщает о конфликте вместо повторной сегментации или скрытого выбора входа

### Requirement: Скачивание недостающих файлов SAM
Настройки SAM MUST поддерживать `unsloth/sam3.1`, устройство, локальную папку и download_missing. Сохранение и загрузка настроек MUST NOT запускать скачивание или сегментацию. При обработке с включённым скачиванием MUST загружаться только недостающие необходимые файлы; полная локальная модель MUST переиспользоваться.

#### Scenario: SAM отсутствует при первом выполнении
- **WHEN** выбран `unsloth/sam3.1`, нужных файлов нет и download_missing включён
- **THEN** перед сегментацией загружаются недостающие файлы модели

#### Scenario: Офлайн-исполнение SAM
- **WHEN** download_missing выключен и требуемых локальных файлов нет
- **THEN** выполнение сообщает об отсутствующей модели без попытки скачать её

### Requirement: Полный пресет регионального workflow
Сохранённый конфиг MUST включать общие настройки тегирования, YOLO-источники, SAM-источники, их правила и настройки SAM-модели. Загрузка MUST выдавать options, detectors, sources и sam_model без обязательного отдельного SAM Loader. Сохранение MUST защищать существующий пресет при overwrite=false и MUST NOT включать веса или изображения.

#### Scenario: Работа SAM из конфига
- **WHEN** пользователь загружает сохранённый SAM-пресет
- **THEN** его sources и sam_model подключаются прямо к теггеру и восстанавливают выбор модели, устройства, пути, скачивания и правила источников

#### Scenario: Старый конфиг без настроек SAM-модели
- **WHEN** конфиг содержит SAM-источники, но не содержит sam_model
- **THEN** загрузка использует `unsloth/sam3.1`, auto и download_missing=true

### Requirement: Обработка папки ограниченными батчами
Загрузка папки MUST позволять задать путь, рекурсивность, начальный индекс и лимит, где 0 означает все файлы. Обработка MUST ограничивать батчи изображений, регионов и SAM независимо, сохранять порядок результатов и поддерживать TXT/JSON. Сбор путей MUST NOT запускать загрузку моделей или инференс.

#### Scenario: Папка с разными размерами изображений
- **WHEN** пользователь обрабатывает папку с изображениями разных размеров и заданными размерами батчей
- **THEN** изображения обрабатываются ограниченными порциями, а результаты остаются связаны с исходными путями

### Requirement: Интерактивный выбор области без исчезновения рамок
Results Viewer MUST синхронизировать выбор области в списке и кликом по изображению. Выбранная область MUST подсвечиваться, а рамки остальных областей MUST оставаться видимыми. Для доступных SAM-масок выбор MUST учитывать форму маски; иначе используется bbox. Повторный клик MUST переключать перекрывающиеся области; стрелки MUST выбирать области, Esc MUST снимать выделение.

#### Scenario: Первый клик по области
- **WHEN** пользователь нажимает на область изображения
- **THEN** она подсвечивается, список и теги переключаются на неё, а остальные рамки не исчезают

#### Scenario: Перекрывающиеся области
- **WHEN** пользователь повторяет клик в той же точке пересечения областей
- **THEN** выбор циклически переключается между попавшими под клик областями, начиная с наименьшей

#### Scenario: Снятие выделения
- **WHEN** пользователь нажимает Esc или кликает вне областей
- **THEN** выделение снимается, а рамки областей остаются видимыми

### Requirement: Устойчивый лимит просмотра
preview_limit MUST ограничивать только число показанных кадров, без ограничения обработки. При восстановлении workflow пустое или отсутствующее значение MUST заменяться на 16. Значение 0 MUST показывать все результаты без ограничения 256 кадрами. Интерактивная отправка MUST передавать целое от 0 до 256, сохраняя корректное пользовательское значение после выполнения просмотрщика.

#### Scenario: Старый workflow с пустым лимитом
- **WHEN** Results Viewer восстанавливается с preview_limit, равным пустой строке
- **THEN** интерфейс использует 16 и первый и повторный запуск не завершаются ошибкой преобразования INT

#### Scenario: Все результаты папки
- **WHEN** передано 300 результатов и preview_limit=0
- **THEN** доступны все 300 результатов, а не только первые 16 или 256; выбор влияет только на просмотр и не требует нового инференса

#### Scenario: Сохранение положительного лимита
- **WHEN** пользователь задаёт preview_limit=16 либо 256
- **THEN** показываются первые N результатов с отдельным общим числом, а сохранение и расчёт остальных изображений не ограничиваются

### Requirement: Происхождение тегов в Merged tags
Results Viewer MUST показывать новые региональные теги в открытом блоке `Added from regions` с именем источника и номером области. Клик по тегу MUST выбирать область. Таблицы general/character MUST показывать источник итоговой оценки. Тег, уже присутствующий в категории полного кадра, MUST NOT считаться новым лишь из-за повышения оценки областью.

#### Scenario: Новый тег из области
- **WHEN** принятый merged-тег получен из области и отсутствовал в той же категории полного кадра
- **THEN** блок новых тегов показывает тег и его область, а нажатие подсвечивает эту область и выбирает её в списке

#### Scenario: Повышение оценки существующего тега
- **WHEN** тег присутствовал в полном кадре, а область дала более высокую принятую оценку
- **THEN** таблица указывает область как источник оценки, но блок новых тегов не считает тег добавленным

#### Scenario: Ручной тег из правил области
- **WHEN** правило области добавляет тег, который принят в merged-результат
- **THEN** результат сохраняет manual_rule и region_source, а просмотрщик показывает источник области и пометку rule

#### Scenario: Ручной тег общего результата
- **WHEN** тег добавлен общим правилом без регионального источника
- **THEN** просмотрщик обозначает его как Manual rule и не приписывает области

### Requirement: Сохранение одного результата отдельной нодой
Нода `Save Result` MUST сохранять один выбранный результат в TXT и/или JSON без Results Viewer. Пользователь MUST задавать каталог, имя без расширения, result_index и разрешение перезаписи. Нода MUST возвращать пути созданных файлов. JSON MUST сохранять полный переданный результат; TXT MUST использовать подключённые tags либо итоговый текст merged_tags с сохранёнными настройками вывода.

#### Scenario: Один результат без просмотрщика
- **WHEN** results_json и tags подключены от теггера к Save Result, оба формата включены и файл ещё не существует
- **THEN** создаются `<filename>.txt` с точной строкой tags и `<filename>.json` с полным результатом, а выходы содержат пути к ним

#### Scenario: Выбор результата из батча
- **WHEN** передан список результатов и result_index указывает на один из них, начиная с 0
- **THEN** сохраняется только выбранный результат и соответствующая строка tags

#### Scenario: Сохранение без входа tags
- **WHEN** подключён только results_json и включён TXT
- **THEN** TXT содержит итоговый текст выбранного merged_tags с сохранёнными настройками вывода; для старого JSON без настроек используется taglist либо caption при отсутствии taglist

#### Scenario: Защита существующих результатов
- **WHEN** overwrite выключен и хотя бы один из выбранных файлов уже существует
- **THEN** нода сообщает об ошибке до записи любого файла, сохраняя существующее содержимое

#### Scenario: Явная перезапись
- **WHEN** overwrite включён и целевые файлы существуют
- **THEN** выбранные файлы заменяются результатом текущего сохранения

#### Scenario: Неверные параметры сохранения
- **WHEN** индекс вне списка, длины tags и results_json различаются, оба формата выключены либо имя содержит путь или недопустимое имя файла
- **THEN** нода сообщает о неверных параметрах до создания выходных файлов

### Requirement: Белый список тегов источника
Региональные правила MUST предоставлять отдельный белый список разрешённых general/character-тегов источника. Непустой список MUST ограничивать принимаемые из всех его областей теги, включая ручные добавления; пустой MUST означать отсутствие этого ограничения. Список MUST NOT добавлять теги принудительно или менять соседние источники и ratings полного кадра. Владение и белый список MUST применяться совместно, без обхода порогов, удалений и подтверждения полным кадром.

#### Scenario: Принимать только перечисленные теги
- **WHEN** белый список eyes содержит blue_eyes и red_eyes, а область также предсказывает blonde_hair
- **THEN** из eyes разрешены только принятые blue_eyes и red_eyes; blonde_hair может прийти из другого разрешённого источника

#### Scenario: Пустой белый список
- **WHEN** список разрешённых тегов источника пуст либо отсутствует в старом конфиге
- **THEN** источник принимает теги по прежним правилам без дополнительного ограничения

#### Scenario: Владение не является белым списком
- **WHEN** eyes владеет blue_eyes, его белый список пуст и он принял eyelashes
- **THEN** источник может передать оба тега; закрепление blue_eyes не ограничивает остальные теги eyes

#### Scenario: Пересечение владения и белого списка
- **WHEN** blue_eyes закреплён за eyes и face, но белый список eyes не содержит его, а белый список face содержит
- **THEN** eyes не передаёт тег, face может передать его по своим правилам, остальные источники и полный кадр по-прежнему запрещены

#### Scenario: Белый список не принуждает добавление
- **WHEN** тег указан в белом списке, но отсутствует в предсказании или не проходит другие правила источника
- **THEN** один факт присутствия в списке не добавляет тег в результат

#### Scenario: Ручной тег вне белого списка
- **WHEN** add_to_regions содержит тег, не входящий в непустой белый список того же источника
- **THEN** этот ручной тег не принимается из источника

### Requirement: Перенос настроек владения и белого списка
UI MUST предоставлять раздельные поля владения тегами и белого списка в Region Tag Rules с одинаковой канонизацией пробелов и подчёркиваний и дедупликацией. Workflow и pipeline-конфиги MUST сохранять оба списка для каждого YOLO/SAM-источника. Старые настройки без этих списков MUST означать отсутствие владения и ограничений белого списка; API MUST применять ту же политику, что UI.

#### Scenario: Сохранение нескольких владельцев и ограничений
- **WHEN** пользователь сохраняет и повторно загружает конфиг с общим тегом у двух владельцев и разными белыми списками
- **THEN** оба владельца и оба списка восстанавливаются без ошибки конфликта, а поведение совпадает с сохранённым workflow и API

#### Scenario: Канонические имена тегов
- **WHEN** в списках присутствуют blue eyes и blue_eyes
- **THEN** они обозначают один тег без дублирования, как в остальных правилах тегирования

### Requirement: Общие настройки через options
Tag Image / Regions MUST предоставлять только подключения данных, моделей и options, без локальных виджетов тегирования и вывода. Глобальные пороги, правила, prefix/suffix, формат текста и размеры батчей MUST задаваться в Tagging Settings и сохраняться через options в pipeline-конфиге. Без options MUST использоваться стандартные значения.

#### Scenario: Единое место настройки
- **WHEN** пользователь добавляет Tag Image / Regions и подключает Tagging Settings
- **THEN** настройки редактируются только в Tagging Settings, а нода обработки не дублирует поля, включая tag_separator и sam_batch_size

#### Scenario: Старый workflow без options
- **WHEN** загружается UI-workflow с локальными настройками теггера и без подключённого options
- **THEN** локальные настройки переносятся в новую подключённую Tagging Settings

### Requirement: Явный синтаксис буквальных тегов
Подсказки Tagging Settings и Region Tag Rules MUST объяснять эквивалентность пробелов и `_`, разделение списка запятыми или переводами строк и буквальное значение regex-метасимволов. Пробел внутри имени MUST NOT разделять теги. Поля ручных добавлений MUST явно описывать поддерживаемый формат оценки.

#### Scenario: Два способа записи имени
- **WHEN** список содержит `blue eyes, blue_eyes` и отдельной строкой `long hair`
- **THEN** правила получают два уникальных канонических тега `blue_eyes` и `long_hair`

#### Scenario: Метасимволы в обычном поле
- **WHEN** в обычном поле указан `.*_eyes` или `character_(series)`
- **THEN** значение сопоставляется только с буквальным каноническим именем и не выполняется как regex

### Requirement: Изолированные regex-поля правил
Для удаления из полного кадра и областей, подтверждения полным кадром, владения, белого списка, композиционных ограничений и глобального удаления UI и API MUST предоставлять отдельные regex-поля. Шаблоны MUST сопоставляться со всем каноническим именем general/character-тега с `_`, с учётом регистра. Добавление тегов, prefix и suffix MUST оставаться буквальными.

#### Scenario: Группа тегов
- **WHEN** regex белого списка содержит `.*_eyes`
- **THEN** ему соответствуют `blue_eyes` и `red_eyes`, но не `blue_eyes_extra`

#### Scenario: Пробел внутри шаблона
- **WHEN** regex содержит `blue eyes`
- **THEN** он не преобразуется в `blue_eyes` и не совпадает с этим каноническим именем

#### Scenario: Формат списка шаблонов
- **WHEN** пользователь вводит по одному шаблону на строку, включая `a{1,3}` и `(?:blue|red)_eyes`
- **THEN** запятая остаётся частью шаблона, пустые строки игнорируются и шаблоны не проходят канонизацию тегов

### Requirement: Согласованное применение буквальных и regex-правил
Литералы и regex одного действия MUST объединяться по OR без повторного добавления тегов. Непустой белый список любого вида MUST включать ограничение даже при отсутствии совпадений. Пересечение действий MUST сохранять пороги, приоритет удаления, подтверждение полным кадром, композиционные ограничения и совместное владение. Regex MUST NOT добавлять теги или менять исходные оценки.

#### Scenario: Отсутствие совпадений белого списка
- **WHEN** буквальный белый список пуст, regex задан и не совпадает ни с одним тегом
- **THEN** источник не передаёт general/character-теги, включая ручные добавления

#### Scenario: Совпадение нескольких правил
- **WHEN** `blue_eyes` разрешён литералом и regex, но запрещён удалением
- **THEN** тег исключается, а не дублируется и не восстанавливается разрешающим правилом

#### Scenario: Несколько владельцев
- **WHEN** regex источника eyes и литерал источника face закрепляют `blue_eyes`
- **THEN** оба источника могут передать его по своим ограничениям, а полный кадр и остальные источники не могут; отсутствие принятого тега у владельцев не включает fallback

#### Scenario: Объяснение решения
- **WHEN** regex повлиял на принятие или отклонение тега
- **THEN** результаты фильтрации сохраняют действие, источник и совпавший шаблон отдельно от исходного score, доступные в Inspect

### Requirement: Проверка и перенос расширенных правил
Regex MUST проверяться до применения политики; ошибочный шаблон MUST давать сообщение с полем, номером шаблона и источником при его наличии. Workflow и pipeline-конфиги MUST сохранять шаблоны без изменения. Отсутствующие regex-поля MUST означать отсутствие regex-ограничений. Изменение regex MUST позволять повторную фильтрацию evidence без нового инференса.

#### Scenario: Ошибка шаблона
- **WHEN** regex-поле содержит незакрытую группу `(`
- **THEN** операция завершается диагностикой до фильтрации и экспорта, без частичного результата

#### Scenario: Перенос через конфиг и API
- **WHEN** настройки с regex сохраняют и загружают, затем выполняют через API
- **THEN** шаблоны и буквальные списки восстанавливаются раздельно и дают тот же результат, что UI

#### Scenario: Повторная фильтрация
- **WHEN** при прежней геометрии меняются только regex-правила
- **THEN** Apply Filters переиспользует исходные оценки WD, сохраняя их неизменными

### Requirement: Настраиваемый разделитель итогового текста
Настройки вывода MUST предоставлять `tag_separator` с default `, `. Строка MUST использоваться дословно между тегами, без trim, дополнительных пробелов и завершающего разделителя; пустая строка допустима. Разделитель MUST быть независим от замены `_` и экранирования скобок и MUST NOT менять словари оценок, порядок тегов или синтаксис ввода правил.

#### Scenario: Пробел или другой символ
- **WHEN** приняты упорядоченные `blue_eyes`, `long_hair`, замена `_` выключена и разделитель равен ` `, `,` либо ` | `
- **THEN** результат равен соответственно `blue_eyes long_hair`, `blue_eyes,long_hair` либо `blue_eyes | long_hair`

#### Scenario: Пробелы внутри имён
- **WHEN** замена `_` включена и разделитель равен `; `
- **THEN** текст равен `blue eyes; long hair`, а правила продолжают принимать списки через запятые и переводы строк

#### Scenario: Граничные случаи
- **WHEN** тегов нет, тег один или разделитель пуст
- **THEN** результат соответственно пуст, содержит единственный тег без разделителя или соединяет имена без вставки символов

#### Scenario: Старые настройки
- **WHEN** старый workflow или конфиг не содержит `tag_separator` и regex-полей
- **THEN** используются разделитель `, ` и прежняя буквальная политика

### Requirement: Единый формат вывода во всех потребителях
Выход `tags`, итоговый текст viewer/Inspect и TXT-экспорт MUST использовать сохранённые настройки вывода. JSON MUST сохранять эти настройки и канонические словари. Save Result без `tags` MUST восстанавливать формат из JSON нового результата; старый JSON MUST сохранять прежний fallback. Явно подключённый `tags` MUST сохраняться дословно. Несовместимые настройки текста ветвей MUST отклоняться при merge.

#### Scenario: Сохранение без tags
- **WHEN** результат с разделителем ` | ` передан в Save Result без `tags`
- **THEN** TXT содержит тот же итоговый текст, что выход `tags` этого результата и его просмотр

#### Scenario: Разные разделители ветвей
- **WHEN** Merge Results получает ветви с разделителями `, ` и ` `
- **THEN** выполнение сообщает о несовместимости вместо скрытого выбора одной настройки

#### Scenario: Прямой текст и отчёт
- **WHEN** один results показывают через viewer/Inspect и экспортируют через Export Report, Tag Folder и Save Result
- **THEN** текст каждого изображения использует одинаковый разделитель и форматирование; границы изображений в отчёте остаются отдельными от разделителя тегов

### Requirement: Отдельные поля regex-избыточности
Нода очистки MUST предоставлять независимые regex_enabled и regex_relations_json без изменения буквального relations_json. Правила MUST сохраняться через workflow/пресет/API, а постоянные ошибки шаблонов и подстановок MUST отклоняться до исполнения. Старые настройки без regex-полей MUST означать отключённый механизм. Inspect MUST показывать сработавшее regex-правило и свидетель.

#### Scenario: Настройка семейства без перечисления тегов
- **WHEN** пользователь включает regex_enabled и задаёт одно правило цвета с захваченной группой base
- **THEN** все соответствующие принятые теги обрабатываются по правилу без перечисления отдельных буквальных пар и без повторного инференса

### Requirement: Отдельные операции между генерацией и merge
ComfyUI MUST предоставлять соединяемые этапы получения принятых наборов тегов, необязательной локальной постобработки и объединения в существующий глобальный результат. Настройки операции MUST находиться у отдельной операции и MUST NOT дублироваться в Tag Image / Regions или настройках модели. Старые графы MUST сохранять прежнее поведение.

#### Scenario: Общее описание с деталями от детекторов
- **WHEN** пользователь соединяет сбор исходных оценок, локальные фильтры, удаление избыточности и объединение
- **THEN** итоговые tags и results_json остаются описанием полного изображения с деталями от разрешённых источников, без обязательного вывода отдельных региональных подписей

#### Scenario: Очистка отсутствует
- **WHEN** операция удаления избыточности отсутствует либо все её механизмы выключены
- **THEN** тот же набор исходных оценок и фильтров даёт прежние теги, оценки, порядок и форматирование

### Requirement: Настройка области локальной очистки
Операция MUST позволять выбрать полный кадр, регионы или оба вида наборов, а для регионов — все либо перечисленные источники. Выбранные регионы MUST обрабатываться по отдельности. Настройка MUST NOT включать скрытое удаление тегов полного кадра, подтверждение полным кадром или композиционное отсечение.

#### Scenario: Очистка только одежды
- **WHEN** операция выбрана для регионов источника clothes, а у face и полного кадра есть такие же имена тегов
- **THEN** меняются только отдельные наборы clothes; face и полный кадр сохраняются

#### Scenario: Политика допуска композиции
- **WHEN** регион сохраняет `1girl` после очистки и действующая политика запрещает этот тег в общем описании
- **THEN** локальный набор сохраняет `1girl`, а стадия merge объясняет его отдельное исключение из глобального caption

### Requirement: Проверка и перенос операций избыточности
Workflow и конфиг постобработки MUST сохранять порядок операций, переключатели методов, отношения, защищённые теги и выбор источников. UI и API MUST применять одинаковую политику. Ошибки постоянных параметров MUST обнаруживаться штатной проверкой графа без запуска моделей; старые конфиги без операций MUST означать пустую цепочку.

#### Scenario: Возобновление настроек
- **WHEN** workflow с отношением `miniskirt → skirt`, выключенной эвристикой и защитой тега сохраняется и открывается снова
- **THEN** все настройки восстанавливаются и API даёт тот же результат без frontend-callback

### Requirement: Инспекция тегов до объединения
Инспектор MUST принимать промежуточные наборы тегов и показывать до/после операции, исходные оценки и причины удалений отдельно по кадру, источнику и региону. История операции MUST сохраняться в итоговом JSON. Изменение очистки MUST переиспользовать исходные оценки без нового инференса.

#### Scenario: Проверка удаления юбки
- **WHEN** отношение `miniskirt → skirt` удалило `skirt` из второго региона
- **THEN** Inspect показывает идентификатор второго региона, обе исходные оценки и сработавшее отношение; первый регион не отмечается изменённым

#### Scenario: Прежний Merge Results
- **WHEN** объединяются результаты, полученные из одинаковых исходных оценок, но с разными цепочками локальной постобработки
- **THEN** система сообщает о несовместимости политик и не восстанавливает удалённые теги скрытой повторной фильтрацией

### Requirement: Подбор производителей из контекста входа
При вызове создания соединения от входного порта WDV3, включая протягивание связи на пустое место, интерфейс MUST предлагать зарегистрированные ноды с совместимыми выходами. Основные производители для роли входа MUST отображаться первыми под текущими пользовательскими названиями. Подсказки MUST учитывать имя и назначение входа, а не только его подпись.

#### Scenario: Модель WD и настройки
- **WHEN** пользователь открывает предложения для wd_model или options
- **THEN** первым предлагается соответственно Load Tagger Model или Tagging Settings; Load Pipeline Config также предлагается для options при наличии совместимого выхода

#### Scenario: SAM и YOLO
- **WHEN** пользователь выбирает sam_model, sources или detectors
- **THEN** предлагаются соответственно Load SAM 3.1; SAM Text / Region Settings и Combine SAM Sources; YOLO Detector и Combine YOLO Detectors, а также доступные совместимые выходы Load Pipeline Config

### Requirement: Подключение выбранного совместимого порта
Выбор предложения MUST создавать ноду штатным способом и подключать именно указанный совместимый выход ко входу пользователя. При нескольких подходящих портах интерфейс MUST явно различать варианты. Создание ноды MUST NOT запускать inference или скачивание и MUST NOT молча заменять занятые связи. Отмена MUST сохранять граф без изменений.

#### Scenario: Выход SAM-модели из конфига
- **WHEN** для sam_model выбрана Load Pipeline Config
- **THEN** подключается её выход sam_model, а не первый выход options

#### Scenario: Данные разных стадий
- **WHEN** пользователь выбирает Collect Evidence для входа regions
- **THEN** подключается выход regions, а не evidence

#### Scenario: Отмена и существующие связи
- **WHEN** пользователь отменяет выбор либо вход уже подключён без явного действия переподключения
- **THEN** существующие ноды и связи сохраняются и граф не запускается

### Requirement: Покрытие всех типов соединений WDV3
Подсказки MUST охватывать все зарегистрированные пользовательские типы WDV3, обязательные и optional-входы, предыдущие источники и динамические входы Combine. Для IMAGE/MASK и подключаемых строковых входов MUST сохраняться штатная совместимость. Проверка покрытия MUST обнаруживать WDV3-вход без производителя либо без явно объяснённого исключения.

#### Scenario: Правила и коллекции
- **WHEN** пользователь выбирает rules, previous_detectors или динамический вход Combine SAM Sources
- **THEN** предлагаются Region Tag Rules либо соответствующие производители коллекций YOLO/SAM без смешивания этих типов

#### Scenario: Evidence, результаты и отчёт
- **WHEN** выбирается evidence, results, regions, report или files
- **THEN** предлагаются реальные производители именно этой стадии, включая Collect Evidence, Apply Filters/Merge Results, Inspect или Image Folder соответственно

#### Scenario: Новый тип после установки расширения
- **WHEN** зарегистрирована новая WDV3-нода с новым входным типом и производителем
- **THEN** совместимые предложения появляются из текущего каталога без зависимости от жёсткого списка старых нод

### Requirement: Различение назначения строковых портов
Для подключаемых строковых портов WDV3 рекомендации MUST различать tags, results_json и пути файлов по роли. Для results_json MUST приоритетно предлагаться выходы результатов, для tags — выходы тегов. Это различение MUST NOT менять тип STRING в API, глобально фильтровать сторонние строковые порты или запрещать обычное ручное подключение совместимой строки.

#### Scenario: JSON в просмотрщик
- **WHEN** пользователь выбирает results_json у Results Viewer или Save Result
- **THEN** WDV3-рекомендации предлагают results_json от нод результатов, а не tags или txt_path только из-за общего типа STRING

#### Scenario: Обычная строка стороннего расширения
- **WHEN** пользователь строит строковую связь между сторонними нодами
- **THEN** их меню и обычные правила совместимости остаются прежними

### Requirement: Подбор потребителей из контекста выхода
При создании связи от выхода WDV3 на пустое место интерфейс MUST предлагать зарегистрированных совместимых потребителей и их подходящие входы. Потребители MUST учитывать стадию данных и роль строковых выходов. Выбор MUST создавать корректную связь штатным способом без скрытой перестройки остального графа.

#### Scenario: Выход правил области
- **WHEN** пользователь начинает связь от rules у Region Tag Rules
- **THEN** предлагаются совместимые rules-входы YOLO Detector и SAM Text / Region Settings

#### Scenario: Выход отфильтрованных результатов
- **WHEN** пользователь начинает связь от results у Apply Filters
- **THEN** предлагаются results у Inspect и подходящие входы Merge Results, с явным выбором при неоднозначности left/right

### Requirement: Устойчивость рекомендаций и совместимость workflow
Предложения MUST быть детерминированными, без дублей и отсутствующих нод, и учитывать завершённую регистрацию каталога. Повторная регистрация и восстановление workflow MUST NOT дублировать меню или портить связи. Существующие type IDs, порядок выходов, сериализованные подключения и выполнение через API MUST сохраняться; рекомендации MUST дополнять штатные возможности ComfyUI.

#### Scenario: Динамический вход после восстановления
- **WHEN** открывается сохранённый workflow и Combine добавляет очередной динамический вход
- **THEN** для нового входа работают те же предложения, а прежние связи и их индексы сохраняются

#### Scenario: Нода из другого change ещё не установлена
- **WHEN** TXT/store-нода только запланирована и отсутствует в зарегистрированном каталоге
- **THEN** она не появляется в меню; после её фактической регистрации совместимые предложения становятся доступны

### Requirement: Постоянный кэш в существующих нодах
Tag Image / Regions, Collect Evidence и Tag Folder MUST проверять постоянные расчёты внутри существующего маршрута без обязательного подключения отдельных планировочных нод. Управление кэшем MUST находиться в Tagging Settings через options. Полный совместимый hit MUST пропускать inference; изменение фильтров MUST применять новую политику к прежним raw-оценкам.

#### Scenario: Прежний граф и новые фильтры
- **WHEN** пользователь указал папку кэша и reuse в Tagging Settings и повторяет существующий граф с другими порогами
- **THEN** нода получает исходные оценки из .wdv3 и меняет результат без нового inference; отдельная Inference Settings не требуется

#### Scenario: IMAGE без имени файла
- **WHEN** для IMAGE выбран reuse, reuse_only или refresh, но папка датасета не задана
- **THEN** выводится понятная ошибка пути; для Tag Folder папка может браться из Image Folder

### Requirement: Понятные видимые имена источников
Порты SAM-запросов, выбор имён детекторов для очистки и JSON описаний детекторов MUST иметь разные понятные видимые названия. Изменение подписей MUST сохранять ключи API, типы и индексы существующих соединений, включая динамические входы.

#### Scenario: Восстановление прежних источников
- **WHEN** открывается старый workflow с sources и previous_sources
- **THEN** связи сохраняются, а порты отображаются как запросы областей SAM; sources в очистке обозначает имена детекторов для очистки

### Requirement: Dataset-ветка завершается соседними TXT
Новая dataset-ветка MUST завершаться явным сохранением итоговых тегов каждого изображения в соседний TXT с тем же stem, сохраняя подпапки. По умолчанию `sub/image.png` MUST соответствовать `sub/image.txt`. Запись MUST учитывать выбранный режим существующего файла и проверку коллизий. Evidence MUST оставаться в служебном хранилище отдельно от TXT. Последующие этапы обработки MUST NOT запускаться автоматически.

#### Scenario: Первый расчёт и финальная подпись
- **WHEN** выбран dataset_root и пользователь запускает расчёт с финальным Save Captions
- **THEN** evidence сохраняется в `.wdv3` внутри датасета, а итоговый image.txt создаётся рядом с исходным изображением после фильтров и объединения

#### Scenario: Новые правила после перезапуска
- **WHEN** готовые evidence загружены из `.wdv3` в reuse_only и изменены правила
- **THEN** Filter Tag Sets/операции/Merge Tag Sets либо Apply Filters получают новые итоговые теги без моделей, а Save Captions записывает соседние TXT по явно выбранному режиму

### Requirement: Загрузка сохранённых расчётов в workflow
ComfyUI MUST предоставлять загрузку evidence из постоянного хранилища и импорт поддерживаемых файлов расчётов с передачей в Apply Filters и Inspect. Загрузка MUST проверять формат и целостность без запуска моделей. Расширенный маршрут MUST поддерживать отдельный конфиг хранилища в workflow и pipeline-пресете; обычный маршрут MUST брать режим и папку из Tagging Settings без обязательного второго конфига.

#### Scenario: Правила после перезапуска
- **WHEN** пользователь открывает workflow, загружает сохранённое evidence и меняет Tagging Settings или правила источников у Apply Filters
- **THEN** новые теги, решения и отчёт получаются без загрузки WD/YOLO/SAM и повторного инференса

#### Scenario: Несовместимый файл
- **WHEN** в загрузчик evidence передан TXT, отфильтрованный JSON без полных оценок или неподдерживаемая версия
- **THEN** нода сообщает тип несовместимости и не запускает скрытый пересчёт

### Requirement: Инкрементальный расчёт изображений и папки
Workflow MUST поддерживать планирование и выполнение расчётов для IMAGE и папки с использованием одного постоянного хранилища. План MUST показывать переиспользуемые и недостающие стадии до загрузки моделей. Выполнение MUST сохранять соответствие результатов исходным файлам независимо от порядка, размера батча и перезапуска.

#### Scenario: Дополнили папку
- **WHEN** к ранее обработанной папке добавлено одно изображение
- **THEN** reuse выполняет необходимые модельные стадии только для добавленного изображения и возвращает результаты всей выбранной папки

#### Scenario: Изменили размер батча
- **WHEN** прежний набор обрабатывается другим размером батча
- **THEN** готовые совместимые записи не пересчитываются только из-за смены батча и порядок вывода соответствует текущему запросу

### Requirement: Загрузка TXT как пользовательских подписей
Система MUST загружать существующие UTF-8 TXT отдельно от модельных свидетельств, сохраняя исходный текст, порядок тегов, путь и контрольную сумму. Разбор MUST использовать явный входной формат: notebook-совместимые запятые/переводы строк либо заданный разделитель. Пробел и `_` внутри обычного тега MUST канонизироваться одинаково; неизвестные модели теги MUST сохраняться без выдуманной вероятности.

#### Scenario: TXT с неизвестным тегом
- **WHEN** подпись содержит `blue eyes, custom_tag`, которого нет в словаре WD
- **THEN** оба тега доступны для редактирования и экспорта с происхождением existing_txt; загрузка не требует модели

#### Scenario: Неоднозначный текст с пробелами
- **WHEN** TXT получен соединением тегов пробелом и заменой `_` на пробелы, но структурированных имён рядом нет
- **THEN** интерфейс объясняет невозможность надёжно восстановить границы тегов и требует явного способа разбора, не угадывая их по словарю модели

### Requirement: Явное редактирование готовых подписей
Workflow и API MUST поддерживать добавление тегов в начало/конец, удаление по литералам и отдельным regex, буквальную замену и сортировку по алфавиту либо заданному приоритету. Операции MUST применяться в явно заданном порядке и возвращать предварительный результат без записи и инференса. Удаление MUST иметь приоритет над добавлением в одной операции; прочие теги MUST сохраняться.

#### Scenario: Изменить только TXT
- **WHEN** пользователь загружает TXT, удаляет `watermark` и добавляет `dataset_tag`
- **THEN** предпросмотр показывает изменение подписи без WD/YOLO/SAM и без записи до выполнения экспорта

#### Scenario: Замена и дедупликация
- **WHEN** `blue eyes` заменяется на уже существующий `yellow_eyes`
- **THEN** результат содержит один `yellow_eyes`, сохраняя остальные теги и документированный порядок

### Requirement: Режимы записи подписей датасета
Новая ветка экспорта подписей MUST предоставлять `error`, `skip`, `append`, `overwrite`. При существующем целевом TXT error MUST завершаться ошибкой, skip MUST оставлять его байты неизменными, append MUST сохранять существующие теги и добавлять новые без дублей, overwrite MUST заменять подпись подготовленным результатом. Для отсутствующего файла все режимы MUST создавать подпись.

#### Scenario: Дополнить как в notebook
- **WHEN** файл содержит `blue eyes, smile`, новые теги равны `blue_eyes, long_hair`, выбран append
- **THEN** итоговый набор равен `blue_eyes, smile, long_hair` в этом порядке с выбранным форматированием

#### Scenario: Старые теги и фильтр новых оценок
- **WHEN** append объединяет существующую подпись с новыми отфильтрованными предсказаниями
- **THEN** фильтрация предсказаний не удаляет старые пользовательские теги; их изменение требует явной операции редактирования

#### Scenario: Повторное дополнение
- **WHEN** одинаковые новые теги повторно экспортируются в append
- **THEN** повторов тегов не появляется, а существующая подпись без смысловых изменений не переписывается ради нормализации

#### Scenario: Пропустить готовый результат
- **WHEN** выбран skip, целевой TXT существует и единственный запрошенный выход для изображения — этот TXT
- **THEN** файл не изменяется и модельные стадии для этого выхода не запускаются; при отдельном запросе evidence его полнота проверяется независимо

### Requirement: Однозначные пути подписей
Экспорт MUST поддерживать notebook-имя `image.txt`, имя с расширением изображения `image.png.txt` и явное сопоставление путей. Новая dataset-ветка MUST по умолчанию выбирать соседний stem-TXT; альтернативный каталог задаётся явно. План MUST проверять коллизии и выход за выбранные границы до записи. Подписи-эталоны MUST NOT становиться целью эксперимента без явно выбранного экспорта в это место.

#### Scenario: Одинаковый stem
- **WHEN** в одной папке есть a.jpg и a.png и выбран формат a.txt для обоих
- **THEN** план сообщает коллизию до записи и предлагает выбрать имена с расширением либо явное сопоставление

#### Scenario: Рекурсивные каталоги
- **WHEN** разные подпапки содержат одноимённые изображения
- **THEN** экспорт сохраняет относительные подпапки и не объединяет их подписи

### Requirement: План и безопасная фиксация TXT
Перед записью MUST быть доступен план с путём, режимом, существующими/новыми/удалёнными тегами и ожидаемой контрольной суммой входного TXT. Запись MUST быть атомарной для каждого файла и отклонять конфликт изменения после планирования. Операция MUST возвращать written/skipped/unchanged/conflict/failed по каждому файлу и поддерживать возобновление, не обещая общей транзакции всей папки.

#### Scenario: Ручная правка после предпросмотра
- **WHEN** пользователь изменил TXT после построения плана
- **THEN** применение старого плана возвращает conflict и сохраняет новую пользовательскую версию

#### Scenario: Сбой при записи
- **WHEN** запись нового содержимого одного файла прервана
- **THEN** его предыдущая версия остаётся целой; успешно завершённые другие файлы учитываются при возобновлении

### Requirement: Разделение настроек и совместимость экспорта
Настройки тегирования MUST оставаться в Tagging Settings, правила чтения/редактирования TXT и назначения/режима записи MUST задаваться отдельными конфигурациями подписей и экспорта. Новые ноды MUST исполняться через API без frontend-callback. Прежние Save Result, Tag Folder и notebook-вызовы MUST сохранять defaults и семантику старых параметров; новая ветка MUST явно отличать подпись от исходного модельного результата.

#### Scenario: Старый workflow
- **WHEN** открывается прежний workflow с overwrite=false без новых конфигов экспорта
- **THEN** сохраняется прежняя защита от существующего файла, без скрытого включения append

#### Scenario: Новый workflow через API
- **WHEN** те же конфиги чтения, редактирования и экспорта переданы через API
- **THEN** план и итоговые байты совпадают с интерактивным workflow при тех же исходных файлах

### Requirement: Отложенная загрузка весов в прежнем графе
Load Tagger Model MUST читать метаданные без создания WD-сети и загрузки тензоров весов. Совместимость кэша MUST проверяться по содержимому локальных ресурсов. При полном hit существующий postprocessing-граф MUST обходиться без загрузки WD/YOLO-весов; miss или refresh MUST загружать необходимые модели.

#### Scenario: Новый процесс с готовыми расчётами
- **WHEN** прежний граф запускается после перезапуска с теми же файлами моделей, указанным cache_dataset_root и новыми фильтрами
- **THEN** loader подготавливает метаданные, нода читает сохранённые оценки без выделения WD-сети и нового inference

#### Scenario: Пустой путь не отключает кэш молча
- **WHEN** для IMAGE выбран дисковый reuse, а cache_dataset_root пуст
- **THEN** нода просит указать путь или выбрать off, не запускает новый inference и не выдаёт кэш процесса за постоянный

### Requirement: Автоматическая папка расчётов и понятное переопределение
Tag Folder MUST по умолчанию брать папку расчётов из Image Folder. Необязательный dataset_folder_override MUST сохранять API-ключ cache_dataset_root и принимать папку датасета либо её .wdv3 как одно назначение без повторного вложения .wdv3. Папка вывода TXT/JSON MUST NOT менять выбранное хранилище расчётов.

#### Scenario: Обычный повтор без настройки пути
- **WHEN** cache_dataset_root пуст, выбран reuse и Tag Folder повторно обрабатывает ту же папку
- **THEN** совместимые расчёты читаются из Image Folder/.wdv3, а модели вызываются только для недостающих стадий

#### Scenario: Пользователь выбрал сам служебный каталог
- **WHEN** cache_dataset_root указывает на dataset/.wdv3 либо повторно вложенные каталоги с именем .wdv3
- **THEN** используется dataset/.wdv3 без создания нового вложенного хранилища; существующие ключи расчётов сохраняются

#### Scenario: Изменили только место сохранения подписей
- **WHEN** output_directory Tag Folder изменён, а Image Folder и cache_dataset_root прежние
- **THEN** место поиска evidence не меняется и совместимые расчёты переиспользуются

### Requirement: Независимые режимы расчёта и сохранения Tag Folder
Tagging Settings MUST обозначать cache_mode как calculation_mode с пояснением reuse, reuse_only, refresh и off. Tag Folder MUST отдельно управлять save_txt, save_json и overwrite. Ошибка существующего файла MUST объяснять обновление или просмотр без записи; ошибка недостающих расчётов MUST показывать хранилище, изображение и стадии без скрытого инференса в reuse_only.

#### Scenario: Обновление TXT из готового кэша
- **WHEN** выбран reuse_only, save_txt=true и overwrite=true при наличии совместимых расчётов
- **THEN** итоговый TXT обновляется после применения текущих фильтров без загрузки весов и инференса

#### Scenario: Повторная запись запрещена
- **WHEN** итоговый файл уже существует и overwrite=false
- **THEN** файл остаётся неизменным; сообщение предлагает включить overwrite или выключить сохранение и объясняет отличие записи от режима расчёта

#### Scenario: В выбранном хранилище нет расчёта
- **WHEN** reuse_only не находит совместимый расчёт
- **THEN** ошибка показывает фактическую папку .wdv3, изображение и недостающие стадии, объясняет запрет инференса и выбор исходной папки; новый расчёт не начинается

### Requirement: Управляемая экономия памяти моделей
Tagging Settings MUST предоставлять low_memory_mode, включённый по умолчанию и сохраняемый через options и pipeline-пресеты. При включении веса WD MUST освобождаться из RAM перед необходимым SAM-инференсом и загружаться только при последующей необходимости WD. Выключение MUST сохранять WD для повторного использования при достаточной памяти; совместимость кэша MUST NOT зависеть от этой настройки.

#### Scenario: Последовательная обработка папки с SAM
- **WHEN** очередное изображение требует SAM, а low_memory_mode включён
- **THEN** ранее удерживаемые отложенным загрузчиком веса WD освобождаются перед SAM; SAM завершается до загрузки WD для полного кадра и регионов

#### Scenario: Сохранение WD в памяти
- **WHEN** low_memory_mode выключен и новое изображение требует SAM
- **THEN** SAM не вызывает принудительное освобождение WD; подсказка объясняет повышенную пиковую память и возможность уменьшить повторные загрузки WD

#### Scenario: Только фильтры или смена режима памяти
- **WHEN** все расчёты сохранены и меняются фильтры либо low_memory_mode
- **THEN** готовые артефакты не инвалидируются, SAM не запускается и лишняя выгрузка WD не выполняется

### Requirement: Изоляция аварий SAM от ComfyUI
SAM-инференс в ComfyUI MUST исполняться изолированно от процесса сервера при обоих значениях low_memory_mode. После сегментации его ресурсы MUST освобождаться. Аварийное завершение SAM MUST превращаться в ошибку ноды с доступной причиной; распознанная ошибка выделения памяти MUST объяснять нехватку памяти и уменьшение sam_batch_size.

#### Scenario: Нативный отказ выделения памяти
- **WHEN** исполнитель SAM завершается с сообщением memory allocation failed
- **THEN** вызывающая нода получает диагностику нехватки памяти, а нативный abort не исполняется в процессе ComfyUI

#### Scenario: Успешный SAM перед WD
- **WHEN** завершена сегментация требуемой группы изображений
- **THEN** исполнитель SAM закрывается до следующей загрузки WD, а исходные размеры, маски, рамки и привязки источников сохраняются

### Requirement: Надёжная загрузка WD на Windows
Загрузка локальных safetensors-весов WD на Windows MUST поддерживать чтение без отображения файла весов в память и совместимость с поддерживаемыми версиями загрузчика. Этот путь MUST сохранять исходные параметры модели и не менять её идентичность для кэша.

#### Scenario: Загрузка большого WD на CPU
- **WHEN** в проверенном окружении Windows загружается полный локальный checkpoint WD Huge
- **THEN** веса корректно загружаются и позволяют выполнить настоящий forward без прежнего сбоя доступа к отображённой памяти

### Requirement: Ограниченная служебная работа при повторной фильтрации
Повторная фильтрация готового evidence MUST NOT запускать модельные стадии или обходить полный словарь оценок только ради служебного поиска удерживаемых тензоров ComfyUI. Ненужный проход regex-диагностики при отсутствии regex MUST пропускаться. Оптимизация MUST сохранять исходные оценки, принятые теги, решения и формат вывода.

#### Scenario: Повторная фильтрация полного датасета
- **WHEN** сохранённые raw-оценки передаются через обычные ноды ComfyUI с новой политикой
- **THEN** время учитывается отдельно от инференса, результаты совпадают с прежней семантикой, а служебный учёт памяти не требует полного декодирования словаря на каждом узле

### Requirement: Примеры для всех строковых входов
Каждый STRING-вход WDV3 MUST содержать пример допустимого ввода в подсказке, включая пути, JSON, regex, обычные теги и разделители. Пример MUST соответствовать назначению поля; буквальные теги и regex MUST явно различаться. Добавление подсказок MUST сохранять ключи, defaults, порядок виджетов и старые workflow.

#### Scenario: Настройка сложного текстового поля
- **WHEN** пользователь открывает подсказку JSON, regex либо строкового разделителя
- **THEN** виден пример соответствующего синтаксиса, а для разделителя объяснено сохранение пробелов и отсутствие кавычек в самом значении

### Requirement: Рекомендации просмотра подробных результатов
Для каждого WDV3-выхода results_json рекомендации MUST первыми предлагать Results Viewer. На входе results_json просмотрщика MUST предлагаться Tag Folder, Tag Image / Regions, Merge Tag Sets, Apply Filters и Merge Results. Выбор MUST подключать именно results_json, сохраняя отдельное назначение tags и файловых путей.

#### Scenario: Просмотр результатов папки
- **WHEN** пользователь протягивает results_json из Tag Folder
- **THEN** первой рекомендацией является Results Viewer с подключением к results_json; изображения читаются из путей результата без обязательного IMAGE-входа

#### Scenario: Выбор источника у просмотрщика
- **WHEN** пользователь выбирает источник на входе results_json Results Viewer
- **THEN** перечисляются все пять поддерживаемых производителей; описание и подсказка объясняют допустимые соединения и дополнительный IMAGE-вход для Tag Image / Regions

### Requirement: Настройка каскада региональных этапов
Region Tag Rules MUST принимать дочерний стек обычных YOLO/SAM и separate/merge_to_parent. Дерево MUST выводиться из подключений без ручных stage_id/parent_stage и отдельных Cascade/Route-нод. Настройки MUST оставаться независимыми; дочерний поиск MUST получать исходный bbox, собственная заливка относится к WD ребёнка. Tag Image / Regions, Tag Folder и Collect Evidence MUST исполнять эту структуру.

#### Scenario: Три уровня через обычные правила
- **WHEN** стек глаз подключён к Region Tag Rules лица, а стек лиц — к Region Tag Rules человека
- **THEN** обычный Tag Image / Regions исполняет человек → лицо → глаза без добавочных Cascade/Route-нод и ручных идентификаторов

#### Scenario: Смешанный дочерний стек
- **WHEN** родитель SAM получил rules с child_detectors и парой child_sam_model + child_sources
- **THEN** обе дочерние ветви ищут внутри каждого исходного bbox родителя, а их обычные настройки и собственная заливка независимы

#### Scenario: Обычный merge после операций
- **WHEN** Filter Tag Sets и локальные операции передают иерархию в Merge Tag Sets
- **THEN** маршрутизация выполняется автоматически по сохранённым rules, без дополнительного Route и повторного вклада тегов

### Requirement: Ранняя проверка конфигурации каскада
Известные постоянные ошибки схемы и лимитов MUST отклоняться штатной проверкой графа до загрузки моделей. Весь собранный план MUST дополнительно проверяться до первого инференса каскада: ссылки, циклы, уникальность имён, типы детекторов, SAM-пары и лимиты. Значения, вычисляемые upstream-нодами, MUST NOT выдаваться за проверенные до их получения.

#### Scenario: Отсутствующий родитель
- **WHEN** собранный план содержит parent_stage, которого нет в плане
- **THEN** выполнение каскада завершается конкретной диагностикой до вызова детекторов и WD

#### Scenario: Цикл
- **WHEN** body назначен потомком face, а face — потомком body
- **THEN** план отклоняется с путём цикла без частичного дерева результатов

### Requirement: Просмотр дерева и вкладов тегов
Inspect и JSON-отчёт MUST сохранять дерево областей, показывать путь родителей, рамки/маски в исходном кадре, входную вырезку и собственные/полученные от потомков теги. Отдельные дочерние наборы MUST быть доступны и при merge_to_parent. Просмотр MUST различать отсутствие детекций, пропуск по отсутствию родителей, ограничение лимитом и ошибку.

#### Scenario: Проверка второго человека
- **WHEN** пользователь выбирает глаза лица второго человека
- **THEN** просмотр показывает только их путь body/face/eyes, точные исходные рамки, собственные оценки и вклад в соответствующего родителя

#### Scenario: Смена изображения и размер ноды
- **WHEN** пользователь переключает изображения разных пропорций в Results Viewer или Inspect и меняет размер ноды
- **THEN** DOM-панель, списки, текст и таблицы занимают доступную ширину ноды без сжатия влево; изображение сохраняет пропорции, а высота панели выделяется штатным DOM-widget layout ComfyUI

### Requirement: Глобальный вывод и совместимость каскада
Каскад MUST поддерживать существующий общий caption из полного кадра и допустимых региональных вкладов. Separate MUST сохранять независимый регион, но MUST NOT требовать нового формата объектных подписей. Старые плоские workflow MUST сохранять прежние результаты. Политики и дерево MUST переноситься через workflow/API без frontend-callback.

#### Scenario: Прежний плоский граф
- **WHEN** граф не содержит настроек каскада
- **THEN** детекторы работают по полному кадру и выдают прежние теги/JSON без обязательной миграции

#### Scenario: Пустые новые виджеты старого workflow
- **WHEN** старый workflow восстанавливает пустое, null или отсутствующее значение child_tag_route либо tag_enabled
- **THEN** восстановление и отправка frontend, серверная проверка и исполнение используют separate и true соответственно; явные merge_to_parent и false сохраняются, а неизвестные непустые значения отклоняются

#### Scenario: Повторная загрузка
- **WHEN** каскад с двумя режимами передачи сохраняют, открывают и выполняют через API
- **THEN** дерево и режимы восстанавливаются и дают тот же общий caption, что интерактивный workflow

#### Scenario: Повторное объединение результатов
- **WHEN** объединяются ветви с конфликтующей геометрией родителей или разными политиками маршрутизации одного этапа
- **THEN** система отклоняет конфликт без потери родительских связей и скрытого повторного применения иной политики
