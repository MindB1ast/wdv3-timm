# Spec Delta

## ADDED Requirements

### Requirement: Настройка кастомного правила через интерфейс
Пользователь MUST иметь возможность собрать правило через подписанные поля ноды с выбором этапа, областей, тегов, условия, действия и оценок. Ноды MUST поддерживать упорядоченную цепочку. Обязательный ввод JSON MUST отсутствовать в обычных сценариях. Подсказки выходов MUST описывать передаваемые данные, а рекомендации подключения MUST предоставляться контекстным меню.

#### Scenario: Удаление тегов лица у тела
- **WHEN** пользователь выбирает дочерние face как источник, агрегат непосредственного parent как цель и subtract как действие
- **THEN** настройки выражаются полями ноды и сохраняются в workflow без ручных идентификаторов экземпляров областей

### Requirement: Подключение правил к источнику и этапу обработки
Region Tag Rules MUST принимать необязательную цепочку кастомных правил. Самостоятельная нода MUST применять такую цепочку к tag_sets без инференса и возвращать tag_sets. Tag Image / Regions, Tag Folder и раздельный граф evidence MUST применять одинаковую семантику. Тип входа MUST сохранять порядок нескольких правил.

#### Scenario: Одинаковый результат двух графов
- **WHEN** одинаковые правила применяются внутри Tag Folder и через Collect Evidence, Filter Tag Sets, кастомную обработку и Merge Tag Sets
- **THEN** собственные/агрегированные теги и общий caption совпадают на одинаковых оценках и настройках

### Requirement: Основные фильтры как готовые примеры
Основные поля Region Tag Rules MUST сохранять имена API, defaults и поведение прежних workflow. UI и документация MUST показывать эквивалентное описание через источник, цель, условие, действие и этап. Пользователь MUST иметь возможность создать отдельную кастомную копию готового правила и отключить исходное правило для сравнения без двойного применения.

#### Scenario: Понятное подтверждение полным кадром
- **WHEN** пользователь изучает require_full_confirmation
- **THEN** описание сообщает, что условие ограничивает вклад этого источника в caption и сохраняет тег региона, а пример кастомного удаления показывает отдельно изменение региона

#### Scenario: Существующий workflow
- **WHEN** пользователь открывает граф с основными фильтрами без подключённой кастомной цепочки
- **THEN** подключения, значения, принятые теги и caption сохраняют прежнее поведение

### Requirement: Просмотр причин и маршрутов
Inspect MUST показывать собственные теги, агрегат, общий caption и историю правил с id, источником, получателем, этапом и причиной. История MUST позволять объяснить сохранение тега в caption из другой ветви. Ошибки настройки MUST указывать правило и поле штатным сообщением ComfyUI, при доступности идентифицируя соответствующую ноду.

#### Scenario: Запрещён только один вклад
- **WHEN** person отклоняет pigeon-toed из-за отсутствия подтверждения full, а другой источник передаёт его
- **THEN** просмотр показывает отклонённый вклад person и принятый вклад другого источника с его именем

### Requirement: Перенос правил между workflow и API
Версия, id, порядок и все поля кастомных правил MUST сохраняться в workflow и pipeline-пресетах. API MUST воспроизводить выполнение без frontend-callback. Новые поля MUST быть необязательными для старых конфигов. Предварительная проверка MUST диагностировать неизвестную версию, ошибочный regex и несовместимые действия до модели, когда значения доступны.

#### Scenario: Повторное открытие
- **WHEN** workflow с тремя правилами сохранён, открыт и выполнен через API
- **THEN** порядок, настройки и результаты совпадают с исходным выполнением

### Requirement: Демонстрации с фиксированными ожиданиями
Каждая новая нода и каждое действие MUST иметь комментированный workflow с фиксированными оценками и ожидаемым результатом. Набор MUST включать базовую ветку, отдельный случай каждого основного фильтра и его кастомный эквивалент. Проверка MUST выполнять все случаи одной командой с отдельными PASS/FAIL и ненулевым кодом при расхождении. Эталоны MUST обновляться только явно.

#### Scenario: Все правила за один запуск
- **WHEN** запускается набор демонстраций на сохранённых оценках с запрещёнными загрузчиками моделей
- **THEN** каждый случай проверяет ожидаемые собственные теги, агрегат и caption без переключения виджетов вручную

#### Scenario: Каскад нескольких людей
- **WHEN** выполняются примеры передачи, вычитания и подтверждения для двух родителей и трёх уровней
- **THEN** assertions проверяют привязку по устойчивым ключам, сохранность детей и отсутствие самоподтверждения или передачи соседнему родителю
