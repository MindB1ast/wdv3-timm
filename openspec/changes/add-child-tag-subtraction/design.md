# Design

## Context

comfy_cascade_tags.route_cascade_tags уже начинает с собственных accepted records, создаёт aggregate и origin_candidates и проходит дерево снизу вверх. Сейчас любой маршрут кроме separate передаёт теги родителю, а merge_cascade_tag_sets исключает такие дочерние записи из независимых вкладов. Добавить только значение enum недостаточно: новый режим нужно явно отличать от merge в обоих местах. См. proposal.md.

## Goals / Non-Goals

**Goals:** третий режим без дополнительной ноды, локальность по parent_region_uid, воспроизводимый порядок и объяснение каждого удаления.

**Non-Goals:** глобальный запрет тега, произвольная межрегиональная логика, изменение raw, категорий или схемы сохранения.

## Decisions

Маршрут выбирается в Region Tag Rules дочернего источника. Пример: Rules лица → YOLO лица.detectors → Rules человека.child_detectors → YOLO человека.detectors → Tag Image / Regions.detectors. У лица subtract_from_parent, у корневого человека separate. Прежний backend child_tag_route сохранить; tooltip явно описывает действие результата текущего источника в родителя.

Дополнить Literal/валидаторы enum в Scripts/cascade.py и связанных контрактах, frontend restore/preflight/config. Пустое значение остаётся separate. Корень допускает только separate, как сейчас.

При обработке ребёнка сначала завершить его собственные дочерние вклады/вычитания, затем его aggregate_operations. Merge-ребёнок передаёт origin_candidates прежним способом. Subtract-ребёнок накапливает у parent ключи category/tag и полный список свидетельств (source/region_uid/score/path). Перед aggregate_operations родителя применить объединение накопленных удалений к его aggregate, включая origin_candidates и decisions; зафиксировать before/after и route_history только для существовавших тегов. Удаление доминирует над merge-вкладом соседа, без зависимости от сортировки UID. Собственные general/character родителя остаются входным снимком; визуализация различает own и aggregate.

Subtract-ребёнок сохраняется независимым при построении глобальных кандидатов, аналогично separate; исключать из независимого merge только merge_to_parent. Теги могут вернуться в общий caption из разрешённого ребёнка/полного кадра: это ожидаемая локальная политика. Ratings не вычитаются. Повтор routing очищает производные aggregates, histories и pending removals и строит всё из own; raw/evidence не меняются. Совместимость merge_results сравнивает новые маршруты и воспроизводит их без потери причин.

## Risks / Trade-offs

- [Непонятно, где выбирать маршрут] → комментарии в workflow и tooltip на правилах лица.
- [Зависимость от порядка детей] → pending removals применяются у родителя после сбора всех вкладов.
- [Тег остаётся в общем caption] → Inspect показывает происхождение; демонстрация проверяет локальные наборы отдельно от общего caption.
- [Нечаянно потерян отдельный ребёнок] → явно проверять условие исключения в глобальном merge и несколько родителей.

## Migration Plan

Расширение enum совместимо с прежними графами. Новые конфиги требуют новой версии расширения; старый backend должен отклонять неизвестное значение. Для отката выбрать separate. Реализация завершается комментированными примерами и регрессионной проверкой старых двух маршрутов.


## Зафиксированный текущий пример

По запросу пользователя сохранить неизменённый yolo_with_child_detector_test.json из ComfyUI и его TXT от 2026-11-10 как отдельную демонстрацию существующего separate-поведения. Не переименовывать источники и не менять regex/пороги ради ожидаемого вывода. Проверка сравнивает точный текст и набор тегов; отсутствие raw/регионального JSON в этом сохранении не позволяет заявлять подтверждение состава регионов. Опциональный API-запуск использует schema object_info для преобразования workflow, сохраняет TXT только во временную папку проекта и сравнивает с зафиксированным ожиданием. Обновление эталона не автоматическое. Это базовый пример перед реализацией нового режима, а не свидетельство реализации subtract_from_parent.
