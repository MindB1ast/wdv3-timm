# Spec Delta

## ADDED Requirements

### Requirement: Структурированный выход для сохранения
Tag Image / Regions и Tag Folder MUST выдавать дополнительно пакет результата с доступными масками и региональными тегами. Старые tags/results_json MUST сохранять тип и смысл. Пользователь MUST иметь возможность сохранить одно изображение или батч без подключения Evidence-ноды и без повторного SAM/WD.

#### Scenario: Одно изображение с SAM
- **WHEN** Tag Image / Regions выполняет SAM и тегирование
- **THEN** его структурированный выход принимается сохранением пакета и БД с индивидуальными масками, тегами и связями регионов

### Requirement: Ноды локального каталога
ComfyUI MUST предоставлять настройки хранилища результатов и ноды записи, поиска и загрузки выбранной версии. Данные и refs MUST передаваться через типизированные входы и workflow/API без frontend-callback; существующие настройки хранилища MUST переиспользоваться при совместимости.

#### Scenario: Загрузка после перезапуска
- **WHEN** сохранённый result_ref выбран поиском после перезапуска
- **THEN** загружены та же версия, маски и теги без моделей; пакет доступен просмотру и экспорту

### Requirement: Согласованные режимы сохранения
Tag Folder и Save Result MUST поддерживать общий необязательный конфиг записи. TXT MUST поддерживать error/skip/append/overwrite с дедупликацией append. JSON и пакеты MUST поддерживать error/skip/overwrite; неявное слияние регионов MUST быть запрещено. Старые defaults MUST сохраняться.

#### Scenario: Совместимость и конфликты
- **WHEN** старый граф использует только overwrite
- **THEN** действует прежнее поведение; при новом конфиге противоречащие явно заданные режимы отклоняются до записи

#### Scenario: Добавление к подписи
- **WHEN** выбран append для TXT, содержащего пользовательские теги
- **THEN** существующие теги сохраняются и дополняются отсутствующими без выдуманных вероятностей; JSON продолжает описывать вычисленный результат и не выдаёт старые TXT-теги за модельные

### Requirement: Сохранение независимо от вычислений
Режимы записи MUST применяться к назначениям и MUST NOT неявно пропускать инференс или менять его кэш. Неизвестные настройки и несовместимые режимы MUST отклоняться до записи. БД и файлы MUST иметь раздельные отчёты успеха и ошибок.

#### Scenario: Существующий файл
- **WHEN** TXT пропущен по skip, а запись в БД включена
- **THEN** результат может быть сохранён в БД; пропуск TXT явно отражён и не объявляется пропуском изображения

### Requirement: Проверяемая демонстрация каждой новой ноды
Каждая новая нода хранения MUST быть покрыта исполняемым демонстрационным workflow с ожидаемыми данными и автоматическими assertions. Общая команда MUST возвращать ошибку при расхождении поведения и явно отмечать недоступные зависимости.

#### Scenario: Проверка связей масок
- **WHEN** демонстрация сохраняет и загружает два региона одного изображения
- **THEN** проверяются содержимое масок, локальные теги, связи и версии; перестановка связей приводит к падению теста, а не автоматическому обновлению ожиданий


### Requirement: Входы Save Result зависят от формата записи
Save Result MUST позволять сохранять только TXT из tags без results_json и проверять result_index по tags. Для JSON либо TXT без tags MUST требоваться results_json. Недостающие данные, неверный индекс, несовпадение длин при совместном сохранении и отключение обоих форматов MUST отклоняться до записи файлов.

#### Scenario: Только текст из tags
- **WHEN** save_txt=true, save_json=false, подключён только tags
- **THEN** ComfyUI принимает граф и нода сохраняет выбранный текст без требования results_json

#### Scenario: JSON отсутствует
- **WHEN** включено сохранение JSON либо включён TXT без tags, но results_json не подключён
- **THEN** выдаётся понятная ошибка о недостающем входе и файлы не записываются

#### Scenario: Совместное сохранение
- **WHEN** подключены tags и results_json при сохранении обоих форматов
- **THEN** проверяются оба списка и индекс до записи; прежние корректные графы сохраняют форматирование tags


### Requirement: Настраиваемый компактный экспорт регионов
Save Region Results MUST экспортировать выбранный результат или батч из ровно одного входа: `results_json` или типизированного `results`. По умолчанию MUST сохранять принятые теги списками, bbox, источник и ключи региона. Оценки, ratings, общий caption, агрегированные теги и история MUST включаться независимо. Режимы записи MUST поддерживать error, skip и overwrite.

#### Scenario: Два источника с одинаковым номером региона
- **WHEN** в компактном режиме сохраняются person:0 и face:0
- **THEN** оба региона различимы, собственные теги сохраняются отдельно, а raw_scores и decisions отсутствуют

#### Scenario: Выбор подробностей
- **WHEN** пользователь включает оценки, агрегаты и историю
- **THEN** выбранные данные сохраняются, исходные и агрегированные теги различимы, а прежняя нода Save Result остаётся доступной для полного JSON


### Requirement: Выбор областей и категорий компактного экспорта
Save Region Results MUST позволять отдельно выбирать полный кадр, регионы, general и character. Выбор категорий MUST применяться к принятым тегам и опциональному caption. result_index MUST выбирать изображение в порядке входного списка; -1 MUST сохранять все изображения. Старые workflow MUST включать обе области и категории по умолчанию.

#### Scenario: Только общие теги полного кадра
- **WHEN** включён include_full, отключены include_regions и include_character
- **THEN** сохраняются только general полного кадра и явно выбранные дополнительные данные; результат распознавания и локальные фильтры не изменяются

### Requirement: Пробелы в именах тегов компактного экспорта
Save Region Results MUST учитывать сохранённую настройку replace_underscores для имён принятых general и character в полном кадре, регионах и агрегатах. При отсутствии настройки MUST использоваться тот же режим, что у caption по умолчанию: подчёркивания заменяются пробелами.

#### Scenario: Экспорт оценки регионального тега
- **WHEN** replace_underscores=true и включён include_scores
- **THEN** тег blue_eyes экспортируется под ключом blue eyes с прежней оценкой; ключи областей и диагностическая история сохраняются


### Requirement: Выбор глубины областей при экспорте
Save Region Results MUST записывать depth для полного кадра (0), корневых регионов (1) и вложенных регионов. Экспорт MUST поддерживать все уровни, точный уровень и максимум включительно. Фильтр глубины MUST применяться вместе с переключателями областей и сохранять исходные ключи дерева.

#### Scenario: Экспорт только уровня лица
- **WHEN** в каскаде тело → лицо → глаза выбрана точная глубина 2
- **THEN** экспортируются записи лиц; выбранные caption и агрегаты сохраняют исходное содержимое

### Requirement: Экспорт SAM-масок без Inspect
Export Report MUST принимать ровно один из `report` и типизированного `results`. Прямой вход MUST сохранять выбранные форматы отчёта с доступными масками без запуска Inspect, создания предпросмотра или повторного инференса. Существующий маршрут через `report` MUST оставаться совместимым.

#### Scenario: Прямой отчёт с двумя областями
- **WHEN** типизированный `results` с двумя разными SAM-масками подключён напрямую к Export Report
- **THEN** отдельные PNG и их связи с регионами и принятыми тегами эквивалентны экспорту через `Inspect.report`; временные файлы и IMAGE-предпросмотр Inspect не создаются

### Requirement: Опциональные PNG-маски компактного экспорта
Save Region Results MUST предоставлять `include_masks`, выключенный по умолчанию. Включённый режим MUST требовать `results` и сохранять маски выбранных регионов отдельными бинарными PNG (`0/255`) в размере и координатах исходного кадра. Запись региона MUST связывать тегированный регион с маской через относительный `mask_asset`. Имена файлов MUST различать регионы и не зависеть от тегов.

#### Scenario: Компактный переносимый набор
- **WHEN** выбраны два SAM-региона с разными тегами и один YOLO-регион без маски
- **THEN** компактный JSON связывает каждую SAM-запись со своим отдельным PNG через `mask_asset` рядом с источником, идентификатором, bbox и выбранными локальными тегами; YOLO-запись не получает `mask_asset`, а перенос каталога сохраняет работоспособность ссылок

#### Scenario: Старый строковый вход или пропуск записи
- **WHEN** `include_masks` включён при подключённом только `results_json` либо режим `skip` пропускает существующий экспорт
- **THEN** в первом случае нода сообщает, что требует `results`, до файловых операций; во втором не создаёт новые assets и не меняет существующие JSON и маски
