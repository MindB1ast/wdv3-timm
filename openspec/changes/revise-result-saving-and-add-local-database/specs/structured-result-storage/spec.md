# Spec Delta

## Purpose

Структурированно хранить версии результатов тегирования и связанные изображения, регионы, теги и маски локально, позволяя повторно загружать и экспортировать их без модельных вычислений.

## ADDED Requirements

### Requirement: Полный пакет результата
Пакет MUST иметь версию схемы, идентичность изображения, размер, источник изображения и список регионов с уникальными ключами, источниками, bbox и родительскими связями. Он MUST сохранять локальные теги, категории, доступные оценки, историю и настройки; общий caption MUST быть необязателен.

#### Scenario: Два источника и каскад
- **WHEN** два источника имеют region_id=0, а один регион является дочерним
- **THEN** записи остаются различимыми по ключам, родитель однозначен, а локальные теги доступны без merge

### Requirement: Отдельные маски и целостность
Каждая доступная маска MUST быть связана с конкретным регионом и изображением; размер, система координат и контрольная сумма MUST быть сохранены. Отсутствующая маска MUST быть обозначена явно; bbox MUST NOT выдаваться за SAM-маску.

#### Scenario: Маски одного изображения
- **WHEN** сохранены два SAM-региона
- **THEN** каждая PNG-маска восстанавливается без потерь в координатах исходного изображения и связана только со своими локальными тегами

#### Scenario: Неполный импорт
- **WHEN** импортируется results_json без пикселей масок
- **THEN** теги и bbox могут сохраняться с признаком отсутствия масок, а запрос полного экспорта масок завершается явной ошибкой

### Requirement: Локальный каталог версий
Система MUST поддерживать необязательный локальный каталог результатов с выборкой по изображению, источнику, тегу и версии результата. Различные политики обработки MUST сохраняться как отдельные версии; повтор той же операции с тем же содержимым MUST быть идемпотентен.

#### Scenario: Изменение фильтра
- **WHEN** одно изображение сохранено с двумя разными политиками
- **THEN** доступны обе версии, их настройки и теги; маски могут переиспользоваться без смешивания версий

### Requirement: Надёжная публикация и загрузка
Читатель MUST получать только полностью опубликованный результат. Ошибка записи или повреждённый asset MUST NOT создавать успешную доступную версию. Загрузка и выборка MUST выполняться без моделей и проверять целостность ссылок.

#### Scenario: Сбой и конкурентная запись
- **WHEN** запись прерывается либо два процесса публикуют одну операцию
- **THEN** нет частичного результата или дубликата операции; повтор завершается или сообщает конфликт без потери опубликованных данных

### Requirement: Переносимый экспорт
Система MUST экспортировать выбранную версию в каталог с изображением, отдельными PNG-масками и JSON-манифестом, связывающим относительные пути, ключи регионов и локальные теги. Вырезки и обзор с номерами MUST быть доступными опциями; исходные данные MUST NOT изменяться.

#### Scenario: Перенос каталога
- **WHEN** экспортированная папка перенесена без исходной БД
- **THEN** изображение, маски и теги читаются по относительным ссылкам; перекрывающиеся маски и одинаковые имена исходных файлов не теряются
