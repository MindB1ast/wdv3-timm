# Design

## Context

ArtifactStore уже использует `.wdv3/index.sqlite3` как индекс артефактов/операций и `.wdv3/objects/<digest>/data` для бинарных данных. Это кэш расчётов, а не запрашиваемый каталог итоговых региональных аннотаций. `comfy_evidence.outputs` удаляет mask_png из строкового results_json. Save Result и Tag Folder умеют только error/overwrite, тогда как caption_files уже реализует error/skip/append/overwrite. Export Report умеет сохранять маски и ссылки, но не предназначен для версионированного каталога.

## Goals / Non-Goals

**Goals:** единый lossless-пакет, опциональная БД, надёжные связи регионов и масок, сохранение без обязательного явного evidence-пайплайна, переиспользование существующего кэша и безопасной записи.

**Non-Goals:** обучение, конкретный формат тренера, SQL-редактор/GUI-каталог, сервер БД, редактор масок, изменение логики фильтрации. Обзор экспортируется как файл, полноценный интерактивный каталог откладывается.

## Decisions

### 0. Файловый экспорт масок без предпросмотра

Этот этап выполняется независимо от `ResultPackage` и SQLite. `Export Report` принимает ровно один из `report` и типизированного `results`. В прямом маршруте переиспользовать `make_report` и файловый экспорт, не вызывая `preview_report`: без временных PNG предпросмотра, отрисовки рамок и построения IMAGE-тензоров. Явно выбранные выходные форматы отчёта продолжают работать. Нода `Inspect` и её маршрут `report` не изменяются.

В компактной ноде (`WDV3SaveRegionResults`) принимать ровно один из `results_json` и типизированного `results`. `include_masks` по умолчанию выключен; при включении требовать `results`, так как старый JSON пикселей не содержит. Сохранять маски только для регионов, выбранных существующими переключателями кадра, областей и глубины. Кадр без подходящих масок остаётся валидным. Не сохранять дополнительные цветные вырезки или предпросмотр в компактном режиме.

Компактный экспорт записывает отдельные PNG без потерь, одного канала, `0/255`, в координатах и размере исходного кадра. Ссылку `mask_asset` записывать относительным путём в той же записи, где `source`, ключ региона, `bbox` и выбранные локальные теги. Имена файлов выводить из безопасного ключа кадра и источника с `region_uid` либо `region_id`, не из текста тегов; исключить коллизии и выход из каталога. Если маски у записи нет, поле `mask_asset` отсутствует. JPEG и отдельный битовый формат маски не входят в этап.

Проверять возможность записи и вход до файловых операций. При включённых PNG не публиковать новый JSON до успешной записи всех масок, на которые он ссылается; `skip` не должен создавать новые assets при пропуске, а неудачный `overwrite` — ломать ссылки ранее опубликованного JSON. Прежний компактный режим без масок сохраняет формат и режимы записи.

### 1. ResultPackage и отдельные идентичности

Ввести тип WDV3_RESULT_PACKAGE с schema_version, image_key, image size/digest, snapshot_id, policy_digest, source settings, необязательным merged result и списком регионов. Ключ изображения не равен одному basename; путь датасета хранится отдельно от хеша пикселей. В одном пакете обрабатываются все кадры с dataset-relative mapping, если он известен. Для одиночного IMAGE без имени сохраняется стабильный ключ по содержимому и явно задаваемая метка экспорта.

Ключ региона составляется из snapshot/image, source/stage и region_uid; для плоских результатов используется source+region_id. Числовой region_id сам по себе не уникален. Сохраняются parent key, bbox исходной картинки, general/character/ratings, принятые и доступные raw scores, provenance, локальные/агрегированные теги и история без подмены друг другом. Нет оценки — null/отсутствие, а не 1.0.

Маска — отдельный PNG 0/255 размера исходного изображения с checksum и явной системой координат; cropped-маски адаптируются по проверенной геометрии. Вырезки являются производными. Неполный legacy results_json допускается как tags-only, с capabilities и запретом выдавать его за полный пакет. Пакет не требует merge.

### 2. Каталог поверх существующего SQLite

Добавить result-schema metadata и таблицы result_snapshots, result_images, result_regions, result_tags, result_assets со связями и индексами по image/source/tag. Детальные настройки и история допустимы в JSON, но связи и поиск тегов не требуют сканирования JSON. Все ключи включают snapshot при необходимости; raw и accepted различаются. Пользователь выбирает локальный dataset/store; по умолчанию используется существующая .wdv3, а не второй несвязанный кэш.

Бинарные изображения/маски идут в существующие content-addressed blobs; SQLite хранит ссылки и метаданные. Вариант всех PNG в SQL BLOB отвергнут для этого change: повторяет существующий механизм и раздувает транзакции. Экспорт переносимого каталога покрывает работу без БД. Хранилище результата опционально и не заменяет файловый режим.

snapshot digest зависит от полного содержимого пакета и политики. Идентичный save с тем же operation_id идемпотентен; иное содержимое под тем же operation_id — конфликт. Новая политика создаёт новую версию. Поиск возвращает refs/метаданные с пагинацией; latest выбирается явно по committed sequence, без зависимости от часов.

### 3. Публикация и восстановление

Сначала проверить пакет и опубликовать blobs атомарно, затем одной SQLite-транзакцией записать snapshot, связанные строки и запись операции. Читатели видят только committed snapshot. Ошибка SQL оставляет максимум неиспользуемые blobs, не частичную версию; автоматическая очистка не входит. Проверять checksum при чтении, foreign keys и schema version. Миграции каталога транзакционные и аддитивные; существующие metadata store и inference keys не переписываются. Новая неизвестная версия отклоняется до изменения БД. Восстановление из пакета не запускает моделей.

### 4. Интеграция и сохранение

Добавить выход result_package после существующих выходов Tag Image / Regions и Tag Folder. Формировать пакет до потери mask_png, не повторяя инференс. Tag Folder сохраняет текущую пакетность обработки; запись в каталог/файлы выполняется по кадрам или батчам, графовый выход имеет те же ограничения накопления, что прежние outputs. Отдельные Save Result Package, Find Stored Results, Load Stored Results работают с общим store settings/ref; адаптер просмотра принимает пакет без запуска моделей. Не создавать параллельные настройки БД, если совместим Calculation Store Settings.

Файловая ревизия: общий Result Save Settings содержит независимые TXT mode и JSON/package mode, пути и флаги assets. Старый overwrite используется при отсутствии конфига; при наличии конфиг определяет режим, а явно противоречащий legacy overwrite=true отклоняется. Неоднозначный конфликт API preflight проверяется до IO. Добавление новых входов опционально, выходов — в конец; старые индексы сохраняются. Показ настроек файлов зависит от включённого сохранения, backend API остаётся источником валидации.

TXT append переиспользует caption_files parsing/dedup/atomic plan semantics. JSON описывает новый вычисленный результат, а не объединённую пользовательскую TXT-подпись. Полный пакет — атомарно опубликованный manifest последним, с отдельными PNG/изображением и опциональными crops/preview; относительные пути не выходят за export root. Не обещать общую транзакцию БД и файлов: отчёт по каждому назначению и возможность безопасного повтора.

### 4.1. Условная обязательность входов Save Result

results_json сделать optional в схеме ComfyUI. При save_txt=true и подключённом
tags сохранять выбранную строку напрямую, проверяя result_index по списку tags,
без обязательного JSON и без его разбора при save_json=false. Если tags отсутствует,
для TXT требуется results_json и действует прежнее форматирование из результата.
При save_json=true требуется валидный results_json, независимо от наличия tags.
Если сохраняются оба формата и подключены оба списка, проверить их соответствие
по длине и выбранный индекс до записи любого файла. Оба save-флага false — ошибка.
Preflight проверяет наличие необходимых подключений по постоянным save-флагам;
исполнение повторяет проверки для динамических значений через API.
Старые корректные графы с обоими входами продолжают работать.

### 4.2. Компактный экспорт текущих результатов

Save Region Results принимает существующий список results_json или типизированный results (см. этап 0). Записывает один
`<filename>.regions.json` с `schema_version` и `images`; result_index=-1 выбирает
весь батч, неотрицательный индекс — один кадр. По умолчанию сохраняются теги
полного кадра и собственные принятые теги регионов списками, source, region_id,
bbox и доступные ключи каскада. Оценки, рейтинги, общий caption, агрегаты и история
включаются независимо. Подробные raw_scores и пиксели не нужны для этого профиля.
Режимы записи error/skip/overwrite. Этот профиль реализуется независимо от БД
и последующего lossless-пакета. Существующая Save Result сохраняет полный JSON.
`include_full` и `include_regions` выбирают раздельные области независимо.
`include_general` и `include_character` выбирают категории принятых тегов
во всех сохранённых наборах и caption; `include_ratings` остаётся отдельным.
История при явном включении сохраняет исходные решения для объяснения фильтров.
Настройки действуют только на экспорт и не меняют принятые теги upstream.
Все три добавляемых переключателя по умолчанию включены для прежних workflow.


### 5. Примеры и проверки

Для каждой новой ноды зафиксировать соответствие node → workflow → assertions. Сценарии: один IMAGE с двумя масками без Evidence-ноды; папка с одинаковыми basename и несколькими батчами; каскад; две версии фильтров при общих масках; tags-only импорт; сохранение/поиск/загрузка/экспорт; все режимы записи, гонка и прерванная публикация. Детерминированные fixture masks/raw проверяют семантику, реальный ComfyUI валидатор и API проверяют схемы; отдельный smoke с реальной SAM отмечается отдельно. Ожидания не перегенерируются по текущему результату автоматически.

## Risks / Trade-offs

- [Результат ошибочно воспринимают как evidence] → capabilities и раздельные refs; пакет без полных raw не обещает refilter.
- [Маски потеряны до Save Result] → структурированный выход создаётся до outputs; legacy JSON не восстанавливает потерянные данные.
- [Смешивание вариантов обработки] → immutable snapshots, явный выбор версии, FK и тесты перекрёстных связей.
- [Копирование только sqlite теряет PNG] → документировать перенос всей .wdv3 либо переносимый экспорт; резервное копирование открытой SQLite через sqlite backup API.
- [Большие батчи и дублирование payload] → общие blob refs, сохранение батчами, профиль памяти на фиксированном наборе.

## Migration Plan

Сначала прямой файловый экспорт без предпросмотра (этап 0). Для остальной части — схема пакета/каталога и совместимые миграции, затем ноды, адаптеры старого сохранения и примеры. Существующие файлы и evidence не импортируются автоматически. Откат: отключить новые входы/ноды и использовать прежние выходы; новые таблицы и blobs сохраняются, старая версия не должна переписывать неподдерживаемую схему каталога.
