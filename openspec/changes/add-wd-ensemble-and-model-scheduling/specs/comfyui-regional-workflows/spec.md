# Spec Delta

## ADDED Requirements

### Requirement: Подключение ансамбля вместо WD-модели
Ансамбль MUST выдавать совместимый wd_model для Tag Image / Regions, Tag Folder и Collect Evidence. Участники, селекторы областей и стратегии MUST переноситься через workflow/API и конфиги. Старый граф с одной моделью MUST сохранять поведение.

#### Scenario: Тегирование папки ансамблем
- **WHEN** два участника подключены к Ensemble, а его wd_model к Tag Folder
- **THEN** папка тегируется с выбранной политикой без дополнительных обязательных узлов обработки

### Requirement: Последовательное выполнение с выгрузкой
В sequential для каждого рабочего пакета система MUST выполнить нужную детекцию с соблюдением зависимостей, сохранить геометрию, затем выполнить WD. Смена модели MUST освобождать предыдущую модель в соответствующем пуле ресурсов. При готовом кэше веса MUST NOT загружаться.

#### Scenario: Родитель и два детектора
- **WHEN** дочерняя SAM-стадия зависит от родительской YOLO, а два WD используют найденные регионы
- **THEN** родитель вычисляется первым, ненужные веса освобождаются, WD выполняются по очереди только на своих входах

### Requirement: Ограниченное параллельное выполнение
В parallel независимые готовые задачи MUST выполняться в пределах лимитов одновременности, устройств и памяти. В auto система MUST выбирать режим по доступной информации о ресурсах и использовать последовательный режим при недостатке данных. Родительские зависимости и детерминированный порядок результатов MUST соблюдаться в обоих режимах.

#### Scenario: Независимые ветки
- **WHEN** есть две независимые детекции и достаточный лимит
- **THEN** исполнитель допускает параллельную работу, а зависимый ребёнок ждёт своего родителя

### Requirement: Раздельные батчи и отчёт выполнения
Система MUST позволять отдельно задавать рабочий пакет изображений, батчи детекторов, WD полного кадра и WD регионов. Отчёт MUST показывать выбранный режим, кэш, фактические батчи, загрузки, выгрузки и ошибки. Сбой MUST NOT публиковать частичный результат как полный.

#### Scenario: Сбой и повтор
- **WHEN** одна модель завершилась ошибкой после публикации независимых готовых стадий
- **THEN** итоговый результат не объявляется готовым; повтор переиспользует завершённые стадии и освобождает ресурсы после ошибки

### Requirement: Рабочие демонстрации ансамбля и режимов
Каждая новая нода MUST иметь комментированный исполняемый workflow с фиксированным ожидаемым поведением. Проверка MUST показывать результаты объединения, порядок выполнения, предел одновременности и переиспользование кэша; недоступные аппаратные проверки MUST отмечаться явно.

#### Scenario: Один граф в двух режимах
- **WHEN** демонстрация выполняется на одинаковых фиксированных оценках последовательно и параллельно
- **THEN** итоговые теги, регионы и происхождение совпадают, а отчёт отражает различный порядок запуска
