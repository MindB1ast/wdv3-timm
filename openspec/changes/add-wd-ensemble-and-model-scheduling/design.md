# Design

## Context

Текущий WDRuntime предполагает одну сеть, словарь и transform; RegionTagger получает оценки из него, а model_identity связывает кэш с файлами модели и preprocessing. Каскад уже разделяет детекцию и WD и закрывает SAM-процессы после детекции, но держит SAM workers по моделям до конца фазы. Low memory освобождает WD перед SAM, но не задаёт общий бюджет или последовательность моделей. Tag Folder уже читает данные рабочими пакетами.

## Goals / Non-Goals

**Goals:** одинаковый интерфейс одиночной модели и ансамбля, настройки полноты по категориям, повторное объединение из кэша, управляемые ресурсы на одном компьютере.

**Non-Goals:** автоматическая калибровка уверенности, гарантии реального ускорения на одном GPU, распределённый планировщик, новые модели и изменения региональной топологии. Сохранить прежние значения без включения нового режима.

## Decisions

### Модель и правила объединения

Ввести общий интерфейс batch scoring и identity, адаптировать старый runtime. Ensemble содержит ссылки на ленивые runtime, стабильные IDs участников, селекторы full/regions/all + имена источников и политику каждой категории. Узел конфигурации проверяет пустые группы, дубли ID, веса, ссылки и выбранные источники до выполнения соответствующих задач. Каждый участник использует свой transform и словарь. Выравнивание по (category, canonical name), отсутствующая пара пропускается. Совпадение имени разных категорий сохраняет две категории. max берёт максимум, weighted_mean использует только положительные веса доступных оценок, selected использует только выбранный источник; нулевой знаменатель даёт отсутствие оценки. Ошибка участника останавливает публикацию полного результата, не имитирует отсутствие тега. Порядок редукции стабилен. Применять пороги/правила после объединения. Inspect показывает вклады и метод, ratings не добавляются в текст автоматически.

### План задач и память

Для каждого ограниченного пакета построить зависимости: декодирование → детекция корней → детекция детей → подготовка выбранных WD-входов → WD по участникам → объединение → фильтрация/merge/export. Каскад ограничивает готовность ребёнка исходным bbox родителя. Группировать готовые задачи по model identity, чтобы загрузить веса один раз на группу, не делая барьер для всего датасета. По умолчанию новая политика выключена, legacy пути остаются доступны.

- sequential: одна загруженная модель детекции за раз, завершить детекцию пакета, закрыть детекторные ресурсы, затем одна WD за раз. Выгружать при переключении и завершении, сохранять результаты в промежутке. Освобождение означает закрыть SAM worker или убрать ссылки на сеть и освободить её ресурсы; перенос на CPU сам по себе не считается освобождением RAM.
- parallel: планировщик допускает несколько независимых задач при соблюдении device/host лимитов и max_concurrent, не вызывает один runtime конкурентно без гарантии потокобезопасности. Детекция и WD остаются отдельными фазами пакета. Публикация и объединение стабильны по image/stage/model ID, а не по моменту завершения.
- auto: использовать оценку потребления и доступную RAM/VRAM с резервом пользователя. При неизвестной цене задачи запускать её последовательно. Не обещать точный прогноз пика. При подтверждённой нехватке памяти закрыть ресурсы и один раз повторить незавершённую задачу в sequential с меньшим батчем, если разрешён fallback; остальные ошибки передавать явно. Применить те же настройки модели и входы.

Отдельные размеры рабочей порции файлов, YOLO/SAM-батчей и WD full/region batches. Применять только реально поддерживаемые батчи адаптера и показывать фактическое значение. Размеры, max_concurrent и бюджет сохраняются в конфиге; legacy low_memory_mode остаётся совместимым при отсутствии нового конфига. В новом режиме явная политика ресурсов имеет приоритет. Закрытие при исключении/отмене через контекст владения ресурсом.

### Кэш и идентичность

Ключ детекции — изображение/родительская геометрия/детектор и его настройки. Ключ WD — input view и конкретные веса/словарь/transform участника. Ключ объединения — набор raw refs, выбор областей и политика. Размеры батчей и выбор последовательности не подменяют эти ключи; identity устройства/точности сохраняется там, где влияет на вычисление. Совместимые legacy raw допустимо переиспользовать после проверки полноты. Reuse_only отклоняет недостающие вычисления до загрузки. Частичные завершённые стадии доступны для повтора, общий result публикуется только после полного завершения. Фиксированные fixtures проверяются точно; реальный backend — с документированным допуском для оценок и проверкой порогов отдельно.

## Risks / Trade-offs

- [Max усиливает одиночные ложные кандидаты] → настройка по категориям и видимые вклады.
- [Оценка памяти неточна] → консервативный auto, явный резерв и ограниченный fallback.
- [Глобальный барьер для папки копит память] → детекция и WD завершаются на ограниченном рабочем пакете.
- [Параллелизм делит ресурсы одного устройства] → явные лимиты и измерения, последовательный режим доступен всегда.

## Migration Plan

Добавить адаптер одиночного WD, затем ансамбль и раздельное хранение, после него исполнитель с явным включением. Проверить старые схемы и результаты. Старые конфиги сохраняют прежние defaults; откат — подключить одиночную модель и отключить настройки планирования. Никакой автоматической миграции/удаления результатов.
