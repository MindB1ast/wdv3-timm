## Purpose

Находить подходящие конкретные теги вне локальной базы знаний через исследование Danbooru и визуальное сопоставление исходной области с примерами.

## ADDED Requirements

### Requirement: Запрос на поиск недостающего тега
Субагент MUST принимать исходное изображение, целевую область, известные теги, описание искомой детали и результат локального поиска. Поиск MUST сохранять принадлежность кандидата конкретной области и исходные предсказания теггера.

#### Scenario: Металлические детали на перчатках
- **WHEN** теггер дал общие признаки перчаток, а локальная база не дала подходящего конкретного названия
- **THEN** субагент исследует название видимой детали для этих перчаток, не назначая его другим объектам кадра

### Requirement: Инструменты исследования словаря
Субагент MUST иметь инструменты чтения описаний тегов, импликаций, поиска изображений по сочетаниям тегов и просмотра их тегов в Danbooru. Он MUST поддерживать подключение веб-поиска как дополнительного источника, сохраняя происхождение найденных сведений.

#### Scenario: Поиск конкретизаций
- **WHEN** известен общий тег и несколько признаков области
- **THEN** агент может исследовать теги, подразумевающие общий тег, читать их описания и проверять изображения по сочетаниям признаков

### Requirement: Визуальная проверка кандидатов
Субагент MUST использовать VLM для сопоставления исходной области, описаний и изображений-примеров. Совместная встречаемость тегов на чужом изображении MUST NOT сама по себе подтверждать применимость кандидата к целевой области.

#### Scenario: Тег относится к другому предмету
- **WHEN** найденное изображение содержит похожие перчатки, но кандидат описывает обувь
- **THEN** наличие кандидата среди тегов изображения не считается подтверждением для перчаток

### Requirement: Проверяемый исход исследования
Результат MUST содержать кандидатов, источники, визуальное обоснование и статус подтверждения либо явное отсутствие подтверждённого ответа. Сбой инструмента или исчерпание бюджета MUST отличаться от завершённого поиска без ответа.

#### Scenario: Недостаточные свидетельства
- **WHEN** подходящее название не подтверждено изображениями и описанием
- **THEN** агент возвращает неопределённость без выдуманного тега

### Requirement: Передача найденных знаний
Субагент MUST формировать сведения для версионированной базы знаний с источниками и примерами. Найденный кандидат MUST отличаться от принятой записи; его принятие MUST следовать явно заданной политике.

#### Scenario: Найден новый кандидат
- **WHEN** исследование даёт отсутствовавший в базе тег
- **THEN** формируется кандидат записи с описанием и свидетельствами, не теряющий статус проверки при передаче в базу
