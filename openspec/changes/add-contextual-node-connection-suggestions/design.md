# Design

## Context

Мотивация — в `proposal.md`. Backend уже объявляет различные custom types через legacy INPUT_TYPES/RETURN_TYPES и V3 `io.Custom`: MODEL, OPTIONS, RULES, DETECTORS, SAM_MODEL, SAM_SOURCES, SAM_REGIONS, FILES, EVIDENCE, RESULTS, REGIONS, REPORT. Проблема относится к обнаружению производителей/потребителей в UI, а не к классификации изображений или отсутствию серверных типов.

В `web/tagger_inputs.js` динамически скрывается/восстанавливается незадействованный sam_regions у Tag Image / Regions; Combine использует V3 Autogrow. Выходы Load Pipeline Config имеют разные типы и индексы, а tags/results_json/пути используют общий STRING. Простого сопоставления по имени входа или подключения выхода 0 недостаточно.

В локально установленном frontend 1.57.4 прочитаны механизмы регистрации: штатное расширение собирает типы из node definitions и формирует `slot_types_default_in/out`, помещая Reroute первым и ограничивая список пользовательским лимитом. Canvas вызывает `showConnectionMenu` с nodeFrom/slotFrom или nodeTo/slotTo и отдельно использует поиск. Следовательно, типы могут уже быть совместимы, но нужные WDV3-ноды не приоритетны или не видны в коротком списке. Это наблюдение о данной установленной версии, а не обещание одинаковых внутренних APIs всех версий ComfyUI.

## Goals / Non-Goals

**Goals:** единый чистый резолвер по текущему каталогу и роли порта; корректные предложения в обе стороны; точный выбор порта; полное проверяемое покрытие WDV3.

**Non-Goals:** изменение custom type IDs, переименование options в opinion, изменение схем инференса/Bundle, запуск моделей при выборе, создание бизнес-нод из другого change, замена общего поиска ComfyUI или запрет сторонних совместимых связей. Обычные числовые/текстовые виджеты без входного сокета не превращаются в отдельные ноды ради подсказок.

## Decisions

### 1. Источник истины — зарегистрированные node definitions

Добавить чистый модуль `web/connection_suggestions.mjs` с каталогом `node_id → inputs/outputs/display_name` и функцией `suggestConnections(context, catalog)`. Контекст содержит направление связи, node_id, имя/индекс и тип актуального порта. Каталог строится из definitions, прошедших регистрацию ComfyUI, с адаптацией legacy и V3/Autogrow. Не создавать экземпляры вычислительных нод и не исполнять loaders для определения типов.

Каждый кандидат содержит node_id, отображаемое имя, целевое направление, точный slot name/index, type, semantic role и priority. Отсутствующий node_id не попадает в результат. Имена в UI берутся из текущего каталога, поэтому пользователь видит реальные названия вроде `WDV3 Load Tagger Model`, а не Python-класс или имя функции.

Реестр задаёт предпочтения ролей, но не является закрытым белым списком производителей. Остальные зарегистрированные совместимые ноды дополняют список, особенно для новых WDV3-типов. Дедупликация по `(node_id, direction, slot)`; два разных совместимых порта одной ноды остаются отдельными подписанными вариантами. Стабильный порядок: приоритет роли, display_name, node_id, индекс порта.

Альтернатива жёстко прописать три названия в tooltip отвергнута: это не меню выбора, не проверяет совместимость и не решает multi-output. Глобальная замена STRING на новые типы отвергнута из-за совместимости API и сторонних workflow.

### 2. Матрица основных производителей

| Роль/тип входа | Приоритетные зарегистрированные производители |
| --- | --- |
| wd_model / WDV3_MODEL | Load Tagger Model |
| options / WDV3_OPTIONS | Tagging Settings, Load Pipeline Config |
| rules / WDV3_RULES | Region Tag Rules |
| detectors, previous_detectors, Combine YOLO / WDV3_DETECTORS | YOLO Detector, Combine YOLO Detectors, Load Pipeline Config, legacy Load YOLO Detectors |
| sam_model / WDV3_SAM_MODEL | Load SAM 3.1, Load Pipeline Config |
| sources, previous_sources, Combine SAM / WDV3_SAM_SOURCES | SAM Text / Region Settings, Combine SAM Sources, Load Pipeline Config |
| sam_regions / WDV3_SAM_REGIONS | SAM Segment Images, Tag Image / Regions |
| files / WDV3_FILES | Image Folder |
| evidence / WDV3_EVIDENCE | Collect Evidence |
| results, left/right / WDV3_RESULTS | Apply Filters, Merge Results |
| regions / WDV3_REGIONS | Collect Evidence, выход regions |
| report / WDV3_REPORT | Inspect |
| images / IMAGE | Load Image, совместимые IMAGE-выходы текущего каталога |
| mask / MASK, когда есть такой вход | Совместимые MASK-выходы, включая SAM Segment Images, без смешивания с WDV3_SAM_REGIONS |
| results_json / STRING | Tag Image / Regions, Tag Folder, Apply Filters, Merge Results, выход results_json |
| tags / STRING | Выходы tags тех же нод и Inspect |
| пути файлов / STRING, если поле преобразовано в сокет | Выходы соответствующих путей экспорта; обычный строковый ввод остаётся доступен |

Таблица описывает текущий набор, а не необходимость создавать отсутствующий вход mask или ноды будущего change. Идентификаторы брать из NODE_CLASS_MAPPINGS и зарегистрированных definitions. Для нового custom type без заданного ранга использовать обычный discovery производителей/потребителей. Отдельная проверка перечисляет все порты WDV3 и запрещает незаметно пропустить новый тип: вход без реального производителя требует документированной причины (например, внешний стандартный тип).

`sources` пользователя соответствует существующему SAM Text / Region Settings (нода prompt/view); переименование UI в этом change не требуется. Для `opinion` используется существующий порт `options`.

### 3. Строковые роли задаются по контексту

Роль определяется парой `(node_id, port_name)` и явной семантикой выходов; нельзя считать любой STRING совместимым JSON или путём. Для WDV3-рекомендаций results_json подходят именно выходы results_json, а для tags — tags. При этом серверный тип и обычный ручной выбор остаются STRING. Сторонние порты STRING не получают глобального фильтра WDV3.

Не объявлять, что проверка совместимости типа валидирует содержимое JSON: проверки значений сохраняются в backend. Обычные IMAGE/MASK-порты пользуются штатными producers и совместимостью; рекомендации WDV3 дают удобный порядок без удаления нод других расширений.

### 4. Один адаптер штатного меню и поиска

Добавить `web/connection_suggestions.js`, который регистрирует расширение ComfyUI, собирает definitions и подключает резолвер к контекстному меню/поиску соединений. Использовать доступные API `app`/canvas и штатный механизм создания ноды. Конкретные методы изолировать в одном адаптере и проверять feature detection; не импортировать хешированные bundle-файлы установленного frontend.

Для custom types WDV3 предпочтения можно передавать штатному механизму default suggestions; для общих IMAGE/MASK/STRING обрабатывать только контекст WDV3, без глобальной перезаписи таблиц. Обёртки menu/search сохраняют вызов предыдущего обработчика для неприменимых контекстов и штатный полный поиск как продолжение списка. Не менять общий пользовательский лимит suggestions. При коротком списке основные ноды должны стоять перед техническим Reroute; остальные остаются доступны через штатный поиск/меню.

Инициализация идемпотентна: маркер установленной обёртки, отсутствие повторного append, пересборка каталога после регистрации/обновления definitions. Резолвер читает текущий порт при открытии меню: не хранить старый индекс sam_regions до его восстановления и не фиксировать один индекс всех autogrow-входов. Неподдерживаемая версия frontend не ломает canvas: сохраняет native поведение и понятную однократную диагностику; заявленная поддержка проверяется на фактически установленной версии.

Альтернатива полностью заменить меню LiteGraph отвергнута из-за конфликтов с другими расширениями и разницы frontend-режимов. Одной сортировки global type lists недостаточно для разных ролей STRING и выбора конкретного multi-output-порта, поэтому нужен контекстный адаптер.

### 5. Создание и подключение

Результат выбора передаёт точный порт источника/потребителя; после создания найти порт по имени и подтвердить тип по актуальному definition, затем выполнить штатное соединение. Не полагаться на `connect(0, ...)`. Для нескольких однотипных портов показывать `Нода · имя порта`, например Merge Results · left / right.

Создание/соединение включить в обычный undo/redo ComfyUI. Отмена не оставляет ноду. Занятый порт не переподключается без явно начатой операции переподключения, прежние ветви не удаляются. Выбор элемента не запускает очередь, модели или скачивание. Позиция создаваемой ноды соответствует точке вызова меню и направлению связи.

Для протягивания от выхода строится обратный индекс потребителей из того же каталога. Уникальность, роли STRING и точные slot indices применяются симметрично. Если Combine имеет свободный динамический вход, использовать его актуальный slot; создание следующего свободного входа остаётся обязанностью штатного Autogrow.

### 6. Независимость от соседнего change

`add-persistent-evidence-and-caption-file-workflows` пока содержит план новых loaders/configs/store/TXT-нод. Этот change не создаёт их и не показывает несуществующие пункты меню. Discovery автоматически подхватывает их после регистрации; при появлении нескольких выходов общего типа добавляется явная роль/приоритет. Проверки используют синтетическую дополнительную ноду как контракт расширяемости, поэтому реализации change можно выполнять в любом порядке.

Документация содержит полную матрицу фактического каталога и пользовательские действия вход → меню → выбор → корректная связь, а также обратный путь от выхода. Server API/workflow JSON не получают новых обязательных полей и не требуют миграции вычислительных типов.

## Risks / Trade-offs

- Разные frontend-режимы и версии используют разные menu/search APIs → адаптер и feature detection, браузерная проверка фактического сценария, штатный fallback без падения.
- Штатная регистрация может перезаписать default suggestions → финальная пересборка после загрузки каталога и проверка повторной регистрации/смены пользовательского лимита.
- Один тип STRING скрывает назначение → контекстные роли без глобального изменения совместимости и без ложного обещания проверки содержимого.
- Динамические порты и multi-output → разрешение актуальных слотов по имени/типу и тесты Load Pipeline Config, Collect Evidence, Combine.
- Конфликт расширений → цепочка предыдущих обработчиков, отсутствие глобального сброса чужих подсказок, одноразовая регистрация.

## Migration Plan

1. Добавить чистый каталог/резолвер и тестовую матрицу фактических definitions.
2. Подключить адаптер меню/поиска, проверить обе стороны, автосоединение и динамические порты.
3. Выполнить браузерную приёмку и regression старых workflow/API; обновить документацию проверенной версии.
4. Откат — отключить новое frontend-расширение; backend-типы, ноды и существующие workflow сохраняются.
