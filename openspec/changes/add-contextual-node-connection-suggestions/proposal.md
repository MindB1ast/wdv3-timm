# Proposal

## Why

Пользователю приходится помнить, какая нода создаёт данные для каждого входа WDV3, хотя типы портов уже объявлены. При построении workflow нужны контекстные предложения совместимых нод с правильным выходом, чтобы `wd_model` сразу предлагал Load Tagger Model, а `options` — Tagging Settings.

## What Changes

- Добавить подсказки создания/подключения совместимых нод из контекста входа и при протягивании связи на пустое место canvas; использовать штатное меню/поиск ComfyUI.
- Охватить все зарегистрированные WDV3-типы, включая WD, options, rules, YOLO, SAM-модель/источники/регионы, файлы, evidence, results, regions и report; учитывать обычные IMAGE/MASK/STRING-порты по их назначению.
- Показывать основные ноды первыми: `wd_model → Load Tagger Model`, `options → Tagging Settings`, `sam_model → Load SAM 3.1`, `sources → SAM Text / Region Settings / Combine SAM Sources`, `detectors → YOLO Detector / Combine YOLO Detectors`.
- Учитывать Load Pipeline Config и другие реально зарегистрированные совместимые выходы, автоматически подключать нужный порт выбранной ноды, а не всегда выход 0.
- Поддержать обратный сценарий от выхода к совместимым потребителям, динамические входы Combine и восстановление workflow.
- Не менять серверные type IDs, семантику расчётов и общие настройки ComfyUI; для строк отличать теги, JSON и пути без глобального вмешательства в STRING.
- Добавить проверяемый реестр ролей/приоритетов поверх фактических node definitions и проверку покрытия, чтобы новые ноды автоматически попадали в совместимые предложения.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `comfyui-regional-workflows`: контекстный подбор совместимых нод и корректных портов при построении графа, в обе стороны соединения.

## Impact

Изменения преимущественно frontend: новый модуль реестра/резолвера рекомендаций и адаптер ComfyUI в `web/`, интеграция с существующими autogrow/`tagger_inputs.js`, профильные Node.js и браузерные проверки, `docs/comfyui.md`. `comfy_nodes.py`, `comfy_ui_nodes.py`, `comfy_pipeline_nodes.py` и `/object_info` являются источником контрактов портов; их вычислительное поведение менять не требуется. Change не зависит от реализации `add-persistent-evidence-and-caption-file-workflows`, но должен подхватывать его новые типы и ноды после их регистрации. Создание самих TXT/store-нод и изменение названий/типов существующего API в scope не входят.
