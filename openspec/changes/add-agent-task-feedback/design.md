# Предварительный дизайн

## Context
Будущие роли поиска и проверки уже описаны в отдельных change. regional-tag-optimization содержит реестр экспериментов над профилями, но не универсальную обратную связь по каждой попытке. См. proposal.md.

## Goals / Non-Goals
Общая запись для разных задач, привязанная к результатам и свидетельствам. Автоматическое обучение по журналу не входит.

## Decisions
- Разделить задачу, попытку, результат и оценку. Один статус «успех» теряет различие между завершением поиска и правильным ответом.
- Хранить наблюдаемые действия, запросы, ответы инструментов или ссылки на них и краткое обоснование. Не требовать внутренние рассуждения модели.
- Оценки пользователя, другого проверяющего и самого агента различать по происхождению. Исправления добавляются с историей.
- Связывать журнал с версиями результатов и знаний, не копировать весь каталог изображений. Реестр экспериментов можно связать через идентификатор запуска.

## Risks / Trade-offs
- Самооценка ошибочна → отдельная проверенность и источник оценки.
- Повтор доставки создаёт дубликаты → стабильные идентификаторы событий.
- Большие артефакты → ссылки на хранилище с контролем доступности.

## Migration Plan
Добавить журнал независимо от существующих результатов; старые попытки не объявлять восстановленными без свидетельств. Отключение сбора не удаляет историю.

## Open Questions
Перед реализацией уточнить место хранения, интерфейс ввода/просмотра фидбека и критерии успеха для каждого типа задач. Это предварительный план; критерии не угадываются.
