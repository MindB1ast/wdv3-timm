## Purpose

Сохранять проверяемую историю исходов и обратной связи по разным задачам агентов, чтобы анализировать неудачи и повторно использовать успешный опыт.

## ADDED Requirements

### Requirement: Запись попытки агентной задачи
Система MUST сохранять тип задачи, идентификаторы задачи и попытки, агента и его версии, входы, результат и время выполнения. Для задач об изображении запись MUST ссылаться на изображение и доступные объект/регион; отсутствие такой привязки MUST отмечаться явно.

#### Scenario: Поиск тега для объекта
- **WHEN** агент исследует конкретные перчатки на изображении
- **THEN** запись связана с этой областью и поисковой задачей, а не только с названием тега

### Requirement: Объяснение успешных и неуспешных исходов
Запись MUST содержать выполненные действия, существенные запросы, источники и артефакты результата либо причину неудачи. Она MUST различать успешный результат, отсутствие решения, частичное выполнение, ошибку инструмента и остановку по лимиту.

#### Scenario: Тег найден
- **WHEN** поиск нашёл подходящий тег через описание и изображения
- **THEN** журнал сохраняет тег, путь поиска и свидетельства применимости

### Requirement: Неудача не доказывает отсутствие тега
Неуспешная попытка MUST сохранять искомые признаки, проверенные варианты и доступную причину остановки. Она MUST NOT утверждать отсутствие тега в словаре лишь потому, что агент его не нашёл.

#### Scenario: Поиск оборвался
- **WHEN** инструмент Danbooru недоступен до завершения исследования
- **THEN** журнал фиксирует сбой инструмента и нерешённую задачу отдельно от завершённого поиска без ответа

### Requirement: Фидбек и оценка результата
Система MUST принимать обратную связь об успешности и корректности результата с указанием автора или оценщика, времени, основания и версии оцениваемого результата. Самооценка агента MUST отличаться от внешней проверки; исправления MUST сохранять историю.

#### Scenario: Успех опровергнут
- **WHEN** пользователь сообщает, что найденный тег относится к другой детали
- **THEN** новая оценка связана с прежней попыткой, её первоначальный результат и самооценка остаются доступны

### Requirement: Просмотр результатов по задачам
Система MUST предоставлять выборку записей по типу задачи, исходу, оценке и связанному изображению/региону. Повторные попытки MUST сохраняться раздельно и связываться с одной задачей.

#### Scenario: Повторный поиск
- **WHEN** первая попытка не дала ответа, а вторая нашла тег
- **THEN** можно получить обе попытки и объяснение успешного решения без потери предыдущей неудачи
