# Design

## Context

Мотивация: [proposal.md](proposal.md). Контракт: [delta-spec](specs/regional-tag-optimization/spec.md). Отправная точка — опубликованный `433d29b`, 55 проходящих регрессий, Pylint 10/10 и проверенные Python 3.11/3.12.

Наблюдения по исходникам:

- `_BatchResources` и `_TaggingRuntime` используют `object`, неуточнённые коллекции; `tag_image` возвращает голый `Dict`, BatchTagging — неаннотированный кортеж или None.
- `tag_utils` владеет нормализацией/построением текста; `preprocess` объединяет ту же форму результата и provenance. Сохранение, визуализация и оценка читают вложенные словари.
- `_sample_metrics` использует нули для пустых множеств, `analyze_tagging_errors` — единицы, `analyze_tag_performance` снова вычисляет P/R/F1 отдельно.
- Общие P/R усредняются по изображениям, F1 — гармоническое среднее этих двух средних. Переход к среднему индивидуальных F1 изменил бы историческую агрегацию.
- В пользовательских настройках Pylance выбран standard, но проектные inlay hints отсутствуют. `.vscode/settings.json` сейчас игнорируется Git; одной локальной настройки недостаточно для воспроизводимой поставки.
- В `audit/test_fixes.py` есть точные проверки Recall=0.5 и исторического F1; `audit/fixtures/analytics-before.json` содержит графические/табличные снимки. Числа epsilon затронут эти ожидания намеренно, остальные свойства должны сохраниться.

## Goals / Non-Goals

**Goals:** типовая информация проходит через текущий module WD-обработки и его потребителей; статический потребитель видит поля/оценки; единая арифметика оценки; понятная проверка в редакторе и CLI; сохранение текущих runtime-контейнеров.

**Non-Goals:** новая модель владения ресурсами, универсальные adapter/registry для VLM, устранение распаковки ради уменьшения числа аргументов, переписывание фабрик/оформления графиков, ComfyUI, обучение моделей, новая формула агрегации F1. Положительная цель — уточнить существующий interface, а не нарастить промежуточные вызовы.

## Decisions

### 1. Структурные типы поверх существующих данных

Добавить небольшой `Scripts/types.py` с `TypedDict`, именованными type aliases и только необходимыми callable-контрактами. Использовать синтаксис, совместимый с Python 3.11; не применять оператор `type`, требующий Python 3.12. Runtime-результаты остаются обычными словарями/списками/кортежами. Альтернатива — заменить всё dataclass/Pydantic — отклонена: она потребовала бы преобразований, новых зависимостей и миграции вызовов.

Типы охватывают:

| Данные | Содержание и совместимость |
|---|---|
| Оценки тегов | Отображение строк в поддержанные сейчас Python/NumPy-скаляры, без изменения значений или округления |
| WD-результат | caption, taglist, general, character, ratings; provenance необязателен |
| Provenance | Нынешние модельные записи source/model_score и ручные source/assigned_score; без нового обязательного discriminator в JSON |
| Регион и вырезка | region_id, bbox; существующая тройка PIL-изображение/bbox/источник для внутренних вырезок |
| Подробный результат | image_path, full_image, detectors с именованными списками регионов |
| Объединённый результат | image_path, merged_tags, необязательный txt_path |
| Пакет | Кортеж двух списков; возврат None при отсутствии файлов остаётся допустимым |
| Оценка | Множества тегов по ID, целочисленные TP/FP/FN, значения P/R/F1 и опциональные diagnostics |

Для bbox сохранить `list[float]` и документировать четыре координаты `[x1,y1,x2,y2]`: tuple-замена не нужна ради выражения длины в аннотации. Преобразование изображения описать как PIL→Tensor. Модель и словарь — существующие nn.Module/LabelData; детекторы и загруженные YOLO имеют уточнённые коллекции. В конфигурации правдиво отразить поддержанные str/Path и None-сентинелы, сохранив их нормализацию и умолчания.

Не расширять тип WD-результата до обязательного формата будущей VLM: свободный текст уже запланирован отдельно. Нормализация и форматирование остаются в действующих вычислениях; `types.py` не становится новым forwarding-module.

### 2. Аннотации на переходах и вывод локальных типов

Аннотировать производителей/потребителей перечисленных данных: tagging, main, detection/model/configs, preprocess/tag_utils, evaluation/analitycs, savingProc/visualization. Уточнить поля существующих контейнеров, включая `_MergePolicy`; не объединять их в новую иерархию. Сохранить имена, позиционные аргументы и defaults; добавление return/parameter annotations допустимо.

Внутри helpers сохранять сведения о дополнительных полях региона при форматировании и deepcopy. При необходимости использовать ограниченный TypeVar, чтобы обработка базовых полей результата не стирала тип исходного расширенного результата. Не добавлять runtime-валидацию или новые копирования лишь ради удовлетворения checker.

Граница с фактически нетипизированными timm/Ultralytics/NumPy должна быть локальной: сужение результатов и небольшой callable-контракт по реально используемым операциям. Any не должен протекать в собственные публичные формы результата; широкие cast/ignore и замена object на Any не являются решением. Альтернатива аннотировать каждое присваивание отклонена: типы локальных переменных должны выводиться из понятного interface.

### 3. Общая арифметика оценки и фиксированный epsilon

В `evaluation.py` сосредоточить чистый расчёт TP/FP/FN и преобразование счётчиков в P/R/F1. Таблицы изображений и тегов используют те же операции; это не перенос или переписывание визуальных отчётов.

Единая константа `METRIC_EPSILON = 1e-8` — конкретизация предложенного в обсуждении значения. Новый пользовательский параметр или UI-переключатель не требуется. В этой версии политика фиксированная; значение не дублируется между функциями.

```text
P_i = TP_i / (TP_i + FP_i + epsilon)
R_i = TP_i / (TP_i + FN_i + epsilon)
F_i = 2 * P_i * R_i / (P_i + R_i + epsilon)

P = mean(P_i)
R = mean(R_i)
F1-score = 2 * P * R / (P + R + epsilon)
```

Для статистики тега P/R/F1 считаются той же операцией по его суммарным счётчикам. Средние P/R делятся на действительное N; epsilon не добавляется к N, coverage или статистике числа тегов. Округление — только при отображении.

Пустая строка: все счётчики и метрики нулевые; отсутствие с обеих сторон не создаёт ошибки. Пустой эталон с одним предсказанием: FP=1. Непустой эталон с пустым предсказанием: FN равен числу эталонных тегов. Пустая выборка по-прежнему вызывает ValueError; неверные/лишние ID не маскируются epsilon. Пропущенные предсказания участвуют как пустые с прежней диагностикой покрытия.

Альтернативы — особые ветви с единицей при пустоте, epsilon только в F1, усреднение F_i вместо прежнего F1 — противоречат согласованному поведению. В полностью правильном примере P/R/F1 будут чуть ниже единицы; не компенсировать это округлением или добавлением epsilon к числителю.

### 4. Версия политики и совместимость оценщика

Сохранить обычные ключи `Precision`, `Recall`, `F1-score` и return shape. Расширить только опциональные diagnostics полями `metric_policy_version` и `epsilon`; существующее `F1_definition` уточнить, сохранив обозначение harmonic mean of samples-averaged Precision and Recall и добавив epsilon.

Notebook-сравнение показывает политику и epsilon вместе с определением агрегации. Сохранить прежние CSV-столбцы и формат чисел; не добавлять столбец версии ко всем строкам. Ранее сохранённые эксперименты не переоцениваются и не переписываются; сравнение результатов разных политик требует пересчёта обеих сторон одной версией.

Завершённый fix-audited-tagging-defects ещё не архивирован и дополняет тот же раздел оценки тремя сценариями. Новый delta сохраняет эти сценарии; при синхронизации сначала переносится прежняя ревизия, затем новая политика, чтобы прежнее описание не затёрло epsilon.

Основная спека ранее требовала отличать исторический F1 по имени; реализованный совместимый ключ — `F1-score`. Delta уточняет: различие показывается в описании/отчёте, ключ сохраняется. Сводка и строка изображения не обязаны численно совпадать при N>1, но используют одни счётчики и одну арифметику; это не противоречие политик.

### 5. Checker, редактор и поставка настроек

Использовать Pyright, чтобы CLI и установленный Pylance опирались на одну типовую систему. Добавить проектную конфигурацию: standard для проверяемых собственных источников, усиленную проверку нового модуля типов и положительных примеров; явно перечислить охват текущего pipeline. Модули графического оформления вне этого изменения не объявлять полностью строго типизированными. Исключить .venv/temp/models и отрицательные примеры из обычного успешного запуска.

Проверки содержат положительные `assert_type`/использования и отдельный отрицательный набор: неверное поле, строка вместо score, небезопасное обращение к optional-полю. Отрицательный запуск считается ожидаемым только при конкретных диагностиках; отсутствие импортов/checker не засчитывается как успех. Зафиксировать проверенную версию checker и действительно нужных сторонних stubs в `requirements-dev.txt`, не наращивая notebook runtime.

Включить `python.analysis.inlayHints.variableTypes` и `functionReturnTypes` в проектных настройках, сохранив остальные значения. Для воспроизводимости добавить узкое исключение `.gitignore`, позволяющее отслеживать только `.vscode/settings.json`, а не все локальные настройки VS Code. Путь интерпретатора остаётся переносимым `${workspaceFolder}/.venv/Scripts/python.exe`; глобальные настройки не изменяются.

Справочные источники: [Python typing](https://docs.python.org/3.12/library/typing.html), [Pyright configuration](https://github.com/microsoft/pyright/blob/main/docs/configuration.md). TypedDict описывает форму словаря статически и не заменяет runtime-проверки. Окружение Pylance задаётся выбранным VS Code интерпретатором; общий конфиг не должен содержать абсолютные пользовательские пути.

## Risks / Trade-offs

- [Типы формально есть, но значения остаются Any] → положительные/отрицательные потребители и проверка полей результата/LabelData; без широких ignore.
- [Сторонние типы неполны] → изолировать сужение на существующем seam, не подменять собственные формы данных универсальными object.
- [Новая арифметика ломает точные старые числа] → отдельные ожидаемые значения по согласованной формуле с допуском порядка 1e-12, без ослабления тестов фильтрации/сохранения.
- [Слепое обновление снимков скрывает изменения графиков] → независимо проверить delta только чисел epsilon; тексты, названия и форматы должны сохраниться. Ранжирование и выбор худших строк могут измениться из-за новых значений, особенно у пустых наборов и почти равных оценок; каждый такой эффект объясняется отдельно.
- [Локальные настройки попадают в Git] → отслеживать только переносимые проектные настройки, проверить diff и исключения.
- [Сложность растёт ради метрик кода] → не вводить новую фабрику, универсальный adapter, custom dataclass init или дополнительные промежуточные вызовы ради checker/Pylint.

## Migration Plan

1. Сохранить baseline текущих вызовов, ключей, JSON/CSV и численных соглашений в новых материалах приёмки.
2. Ввести описания данных и аннотации, подтвердить неизменность тегирования отдельно от численного изменения оценки.
3. Добавить общую арифметику и версию политики; обновить только затронутые ожидания метрик и снимков с объяснением каждого изменения.
4. Проверить checker, Pylint 10/10, регрессии, реальные notebook-ячейки и копии изображений в Python 3.11/3.12. GPU не становится обязательным критерием этого change.
5. Откат — вернуть код/аннотации и старый оценщик как одну согласованную версию. Пользовательские изображения, TXT, веса и старые отчёты не мигрируются.

## Open Questions

Блокирующих пользовательских решений нет. Точная версия Pyright и совместимых сторонних stubs фиксируется при реализации после проверки окружений; это не меняет выбранный подход. Конкретные типы/контракты будущих VLM и SAM остаются за границами этого change.
