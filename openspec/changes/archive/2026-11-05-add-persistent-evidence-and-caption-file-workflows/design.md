# Design

## Context

Мотивация и границы — в `proposal.md`. Сейчас `comfy_evidence.collect` собирает полные оценки в `Bundle`, но `_evidence_cache` удерживает только четыре кадра на runtime, `_sam_cache` — два набора сегментации. Кэш исчезает с процессом и объединяет несколько вычислительных стадий в один ключ кадра. `model_identity` требует уже загруженный объект модели, а часть идентичности детектора опирается на путь/mtime/size. Это недостаточно для планирования без загрузки моделей и долговременного доверия к данным.

`apply_filters` уже отделён от inference; `outputs` сохраняет `raw_scores`, но исключает исходные PNG и PNG масок. `Export Report` создаёт самостоятельный отчёт, меняя расположение assets; это пользовательский отчёт, не полноценный индекс повторного расчёта. `Bundle.from_json` проверяет оболочку, но не доказывает полноту словаря, входов и масок.

Notebook `save_tags_to_txt` пишет `image.txt`, объединяет существующие теги с новыми и сохраняет порядок; `TagManager` умеет явное добавление, удаление, замену и сортировку. ComfyUI `Tag Folder` пишет `image.png.txt` с boolean overwrite, а `Save Result` сохраняет выбранный результат с защитой от перезаписи. Существующие глобальные настройки уже вынесены в `options`; их не нужно возвращать в ноды выполнения.

## Goals / Non-Goals

**Goals:** общий для ComfyUI и будущих агентов планировщик над неизменяемыми артефактами; выборочный досчёт; работа с TXT без моделей; независимая, воспроизводимая запись подписей.

**Non-Goals:** реализация самого агента, поиск оптимальных правил, метрики качества, обучение/VLM, распределённые workers между компьютерами, сетевое хранилище, автоматический GC и эвристическое удаление «смысловых дублей». Не обещается сохранение каждого внутреннего тензора модели или отсутствие повторения незавершённой работы после аварии.

## Decisions

### 1. Хранилище артефактов и журнал запусков отделены от TXT

Добавить самостоятельные модули `Scripts/artifact_store.py`, `Scripts/inference_plan.py`, `Scripts/caption_files.py` и `Scripts/workflow_api.py` либо эквивалентные модули с этими ответственностями. Их публичные операции не импортируют UI ComfyUI; модельные зависимости вызываются только через ленивые исполнители отсутствующих стадий.

Для новой dataset-ветки пользователь задаёт `dataset_root`; служебное хранилище
по умолчанию разрешается как `<dataset_root>/.wdv3/`. Это сохранение evidence,
геометрии, raw-оценок и производных версий внутри папки датасета. Явное
переопределение store остаётся доступным, но output ComfyUI, текущий cwd или
временный кэш не подставляются скрыто. Формат v1:

```text
dataset/.wdv3/
  store.json                 # версия формата и store_id
  index.sqlite3              # индексы, зависимости, состояния, leases, idempotency
  objects/<sha256>/...        # неизменяемые JSON/PNG/массивы без pickle
  runs/<run_id>/manifest.json # запрос, ordered dataset entries, refs, итог
```

SQLite входит в стандартную библиотеку Python и позволяет транзакционно координировать локальные процессы. Индекс хранит метаданные и ссылки, не большие base64-строки. Blobs хранятся отдельно с контрольными суммами; массивы загружаются без `allow_pickle`. Сначала записываются и проверяются blobs, затем публикуется complete-запись в транзакции. Остатки незавершённых записей не выдаются как cache hit. Очистка и сетевые файловые системы вне scope.

Во всех новых dataset-сканерах исключать `.wdv3` и фактически выбранный store
внутри дерева до сбора изображений/подписей: сохранённые PNG, маски и служебные
TXT не становятся входным датасетом. Mapping исходных файлов хранится относительно
dataset_root и связывается с content digest; перенос всей папки вместе с `.wdv3`
не требует прежнего абсолютного пути. Для IMAGE без исходных путей явно требуется
dataset_root и mapping при экспорте в соседние TXT; имена из пикселей не угадываются.
Ошибка доступа к выбранному store диагностируется, без скрытой записи в другую папку.

Различать `computation_key` (ожидаемые входы/операция), `artifact_id` (конкретное неизменяемое содержимое) и `run_id` (исполнение). Refresh сохраняет новую версию и не заменяет bytes старой. Одинаковые blobs дедуплицируются, но факт повторного вычисления остаётся в журнале. Альтернатива одному огромному JSON отвергнута из-за частичного восстановления, расхода памяти и конфликтов нескольких writers.

### 2. Граф зависимостей вместо общего флага «уже готово»

Состав ключей и границы стадий:

| Стадия | Существенные зависимости |
| --- | --- |
| Идентичность изображения | Нормализованные исходные пиксели, размеры, версия декодирования/ориентации/alpha-policy |
| YOLO-геометрия источника | image_id, хеш весов и версии адаптера, classes, confidence и параметры детекции |
| SAM-геометрия источника | image_id, хеш модели/процессора/токенизатора, prompt, confidence/mask threshold и отбор масок |
| WD полного кадра | image_id, хеш весов и словаря, профиль preprocessing, версия inference, вычислительный профиль |
| WD вырезки | Хеш фактических пикселей вырезки и версия crop-policy, идентичность WD |
| Evidence изображения | Ссылки на полный кадр и выбранные именованные источники/регионы |
| Результат политики | evidence artifact_id, канонический policy hash, версия алгоритма фильтрации/merge |
| Текст | Принятые упорядоченные имена, параметры форматирования, версия formatter |
| План TXT | Текст/CaptionDocument, сопоставление путей, режим записи и исходный digest назначения |

Физический путь изображения, порядок обхода папки и batch sizes не входят в ключ инференса. Относительный путь и dataset_id сохраняются отдельно для экспорта: одинаковые пиксели могут делить расчёт, сохраняя две разные записи датасета. Имена источников и привязки регионов относятся к evidence-композиции, а не запрещают переиспользование одинаковых пиксельных вырезок.

Идентичность модели вычисляется из содержимого локальных весов, словаря и конфигурации, с pinned revision при наличии. Alias и mtime/size сами по себе недостаточны. Для уже загруженной custom-модели допускается подтверждённый digest state_dict. Неизвестная идентичность означает cache miss/диагностику, а не выбор произвольной старой версии по имени. Для reuse_only без локальных весов используются явно выбранные артефакты или сохранённые pinned identities; искать «последнюю модель из сети» запрещено.

Вычислительный профиль сохраняет версии адаптера/движка и dtype/device-класс, когда это влияет на совместимость результатов. Batch size — ресурсный параметр, не повод пересчитывать имеющийся результат. Гарантируется переиспользование зарегистрированного артефакта, а не побитовая независимость нового inference от любого железа.

Матрица минимального досчёта:

| Изменение | Что выполнить |
| --- | --- |
| Пороги WD, regex, allowed/ownership, prefix/suffix | Только политика и зависимый текст |
| Разделитель, `_`, экранирование | Только formatter и план экспорта |
| Новое изображение | Недостающие стадии этого изображения |
| Новый YOLO/SAM-источник | Его геометрия и отсутствующие WD-вырезки; прежние ветви/полный кадр сохранить |
| Padding или bbox/mask | Новые вырезки/WD при доступных масках; модель сегментации не запускать |
| Prompt, параметры геометрического отбора, confidence детектора | Затронутая геометрия и новые вырезки/оценки; другие источники сохранить |
| Новая WD-модель/словарь/preprocessing | WD полного кадра и вырезок; геометрию сохранить |
| Изменён TXT | Перечитать/перепланировать подпись, не инвалидировать модели |

Текущий backend хранит выбранные маски, а не все logits/неотсечённые предложения. Поэтому изменение SAM mask/confidence или YOLO confidence не обещает дешёвую повторную выборку из неполных данных: геометрическая стадия становится недействительной. Padding и подготовка вырезки должны быть отделены от модели сегментации. Внутреннее кодирование изображения для нового SAM prompt может понадобиться; сохранение SAM embeddings не входит в обязательный контракт v1.

Политику отделить от форматирования и ресурсных настроек до вычисления hash. Текущая `settings.options` смешивает эти параметры, поэтому для новых артефактов нужен нормализованный `PolicySnapshot` и `FormatSnapshot`, а не hash всего словаря options.

### 3. Планирование, ленивые модели и локальная координация

Публичный API имеет операции `plan`, `execute`, `status`, `load_evidence`, `import_calculations`, `plan_caption_export`, `commit_caption_export`. Данные запросов/ответов версионированы и пригодны JSON. CLI `python -m Scripts.workflow_cli <command> --request request.json` вызывает тот же API и выдаёт JSON/определённый exit code. Это инфраструктура агента, не LLM-цикл.

Режимы:

- `reuse` по умолчанию: проверить совместимость и целостность, загружать модели только для misses.
- `reuse_only`: выполнять CPU-постобработку сохранённых данных, но не разрешать модельные loaders, скачивание или inference; вернуть точные missing/invalid причины.
- `refresh`: явно выбрать стадии или весь запрос; заново вычислить выбранное и пересобрать зависимые артефакты, сохранив старые версии.

`plan` проверяет весь запрос и возвращает DAG действий, причины invalidation и refs, ничего не вычисляя и не экспортируя. Хеширование и валидация файлов допустимы; сетевые вызовы и модельные loaders нет. Если pin модели невозможно разрешить локально, план возвращает unresolved_identity с требуемым действием.

В API передаются описания моделей/настроек, а не обязательный `WDRuntime`. Исполнитель группирует готовые misses по модели и рабочему батчу; готовые артефакты не пропускаются повторно через inference. Для старого runtime-пути оставить адаптер, явно указав, что уже выполненную upstream загрузку legacy Model Loader невозможно отменить. Новая UI-ветка использует конфигурацию inference без eager-loader.

Задача стадии получает lease в SQLite с owner_token, сроком и heartbeat. Второй локальный процесс ждёт ограниченное время или получает waiting. После просрочки другой процесс может продолжить; complete принимается только с актуальным token (fencing). Падение между inference и публикацией может потребовать повторить только эту незавершённую стадию. Батч публикует результат по записям; отмена и ошибка сохраняют завершённое.

Стабильный `operation_id` идемпотентен: повтор с тем же содержимым возвращает прежний статус, другое содержимое с тем же id — конфликт. Изменение политики получает новый id/hash и отдельную ссылку на то же evidence. Отчёт содержит image_id, stage, source, computation_key, artifact_id, parent refs, status/reason и run_id. Он не заявляет метрики качества и не активирует профили автоматически.

### 4. Загружаемые evidence и импорт старых JSON

Новые evidence-снимки сохраняют полные general/character/ratings, словарь и профиль модели, геометрию, lossless маски и пиксели, достаточные для Inspect и пересборки вырезок. Для коллекции использовать manifest со ссылками, не загружать весь датасет в RAM: итератор/страницы, ограниченный batch и сборка выбранного `Bundle` для существующих Apply Filters/Inspect.

Поддержать импорт:

1. Evidence `Bundle` v1 с явной проверкой вложенных данных, ссылок и полноты.
2. JSON одного/списка текущих `results_json`: извлекать `raw_scores`, а не merged-теги; проверять число/категории меток против сведений о модели, source snapshots, image_id и региональные привязки.

Импорт публикует `capabilities`: `refilter`, `inspect_pixels`, `recrop_masks`, `resume_inference`. Если текущий JSON потерял PNG/маски, это не мешает refilter при полных оценках, но не даёт права обещать recrop. Доступные исходные файлы можно привязать только после проверки digest; отсутствие пикселей не должно запрещать чистую фильтрацию. Если нет данных, доказывающих полноту/идентичность, вернуть диагностику либо импортировать как ограниченный исторический результат, не выдавая его за полный cache hit.

TXT, обычный отфильтрованный merged JSON и HTML-отчёт не становятся evidence. Импорт `Export Report` со внешними assets не входит в начальный набор форматов: UI указывает на поддерживаемые форматы. Не менять raw_scores при применении новых правил. Альтернатива восстанавливать низкие вероятности из принятого списка отвергнута как недостоверная.

### 5. Отдельный контракт CaptionDocument и операции без моделей

`CaptionDocument` содержит item_id/dataset mapping, source_txt, исходные bytes/digest, упорядоченные канонические имена, происхождение и историю операций. Оценка необязательна: `existing_txt` и ручная правка не получают model_score. Ссылки на предсказания при объединении сохраняются отдельно. Этот документ не подменяет `WDTagResult` и его вероятности.

Read-конфиг:

- `input_format=comma_newline` по умолчанию, как notebook; UTF-8/UTF-8 BOM.
- `input_format=literal_separator` с непустым `input_separator`; запятые/переводы не добавляются скрыто к произвольному разделителю.
- Явное указание, были ли скобки экранированы formatter; никакого общего декодирования escape-последовательностей.

Входной разделитель независим от `options.tag_separator`. Пространства внутри имени канонизируются после выделения токена. Формат с пробельным разделителем при уже заменённых `_` неоднозначен: предложить comma_newline, явную токенизацию пользователем или структурированный список; не угадывать слова по WD-словарю. Неизвестные теги сохранять. Исходные bytes нужны для preview/conflict/unchanged, а не для реконструкции model_score.

Редактор принимает ordered список операций: add_before/add_after, remove с отдельным remove_regex, literal replace, sort (`preserve`, `alphabetical`, `priority` с упорядоченным списком). Внутри одной операции remove блокирует добавление, между операциями действует явный порядок. Нормализация/дедупликация стабильны. Эвристическое удаление «избыточных подтегов» и regex replacement не добавляются в v1. Пользователь явно выбирает, редактируется существующая подпись или только новый модельный кандидат.

Append объединяет документ назначения и новые теги: прежние имена/порядок, затем отсутствующие новые в их порядке; явные before/after следуют notebook-семантике без дублирования существующих имён. Новые модельные удаления не применяются задним числом к existing_txt. Для изменения старого тега пользователь передаёт результат редактора как новый полный документ в overwrite. Если append не добавляет новых тегов, вернуть unchanged и сохранить исходные bytes, даже если они не нормализованы. Для намеренного изменения только форматирования выбрать overwrite подготовленного документа.

### 6. План экспорта, режимы и защита от гонок

Отдельный `CaptionExportConfig`: target_root/in_place, naming (`stem_txt` default для notebook-паритета, `image_extension_txt`, explicit mapping), write_mode (`error` default, `skip`, `append`, `overwrite`), формат вывода и правила чтения существующего назначения. В новой dataset-ветке выбранный dataset_root задаёт default in_place=True: `sub/image.png` сохраняется как `sub/image.txt` рядом с исходником. Это явная пользовательская ветка экспорта; вычисления/эксперименты сами TXT не записывают. Альтернативный target_root задаётся отдельно. Прежние defaults Save Result/Tag Folder не меняются. Права filesystem остаются обычными правами процесса, дополнительных диалогов для уже выбранного режима не требуется.

Save Captions — последний этап текущего пайплайна: один TXT с итоговыми тегами
для каждого выбранного изображения, с общим форматированием и выбранной политикой
существующего файла. Raw-оценки не записываются в TXT и остаются в `.wdv3`.
После нового набора правил можно получить новую версию caption из того же evidence
и явно применить overwrite/append по плану. Дальнейшие этапы обучения, подготовки
нового формата или автоматического агентного цикла здесь не запускаются.

До исполнения построить `CaptionExportPlan`: resolved пути, проверка границ/коллизий (включая case-insensitive Windows), expected digest либо expected absent, исходные и итоговые имена, diff, формат, новый bytes hash, operation_id. dry-run не пишет TXT. Входной и выходной dataset mapping независимы от content-id: два изображения с разными путями могут иметь общие вычисления, но разные назначения.

`error`/`skip`/`append`/`overwrite` определяют поведение существующего файла; отсутствие — создать. Skip-существование нельзя считать evidence hit. Когда запрошен только этот TXT, планировщик не строит ненужные модельные зависимости; когда дополнительно запрошено evidence, проверяет его независимо. Старый `overwrite=false/true` адаптируется только к error/overwrite, не к append.

Commit берёт lock назначения для сотрудничающих процессов, повторно проверяет expected digest, пишет sibling temp, flush/fsync и выполняет атомарную замену; при expected absent используется защита от конкурентного создания. При несовпадении — conflict без потери новой внешней версии. Проверка не является глобальной транзакцией всей папки: журнал фиксирует outcome каждого файла, возобновление сравнивает уже записанный digest с фактическим. Ошибка середины папки не откатывает подтверждённые записи и не требует повторного inference. Произвольный внешний редактор не участвует в наших locks; проверка digest проводится непосредственно перед фиксацией.

После сбоя между заменой и подтверждением журнала восстановление распознаёт ожидаемый output digest, а не дописывает теги снова. Повтор operation_id возвращает подтверждённый результат только если destination не изменился извне; иначе conflict. Manifest записи не служит разрешением молча перезаписать последующую правку пользователя.

### 7. ComfyUI и конфигурация без новых дублей

Предлагаемые ноды (имена фиксировать в реализации и примерах):

- `Calculation Store Settings` → путь хранилища, reuse mode, refresh selection; отдельный подключаемый конфиг.
- `Inference Settings` → ленивые описания WD/YOLO/SAM без загрузки; переиспользовать существующие detector/source snapshots и модельные профили.
- `Plan Calculations` и `Compute Missing Evidence` → IMAGE либо FILES, конфиги и артефакты; выходы plan/evidence/run_report. Валидировать ровно один источник входных изображений.
- `Save Evidence`, `Load Evidence`, `Import Calculations` → явные переносимые refs/manifest, совместимые с Apply Filters/Inspect. Save регистрирует исходные расчёты, а не пользовательский отчёт.
- `Load Captions`, `Edit Captions`, `Combine Captions` → существующие TXT и структурированные теги results без модели.
- `Caption Export Settings`, `Plan Caption Export`, `Save Captions` → параметры чтения/назначения/режима, preview diff, явная запись и отчёт. Много полей редактирования объединяются в конфиг/упорядоченный список операций; не копировать их в ноду inference.

Политика тегов остаётся в Tagging Settings/Region Tag Rules, форматтер берётся из тех же options. Настройки store/export не копируются в Tag Image / Regions. Новые API-ноды работают без browser callbacks. Существующие Save Result/Tag Folder остаются совместимыми простыми путями; новую dataset-ветку направлять в общий writer через отдельный адаптер, не менять смысл старых аргументов.

Pipeline-пресет расширяется необязательными `calculation_store`, `inference`, `caption_read`, `caption_edit`, `caption_export`; пути описывают настройки, не включают веса, датасет или секреты. Старые пресеты продолжают работать. Рабочие manifest/артефакты не вкладывать в переносимый settings-пресет. Для нового store активировать reuse только через явно подключённые настройки; старый workflow не начинает сам писать кэш на диск.

Расширенные workflow (не обязательны для обычного тегирования):

```text
Папка → Plan Calculations → Compute Missing Evidence → persistent store
                                                    ↓
Load Evidence → Apply Filters ← Tagging Settings / Region Tag Rules
                     ↓
                 results → Inspect
                     ↓
Load Captions → Combine/Edit Captions → Plan Caption Export → Save Captions
```

Полностью готовый store: начинать с Load Evidence из `<dataset_root>/.wdv3`, без Model Loader. Далее существующие Filter Tag Sets → локальные операции → Merge Tag Sets (либо совместимый Apply Filters) → Plan/Save Captions, который завершает ветку соседними image.txt. Только редактирование TXT: Load Captions → Edit Captions → Plan/Save, без расчётных нод. Агент вызывает те же операции через Python/CLI, без передачи изображения в LLM.

## Risks / Trade-offs

- Размер raw scores, изображений и масок → blobs отдельно, дедупликация, чтение страницами; автоматическое удаление не входит в этот change.
- Изменение preprocessing, весов либо версии кода делает кэш недостоверным → содержательные ключи и версии операций; недоказанная совместимость означает miss.
- Старые JSON неполны для некоторых стадий → проверка capabilities; честный refilter-only вместо обещания полного resume.
- Одновременные локальные процессы → SQLite leases и fencing; NFS и распределённые workers не поддерживаются в v1.
- Свободные TXT и произвольные разделители неоднозначны → явный parser и независимый input_separator, сохранение исходного текста, отсутствие автоматической токенизации по WD-словарю.
- Потеря ручных тегов/эталонов → отдельный CaptionDocument, явный target/mode, diff и контроль версий назначения; отсутствие скрытого экспорта из эксперимента.
- Большой scope пересекает несколько модулей → последовательность задач по контрактам: storage, planner, import, TXT, UI/API, сквозная приёмка. Не внедрять агентный оптимизатор вместе с инфраструктурой.

## Migration Plan

1. Ввести версионированные store/API и тестовые артефакты, не меняя поведение старых workflow.
2. Адаптировать расчётные стадии к ленивому планировщику и импорту существующих результатов; проверить повторный запуск в отдельном процессе.
3. Ввести CaptionDocument и writer, затем новые UI-ноды и необязательные поля пресетов.
4. Добавить примеры новых режимов и документацию ограничений старых JSON/TXT; проверить notebook и старые API-вызовы.
5. Откат к прежней версии не удаляет store и пользовательские TXT. Новый store не импортируется старым кодом автоматически. Перед разрушительной миграцией будущей версии потребуется отдельная операция; v1 не обновляет неизвестный store молча.

## Уточнение UX от 2026-11-05

Основной маршрут сохраняет существующий граф: Load Tagger Model и YOLO/SAM-настройки → Tag Image / Regions либо Collect Evidence; для папки — Image Folder → Tag Folder. Постоянное evidence проверяется внутри этих нод до их inference. Отдельные Inference Settings, Dataset Files, Plan/Compute и Calculation Store Settings остаются расширенным интерфейсом, а не условием изменения фильтров.

Настройки кэша задаются через options из Tagging Settings: cache_mode (reuse/reuse_only/refresh/off), cache_dataset_root и cache_refresh. Для FILES папка по умолчанию берётся из Image Folder; для IMAGE пользователь указывает её один раз, так как IMAGE не содержит исходного пути. Любой режим дискового кэша IMAGE без пути сообщает ошибку вместо молчаливого fallback. Старые API options без cache_mode сохраняют поведение без постоянной записи. Все размеры батчей и параметры кэша исключаются из policy identity.

Load Tagger Model выдаёт DeferredWDRuntime со словарём/transform/device и читает только метаданные. Файловая identity local-files-v1 позволяет проверить кэш до создания сети; load_network вызывается при первом обращении к model на действительном miss. Legacy YOLO Loader также откладывает веса до детекции. Другие upstream-ноды ComfyUI не отменяются downstream-флагом: если SAM Segment подключён отдельно, его вычисление может потребоваться до тегирования. Для чистой загрузки старого evidence остаётся Load Evidence → фильтры. Старые state_dict-артефакты доступны по refs; смена способа identity может потребовать разового досчёта новых автоматических записей.

Надписи портов отделены от ключей сериализации: sources типа WDV3_SAM_SOURCES отображается как «sam_queries», фильтр имён — «detector_names», sources_json — «region_detectors_json». Типы, API-ключи, внутренние имена и индексы связей не переименовываются.

## Уточнения приёмки и устойчивости от 2026-11-05

### Простая работа с кэшем и результатами

Tag Folder использует `Image Folder/.wdv3`, когда переопределение папки пусто. Видимые `calculation_mode` и `dataset_folder_override` сохраняют прежние ключи `cache_mode` и `cache_dataset_root` и порядок виджетов. В ручном пути удаляются завершающие компоненты `.wdv3`, поэтому путь к служебному каталогу и путь к датасету разрешаются в одно хранилище. Выходная папка TXT/JSON не влияет на выбор кэша. При отсутствии расчётов сообщение указывает фактическую папку, изображение и стадии; `reuse_only` не подменяется новым инференсом. Существующий TXT при выключенном `overwrite` остаётся отдельной ошибкой записи с объяснением режима обновления или просмотра без сохранения.

Строковые входы получают примеры через общий слой подсказок без изменения сериализации. Рекомендации выхода `results_json` сначала показывают Results Viewer, а его вход перечисляет Tag Folder, Tag Image / Regions, Merge Tag Sets, Apply Filters и Merge Results с точными слотами. `preview_limit=0` передаёт все результаты, положительный лимит сохраняет прежнее ограничение первыми N; пустое значение старого workflow восстанавливается в 16. Все результаты и изображения большого датасета по-прежнему требуют памяти просмотрщика: это не ленивый постраничный интерфейс.

### Стоимость повторной фильтрации

Неизменяемый Bundle сохраняет компактный JSON и не рассматривается как Mapping при обходе удерживаемых тензоров ComfyUI; это убирает повторную распаковку полного словаря для служебного учёта памяти. Таблицы сопоставления готовятся один раз, а raw_scores и решения присоединяются после обработки небольшого набора принятых тегов. При отсутствии regex не выполняется отдельный диагностический проход. Владение снимком определяет необходимость копирования; исходное evidence остаётся неизменным. Результат сравнивается с baseline, а время очереди/клиента, исполнения графа и инференса учитывается раздельно.

### Windows и одновременная память WD/SAM

На Windows загрузка safetensors использует доступный немаппированный путь чтения, с совместимым чтением байтов для старого API. Веса и идентичность модели не меняются. Это исправление конкретного воспроизведённого сбоя чтения, а не обещание защиты от любых нативных ошибок.

SAM использует отдельный SamWorker и временные lossless PNG, проверенные маски читаются до удаления файлов. Процесс закрывается после сегментации; неожиданное завершение возвращает ошибку ноды с stderr, выделение памяти диагностируется отдельно. Большие WD-веса освобождаются перед необходимым SAM при `low_memory_mode=true` (по умолчанию), включая следующие изображения папки. Независимая геометрия вычисляется перед WD полного кадра и кропов. При выключении настройки WD остаётся в RAM, но SAM всё равно изолирован и закрывается: настройка не означает постоянное удержание SAM. В текущем постоянном маршруте SAM запускается отдельно для каждого изображения/источника с отсутствующей геометрией; удержание SAM на весь датасет не реализовано. Полный cache hit не вызывает SAM или освобождение WD, а изменение режима памяти не меняет ключи расчётов.
