# Spec Delta

## ADDED Requirements

### Requirement: Evidence внутри папки датасета
Новая dataset-ветка MUST по умолчанию сохранять evidence и служебные артефакты в `<dataset_root>/.wdv3/`. Исходные оценки, геометрия и версии MUST сохраняться отдельно от конечных TXT. Поиск входных изображений и подписей MUST исключать служебное хранилище. Сопоставление с файлами MUST сохраняться при переносе датасета вместе с хранилищем после проверки содержимого.

#### Scenario: Повторная обработка папки с кэшем
- **WHEN** датасет содержит изображения и `.wdv3` с PNG/масками и служебными записями
- **THEN** recursive-сканирование выбирает только исходные файлы датасета; служебные артефакты не тегируются как новые изображения

#### Scenario: Перенос папки
- **WHEN** датасет вместе с `.wdv3` перемещён в другой каталог и выбран новый dataset_root
- **THEN** совместимые evidence разрешаются по относительным путям и содержимому без зависимости от старого абсолютного расположения

### Requirement: Постоянные артефакты расчётов
Система MUST сохранять полные исходные оценки и геометрию в версионированном локальном хранилище, доступном после перезапуска. Завершённый артефакт MUST иметь проверяемую целостность, идентичность входов и зависимости. Фильтрация и форматирование MUST создавать отдельные производные результаты, не изменяя исходные свидетельства. TXT MUST NOT считаться полным evidence.

#### Scenario: Новая сессия без моделей
- **WHEN** полное evidence сохранено и процесс перезапущен без доступных весов моделей
- **THEN** пользователь загружает его и применяет новые правила без загрузки моделей, скачивания и инференса

#### Scenario: Готовый TXT без оценок
- **WHEN** для изображения существует только TXT
- **THEN** он доступен как подпись, но не позволяет восстановить отсутствующие оценки или отметить модельные стадии завершёнными

### Requirement: Переиспользование независимых стадий
Совместимость MUST определяться содержимым входов, версиями моделей, словаря, preprocessing и вычислительных операций. Полный кадр, геометрия каждого источника, оценки вырезок, политика и текст MUST иметь независимые зависимости. Изменение одного входа MUST инвалидировать только зависимые результаты; пути и время изменения файла MUST NOT служить единственным доказательством совместимости.

#### Scenario: Изменены правила и разделитель
- **WHEN** на прежних изображениях меняются пороги WD, regex или разделитель
- **THEN** исходные WD/YOLO/SAM-расчёты переиспользуются; изменение только разделителя требует лишь нового представления и экспорта

#### Scenario: Добавлена одна ветвь
- **WHEN** к готовому датасету добавлен новый источник регионов
- **THEN** вычисляются геометрия и недостающие оценки новой ветви, а полный кадр и прежние совместимые ветви переиспользуются

#### Scenario: Изменились вырезки
- **WHEN** меняется padding или режим mask/bbox при доступных прежних масках
- **THEN** геометрия масок переиспользуется, а новые WD-оценки получают только изменившиеся вырезки

#### Scenario: Перенос и подмена файлов
- **WHEN** изображение перенесено без изменения содержимого либо под прежним путём заменены изображение или веса
- **THEN** перенос не требует повторного инференса, а изменённое содержимое исключает использование несовместимых артефактов

#### Scenario: Изменён режим экономии памяти
- **WHEN** при прежних пикселях, моделях и правилах меняется только low_memory_mode
- **THEN** совместимые полный кадр, геометрия и региональные оценки переиспользуются; ресурсная настройка не становится новой версией модельного расчёта

### Requirement: Явные режимы повторного использования
Планировщик MUST поддерживать `reuse`, `reuse_only` и `refresh`. `reuse` MUST вычислять только отсутствующие совместимые стадии; `reuse_only` MUST запрещать загрузку моделей, скачивание и инференс и сообщать о недостающих данных; `refresh` MUST явно пересчитывать выбранные стадии и зависимые результаты, сохраняя историю. План MUST быть доступен без исполнения.

#### Scenario: Неполный кэш
- **WHEN** для двух изображений есть полные расчёты, а для третьего отсутствуют региональные оценки
- **THEN** reuse планирует только эти оценки и зависимую постобработку, а reuse_only возвращает структурированную причину нехватки данных без запуска моделей

#### Scenario: Принудительное обновление
- **WHEN** пользователь выбирает refresh только для одного источника
- **THEN** пересчёт ограничен выбранной ветвью и её зависимостями, а прежние версии остаются доступны

### Requirement: Возобновление после частичного выполнения
Успешные стадии MUST фиксироваться по мере завершения и переиспользоваться при продолжении. Прерванные, повреждённые и незавершённые записи MUST NOT считаться готовыми. Ошибка одной записи MUST сохранять доступность остальных завершённых записей; фактическое покрытие и ошибки MUST быть отражены в отчёте.

#### Scenario: Остановка в середине папки
- **WHEN** процесс остановлен после завершения части изображений
- **THEN** следующий reuse-прогон сохраняет завершённые вычисления и досчитывает только недостающие стадии

#### Scenario: Повреждённый файл артефакта
- **WHEN** индекс указывает на запись с неверной контрольной суммой или отсутствующим blob
- **THEN** она не возвращается как готовая; reuse_only сообщает повреждение, а reuse может пересчитать только повреждённую стадию и её зависимости

### Requirement: Координация локальных исполнителей
При обращении нескольких процессов к одному хранилищу система MUST координировать вычисление одной стадии и атомарную публикацию результата. Пока действует владение задачей, второй исполнитель MUST ждать результат либо возвращать статус ожидания без дублирования вычислений. Восстановление после потери владельца MUST исключать публикацию от устаревшего исполнителя.

#### Scenario: Два агента запрашивают один расчёт
- **WHEN** два локальных исполнителя одновременно запрашивают один совместимый отсутствующий артефакт
- **THEN** один вычисляет его, второй переиспользует опубликованный результат или получает статус ожидания

#### Scenario: Сбой владельца
- **WHEN** владелец задачи прекращает подтверждать владение и задача передана другому исполнителю
- **THEN** незавершённая работа может повторяться, но поздняя публикация старого владельца не заменяет новый результат

### Requirement: Импорт существующих расчётов с проверкой полноты
Импорт MUST поддерживать evidence-bundle и существующие JSON-результаты с полными raw_scores. Система MUST проверять категории, словарь, идентичность входов и доступные геометрические данные, явно объявляя пригодность к повторной фильтрации и другим стадиям. Отфильтрованный JSON без полных оценок MUST NOT незаметно повышаться до полного evidence.

#### Scenario: Старый подробный результат
- **WHEN** JSON содержит полные оценки полного кадра и областей, сведения о модели и источниках
- **THEN** он импортируется для повторной фильтрации без инференса; отсутствие исходных масок явно ограничивает пересборку вырезок

#### Scenario: Только принятые теги
- **WHEN** старый JSON содержит только теги, прошедшие прежний порог
- **THEN** импорт объясняет, какие свидетельства отсутствуют, и не восстанавливает несуществующие вероятности

### Requirement: Машинный интерфейс планирования и исполнения
Общий Python API и CLI MUST предоставлять план, исполнение, загрузку артефактов и статус без зависимости от frontend ComfyUI. Запросы MUST принимать идентификаторы набора, политики и стадии; отчёт MUST включать run_id, ссылки на артефакты, зависимости и причины reused/computed/missing/invalidated/waiting/failed. Повтор запроса MUST различать вычисления и файловые эффекты.

#### Scenario: Агент проверяет кандидата правил
- **WHEN** агент передаёт новое содержимое политики и прежнее evidence в reuse_only
- **THEN** система выдаёт новую версию результата со ссылкой на исходное evidence и не запускает модели

#### Scenario: Повтор запроса после сбоя связи
- **WHEN** клиент повторяет запрос с тем же идентификатором операции
- **THEN** система возвращает его состояние или результат, не дублируя подтверждённые вычисления и записи файлов
