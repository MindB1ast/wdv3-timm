# Design

## Context

Мотивация и границы — в `proposal.md`. Пользователь выбрал SAM 3; VLM будет отдельным change.

Фактически в коде:
- `Scripts/detection.py::extract_regions_with_detector` использует только YOLO `boxes.xyxy` и возвращает `Crop = tuple[PIL.Image, list[float], str]`. Маски YOLO не читаются.
- `DetectorConfig` и JSON описывают только YOLO и правила тегов; padding отсутствует. `RegionResult` содержит bbox и WD-результат, но не маску, класс или score сегментации.
- `Scripts/tagging.py` последовательно тегирует вырезки. `pil_pad_square` в WD-предобработке добавляет фон для квадратного входа, а не контекст исходного изображения.
- `BatchTagging` обходит изображения по одному; `ScriptOptions.batch` не управляет этим циклом. Результаты сохраняются в конце. `save_txt=True` является legacy-умолчанием и изменяет TXT рядом с изображениями.
- `requirements.txt` фиксирует `torch==2.6.0`. Автоматические проверки находятся в `audit/`, включая геометрию вырезок, два списка результатов и освобождение изображений.

Основная `regional-tag-optimization` описывает будущую систему сцены целиком. Новые требования дополняют её, но реализация этого change не обещает идентичность физических объектов, пространственную семантику и агентную оптимизацию. `add-comfyui-regional-tagging-nodes` ещё не реализован: его ограничения `B=1` и отсутствие SAM относятся к тому MVP, а не к новому Python-пакетному API. Исторические замечания о merge в его design частично устарели после исправлений; текущий `preprocess.py` имеет приоритет при реализации.

## Goals / Non-Goals

**Goals:** отделить сегментацию, геометрию, подготовку RGB-входа и WD-инференс; хранить геометрию независимо от выбранного контекста; реализовать batch без накопления всех пиксельных данных; сохранить legacy-вызовы.

**Non-Goals:** переписывание всех результатов в граф сцены, общий сервер моделей, распределённая очередь, постоянный глобальный GPU-кэш, загрузчики VLM и ноды ComfyUI. Текстовый SAM-промпт выбирает кандидатов, но не гарантирует распознавание любой части или исполнение сложной пространственной инструкции.

## Decisions

### 1. Опциональный SAM 3 в локальном worker

Добавить `Scripts/sam3_adapter.py` на стороне основного процесса и исполняемый модуль worker. `ScriptOptions` получает опциональные `sam_config`, `sam_python`, `regions_output_dir`, `sam_batch_size`, `region_batch_size`; SAM выключен, если `sam_config` отсутствует. По уточнению пользователя Python по умолчанию — `sys.executable`; `sam_python` сохраняется как явный override отдельного окружения. Отдельный `sam_sources.json` не меняет трактовку старого `detectors.json`.

Worker запускается аргументами без shell, на Windows без видимого окна, живёт один запуск и загружает веса один раз. Управление — версионированные JSON Lines по stdin/stdout; логи идут в stderr. Пиксели не кодируются в JSON: запрос передаёт пути к подготовленным lossless PNG, а ответ — пути к бинарным маскам и компактные метаданные во временном каталоге текущей порции. Идентификаторы запроса, изображения и источника обязательны. Основной процесс проверяет размеры/тип маски, допустимые пути внутри каталога порции, версию протокола и наличие всех ожидаемых ответов; удаляет свои временные файлы после commit/ошибки. Worker не пишет итоговые пользовательские экспорты.

Preflight до первого изображения: доступность Python, версий выбранного backend/torch, устройства, модели, локальных весов и протокола. `device=auto` проверяет доступность CUDA и пробное выделение tensor, иначе выбирает CPU; явный device не заменяется молча. `backend=auto` определяет native/Transformers по ключам safetensors или локальному config; без локальных файлов указанный `model_id` выбирает Transformers. Native CPU остаётся неподдержанным и требует другой модели/формата явно. Библиотеки не устанавливаются автоматически; недостающий backend даёт команду установки.

По умолчанию сеть выключена (`allow_download=false`). В примере для предоставленного пользователем `unsloth/sam3.1` скачивание включено явно: отсутствующие конфиг/processor/tokenizer берутся из `model_id`, существующие веса и метаданные не заменяются. Без локальных весов разрешена загрузка стандартного `model.safetensors`/его shards. Само имя файла не определяет исходный репозиторий; он задаётся явно. Авторизация штатная, токены не экспортируются. Ошибка старта — ошибка запуска; отказ worker посреди обработки — сохранение завершённых изображений и остановка с причиной, без фиктивных пустых ветвей.

Альтернатива — обновить общий torch и импортировать SAM внутри WD. Она увеличивает риск поломки проверенного окружения. Worker добавляет дисковый обмен, но позволяет изолировать новые зависимости. Общий сетевой сервис для этой задачи не требуется. Native SAM проверяется по commit/tag и checksum весов; Transformers записывает версию библиотеки и хеши весов/метаданных. Новые checkpoints автоматически проверенными не считаются. CPU поддерживается через `Sam3Model` с float32; общий цикл сегментации, сохранение масок и отбор кандидатов одинаковы для обоих backend. Transformers переиспользует `get_vision_features` для батча кадров между текстовыми запросами, текстовые входы создаются заново для каждого источника.

### 2. Конфигурация источников и отбора

Каждый источник имеет уникальный `source_id`, `name`, `backend=sam3`, модель/веса, текстовый `prompt`, `confidence`, `mask_threshold` (в пространстве вероятностей), `min_mask_area_px`, `max_regions`, `view_mode`, `padding`, `background_rgb` и существующие региональные правила/пороги WD. Глобальные модельные настройки разрешено переиспользовать нескольким источникам. Валидировать обязательные поля, непустой prompt, уникальность имён среди YOLO/SAM, диапазоны 0..1, конечные числа и положительные лимиты до загрузки моделей.

Каждый именованный prompt исполняется независимо; состояние текстового запроса сбрасывается между источниками, embeddings изображения переиспользуются там, где позволяет API. Logits, если backend их возвращает, преобразуются в вероятности до порога. Отбор: confidence → бинаризация → исключение пустых/слишком малых масок → сортировка score по убыванию с tie-break по bbox и хешу маски → `max_regions`. Точные дубликаты одного источника схлопываются, разные prompts не объединяются; перекрытие не означает один физический объект. Счётчики отклонения сохраняются, score сегментации не является score тега.

Пример предлагаемого пользовательского конфига (умолчания: `bbox`, нулевой padding, белый фон):

```json
{
  "schema_version": 1,
  "model": {"checkpoint": "models/sam3/sam3.pt", "device": "cuda", "allow_download": false},
  "sources": [
    {
      "source_id": "eyes", "name": "sam_eyes", "prompt": "eye",
      "confidence": 0.5, "mask_threshold": 0.5,
      "min_mask_area_px": 4, "max_regions": 32,
      "view_mode": "mask", "padding": {"unit": "fraction", "value": 0.15},
      "background_rgb": [255, 255, 255], "region_gen_threshold": 0.35
    }
  ]
}
```

Альтернатива — объединить backend-specific поля в старом `DetectorConfig`. Отдельный конфиг сохраняет старую загрузку YOLO; общие правила извлекаются без дублирования семантики.

### 3. Маска и система координат

Общий тип геометрии в `Scripts/types.py` хранит `image_id`, `source_id`, `region_id`, размер канонического кадра, `bbox`, ссылку на бинарную маску, `segmentation_score`, исходный prompt и model provenance. Для SAM-региона `bbox` — целочисленная минимальная рамка непустой маски в формате half-open. Рамка SAM, если сохраняется, называется `model_bbox` и не подменяет bbox маски.

Для нового SAM-пути канонический кадр создаётся один раз: применить EXIF orientation, перевести в RGB; записать исходный размер, orientation и преобразование в канонический кадр. SAM, новые YOLO-ветви в смешанном запуске и WD получают этот же кадр. Старый YOLO-only путь сохраняет прежнюю ориентацию и геометрию. Канонический кадр сохраняется lossless в SAM-экспорте, чтобы автономный просмотр масок не зависел от неоднозначной EXIF-обработки внешним потребителем.

Маска возвращается в размере канонического кадра: если требуется преобразование сетки, применять nearest-neighbor к бинарной маске и пересчитывать bbox уже после преобразования. Отверстия и раздельные компоненты одного экземпляра сохраняются; они не превращаются автоматически в несколько объектов. Для одного пикселя `(x,y)` рамка равна `[x,y,x+1,y+1]`.

Legacy `Crop` и публичный `extract_regions_with_detector` остаются; для общего ядра добавить структуру с геометрией и ленивой подготовкой входа. В SAM-включённом `RegionResult` дополнительные поля необязательны; `DetailedResult.detectors` сохраняется как совместимый словарь источников, в котором могут быть YOLO и SAM. Значения старых региональных ключей не меняются. Идентификатор региона — результат источника, не идентификатор физического объекта.

### 4. Padding и фактические пиксели

Общая функция подготовки принимает RGB-кадр, геометрию и `RegionViewConfig`, возвращает RGB-вырезку и описание преобразования. Это вход для WD сейчас и для будущего адаптера VLM. Отсутствующие маски YOLO разрешают только `bbox`; запрос `mask` без маски — явная ошибка. Новые bbox-ветви YOLO могут использовать тот же padding без изменения legacy-умолчаний.

Пусть минимальная рамка имеет размеры `w,h`. Для `unit=px` отступы по обеим осям равны `ceil(value)`; для `fraction` — `px=ceil(w*value)`, `py=ceil(h*value)`. Значение едино для всех сторон, но доля рассчитывается от своей оси. Отрицательные/NaN/бесконечные значения отклоняются. `crop_bbox=[x1-px,y1-py,x2+px,y2+py]` ограничивается размером кадра, без синтетических пикселей за его границами.

- `bbox`: все исходные пиксели в `crop_bbox`.
- `mask`: исходная маска расширяется прямоугольным структурным элементом радиусов `(px,py)`, ограничивается кадром; внутри расширенной маски берутся исходные пиксели, вне её — `background_rgb`. Затем применяется тот же `crop_bbox`. При нулевом padding сохраняется только объект. Сохраняемая исходная маска не модифицируется; dilation — только правило видимости контекста.

Так padding в `mask` действительно добавляет контекст, а не просто пустую рамку. Альтернатива — оставить mask неизменной и расширить только холст — не даёт модели окружающих пикселей. Евклидов радиус сложнее сопоставить с padding по ширине/высоте; прямоугольная окрестность имеет простую проверяемую семантику.

`crop_bbox`, запрошенные `px,py`, offset исходных координат в crop, режим, цвет и версия преобразования сохраняются. WD square pad/resize выполняется позже штатным transform и описывается отдельно. Подготовка не запускает SAM и может повторяться по сохранённой маске. Fingerprint представления включает изображение, хеш маски и все настройки; результат тегирования дополнительно зависит от WD-весов, словаря и transform. Постоянный общий cache не нужен: достаточно повторной подготовки через сохранённый экспорт и переиспользования геометрии внутри запуска.

### 5. Батчи и ресурсы

`sam_batch_size` ограничивает число кадров в одной порции сегментации, `region_batch_size` — число подготовленных tensors WD. Оба не меньше одного; legacy `batch` не переопределяется скрытно. Список файлов упорядочивается по относительному пути в новом SAM-пути; source/prompts и результаты имеют явные ключи. Нативный batched image API SAM 3 используется там, где выбранная зафиксированная версия это поддерживает; нельзя объявить последовательный цикл GPU-batch. Для разных размеров разрешена группировка совместимых кадров внутри лимита с восстановлением исходного порядка.

WD-регионы после штатной предобработки имеют совместимые размеры и объединяются через stack; каждая строка выхода возвращается к своему `(image_id,source_id,region_id,view_fingerprint)`. Последняя неполная порция обрабатывается без дополнения фиктивными регионами. Правила тегов применяются после соответствия выходов регионам. Полный кадр может оставаться отдельным WD-инференсом.

В памяти только активная порция кадров, ограниченное число масок/кандидатов выбранного backend и одна WD-порция. Итоговые два списка содержат компактные словари/ссылки, а не PIL/tensors/маски на весь датасет. Маски с диска читаются лениво для подготовки/просмотра. GPU-worker освобождает состояние порции до WD-инференса; для одного GPU предусмотреть явную выгрузку модели SAM на CPU на время WD и обратную загрузку к следующей SAM-порции. Не удерживать обе тяжёлые модели на GPU без учёта памяти. Это медленнее постоянного GPU-residency, но даёт предсказуемый базовый режим.

Повреждённое изображение — per-image error и продолжение; ошибка модели/протокола или OOM после освобождения временных данных — сохранение завершённого и остановка с предложением уменьшить batch. Молчаливого перескока на другую модель/устройство нет. Отмена проверяется между порциями, запрос worker имеет timeout; при отмене процесс завершается, файлы закрываются, незавершённая порция не коммитится. Прогресс различает прочитанные/сегментированные/протегированные/сохранённые изображения и ошибки.

### 6. Экспорт и совместимость правил

SAM-запуск создаёт уникальный каталог `regions_output_dir/<run_id>/` с `manifest.json`, снимком настроек, компактным журналом прогресса и подпапками изображений. `image_id` учитывает относительный путь и хеш исходного содержимого; `region_id` стабилен для одинакового набора результатов при зафиксированной модели. Prompt не используется как имя пути. Внутри изображения: канонический кадр, маски PNG `L` со значениями 0/255 и JSON с версиями схемы/моделей, score, геометрией и WD-результатами. Ссылки относительные; хеши кадра/маски помогают обнаружить несовместимую подмену. Опционально сохранять фактические RGB-вырезки; по умолчанию воспроизводить их по кадру и маске.

Commit изображения: записать пиксельные файлы и JSON через временные имена, затем атомарно отметить запись завершённой в manifest. При сбое допустимы только неподтверждённые временные файлы; отчёт не ссылается на них как на готовый результат. Выполнять commit после каждого полностью обработанного изображения; не ждать конца всей папки. Журнал статусов позволяет понять покрытие после сбоя; автоматическое возобновление не входит в этот change.

Переиспользовать текущие `apply_tag_rules` и `merge_tags_from_regions`; источник SAM предоставляет те же региональные правила, а не второй алгоритм merge. Исходные оценки и текст промпта остаются раздельными. `save_txt` в старом API сохраняется как есть; документация SAM-примера явно задаёт `save_txt=False`, все новые маски и JSON пишутся в каталог запуска. Явное legacy `save_txt=True` по-прежнему разрешает существующий экспорт тегов и не влияет на расположение масок. Старый `output_file` остаётся поддержан; расширенные поля появляются только при включённом SAM.

### 7. Просмотр и приёмка

Расширить `Scripts/visualization.py`: overlay исходной маски, разные стили минимального bbox и crop_bbox, подписи источника/prompt/score; рядом RGB-вход до WD square pad/resize. Просмотр читает и старые результаты без маски. Для сравнения `mask`/`bbox` можно повторно подготовить и протегировать сохранённый регион; варианты не считаются новыми физическими объектами.

В `audit/` добавить геометрические фикстуры и fake SAM worker для протокола, конфигов, маршрутизации batch, отмены и сбоев записи. Численные проверки изображений: одиночный пиксель, отверстия, несвязные части, край, относительный padding, EXIF. Проверять байты маски до/после подготовки и соответствие реальных видимых пикселей. Батч-тест WD должен проверять передачу tensor с B>1 и распределение разных выходных строк, а не только количество вызовов. Прогнать существующую регрессию и статические контракты.

Отдельный реальный GPU smoke обязателен для заявленной поддержки SAM 3: зафиксировать OS/Python/torch/CUDA/SAM commit/checkpoint, два изображения разных размеров, несколько prompts, оба view, batch=1 и batch>1. Проверить одинаковые маски/bbox и scores в заданном допуске; если backend недетерминирован на платформе, определить и зафиксировать поддерживаемые настройки перед объявлением batch-эквивалентности. Сохранить измерение peak GPU memory и переносимый экспорт. Fake-прогон не заменяет этот smoke и не доказывает качество сегментации или улучшение тегов.

### 8. Проверенные внешние основания

Проверено 2026-10-30:
- [Официальный SAM 3 README](https://github.com/facebookresearch/sam3): текстовые prompts, masks/boxes/scores и пример batched image inference; окружение Python ≥3.12, PyTorch ≥2.7, CUDA ≥12.6, доступ к checkpoint требует авторизации.
- [SAM 3 image processor](https://github.com/facebookresearch/sam3/blob/main/sam3/model/sam3_image_processor.py): state изображения и текстового запроса отделены; адаптер не должен смешивать состояния независимых источников.

Конкретный commit и доступность весов устанавливаются и фиксируются при smoke; актуальный README не является гарантией совместимости с Windows или существующим окружением проекта.

## Risks / Trade-offs

- [SAM 3 может не выделять мелкие аниме-детали по короткому prompt] → сохранять исходный запрос, пустые результаты и просмотр; не заявлять гарантированное покрытие/качество.
- [Новый стек SAM несовместим с текущим WD] → отдельное окружение и preflight; установка не меняет текущие pins автоматически.
- [Один GPU не вмещает SAM и WD] → порционное выполнение, явная выгрузка SAM и измерение памяти; OOM не превращается в пустую детекцию.
- [Dilation показывает соседний объект] → сохранять исходную маску и параметры контекста; атрибуты по одному overlap автоматически не назначать.
- [Полноразмерные маски и кадры занимают диск] → lossless PNG, ленивое чтение, лимиты регионов, опциональные RGB crops; без сохранения промежуточных tensors.
- [Изолированный worker усложняет отладку и отмену] → узкий версионированный протокол, stderr-логи, timeout и интеграционный fake-worker.
- [Будущие ноды ComfyUI создадут второй формат] → документировать адаптацию общего региона к `WD_REGIONS`; не реализовывать UI или вторую геометрию здесь.

## Migration Plan

1. Добавить типы и конфиг как opt-in, оставив старые вызовы/дефолты и YOLO-тесты без изменений.
2. Реализовать геометрию и экспорт с fake backend, затем worker SAM и подготовку батчей WD.
3. Документировать создание отдельного SAM-окружения и настройку `sam_python`, доступ к весам и реальную матрицу совместимости. Без подходящего GPU smoke помечается невыполненным; поддержку нельзя объявить проверенной.
4. Добавить пример SAM-запуска с `save_txt=False`, просмотром и повторной подготовкой сохранённой маски; сохранить существующие notebooks.
5. Откат: выключить `sam_config`, вернуть прежнюю версию проекта. Веса и экспорт остаются самостоятельными файлами; данные пользователя не мигрируются разрушительно.
