# Proposal

## Why

В Tag Rules не объяснено, что `blue eyes` и `blue_eyes` обозначают один тег; для групп тегов приходится вручную перечислять имена. Вывод ограничен разделителем `, `, поэтому его неудобно адаптировать к разным форматам подписей и промптов.

## What Changes

- Уточнить в подсказках и документации синтаксис обычных тегов: пробелы и `_` эквивалентны, список разделяется запятыми или переводами строк.
- Добавить отдельные необязательные regex-поля для правил отбора тегов. Обычные поля всегда остаются буквальными, без автоматического распознавания regex.
- Применять regex к каноническим именам с `_`, по полному совпадению; один шаблон на строку. Сохранять существующие приоритеты удаления, владения и ограничений.
- Добавить `tag_separator` в настройки вывода: `, ` по умолчанию, пробел, запятая или произвольная строка по выбору пользователя.
- Обеспечить одинаковый текст на выходе нод, в просмотре и экспорте, включая Save Result без подключённого `tags`; сохранить старые конфиги и workflow.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `comfyui-regional-workflows`: явный синтаксис правил, regex-сопоставление без конфликта с литералами, настраиваемый разделитель и согласованность сохранённого текста.

## Impact

Затрагиваются `Scripts/tag_utils.py`, `Scripts/configs.py`, `Scripts/preprocess.py`, `comfy_config.py`, `comfy_evidence.py`, ноды настроек/правил/тегирования, `web/rules.js`, текстовые блоки viewer/Inspect, `comfy_export.py`, `comfy_reports.py`, документация, примеры и профильные проверки `audit/`. Новых моделей и зависимостей не требуется. Изменения относятся к постобработке оценок; порядок инференса и детекция не меняются. Публичный notebook API и исторические `caption`/`taglist` сохраняются; расширение notebook-интерфейса настройки вывода вне scope.
