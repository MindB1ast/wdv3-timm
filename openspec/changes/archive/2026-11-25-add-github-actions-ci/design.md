# Design

## Context

Регрессии фильтров работают на зафиксированных данных в `audit/fixtures/`; тестовый адаптер импортирует Python-код и использует CPU-тензоры без установленного ComfyUI. `requirements.txt` поддерживает Python 3.11/3.12 и фиксирует версии PyTorch. Основные спецификации проверяются `openspec validate --specs`.

## Goals / Non-Goals

**Цели:** одинаковый набор проверок для `push` в `main` и `pull_request` в `main`; раздельные результаты Python и OpenSpec; запуск без локальных путей, секретов, серверов и модельных весов.

**Не входят:** GPU, загрузка моделей, браузерные и реальные ComfyUI-прогоны, автоисправления кода, настройка branch protection и публикация релизов.

## Decisions

- Один GitHub Actions workflow с двумя независимыми задачами на GitHub-hosted Linux. Использовать `pull_request`, не `pull_request_target`; минимальные права `contents: read`, без передачи credentials checkout следующим шагам и без проектных секретов. Задать разумные таймауты и отменять устаревшие прогоны для одной ветки или PR.
- Для Python использовать 3.11, совместимый с `requirements.txt`. Установить фиксированную CPU-сборку семейства PyTorch с официального индекса, затем остальные зависимости из существующего manifest. Не устанавливать ComfyUI или отдельный SAM runtime. Запускать те же восемь модулей, что перед пушем `bda3e68`, включая `audit.test_saved_region_filters` и `audit.test_region_filter_outcomes`. Не запускать полный discovery, пока не разделены проверки с внешними зависимостями.
- В отдельной задаче установить закреплённую публичную версию OpenSpec CLI, предварительно сверив её с локальной версией `1.15.0` и поддержкой команды. Выполнить `openspec validate --specs`; ненулевой результат должен провалить задачу.

## Risks / Trade-offs

- Результаты на сохранённых оценках проверяют правила, экспорт и эталоны, но не запуск реальных моделей. В документации сохранить явную ссылку на ручной набор прогонов.
- Первый запуск с пустым кэшем скачивает Python-зависимости; CPU-варианты исключают ненужные CUDA-пакеты. При ошибке установки не отключать тесты: проверить совместимость в чистой среде.
- Два сохранённых JSON в `audit/fixtures/region_filters/` имеют побайтовые SHA-256 для CRLF. Фиксировать `eol=crlf` только для этих путей, чтобы чистый checkout на Linux воспроизводил исходные байты без пересчёта эталонов и ослабления проверки.
- Появление статусов в Actions проверяется после публикации workflow. Локальный запуск сам по себе не является доказательством успешного прогона на GitHub.
