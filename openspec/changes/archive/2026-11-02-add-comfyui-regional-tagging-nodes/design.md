# Design

## Context

Мотивация и требования: [proposal.md](proposal.md) и [delta-спека](specs/comfyui-regional-workflows/spec.md).
Состояние сверено с реализацией 2026-11-02. Расширение уже работает в локальном
ComfyUI; исходный план с B=1, отдельными Apply Filters/Inspect и отложенным SAM
не описывает текущий интерфейс. Реализованная архитектура и границы проверки описаны ниже; статусы приёмки находятся в tasks.md.

## Goals / Non-Goals

**Goals:** визуальные настройки регионального WD-тегирования, несколько YOLO/SAM-источников,
IMAGE-батчи и папки, происхождение итоговых тегов, перенос настроек, просмотр и сохранение
без обязательного браузерного callback. Полные свидетельства, повторная фильтрация,
владельцы, белые списки и HTML-отчёт реализуются общим ядром и отдельными нодами.

**Non-Goals:** собственный редактор графа, обучение моделей, онтология объектов,
агентная оптимизация и семантическая композиция описаний. Расширение каталога
SmilingWolf/animetimm выполняется отдельным change.

## Decisions

### 1. Пакет и интерфейс ComfyUI

Репозиторий подключается как custom_nodes/wdv3-timm, в пользовательской установке
через junction на рабочий checkout. Регистрация — корневой __init__.py;
legacy-ноды находятся в comfy_nodes.py, новые V3-ноды — в comfy_ui_nodes.py,
frontend — в web/. Используется смешанная регистрация с comfy_api.latest;
стабильные ID начинаются с WDV3, категория — WDV3. Это сохраняет существующие
workflow и позволяет использовать обычные поля и расширяемые входы V3.
Импорт Scripts ленивый, без обязательной notebook-аналитики.

Фактический каталог и схема подключения описаны в docs/comfyui.md:
Load Tagger Model, Tagging Settings, Region Tag Rules, YOLO Detector,
Combine YOLO Detectors, Load SAM 3.1, SAM Text / Region Settings,
Combine SAM Sources, SAM Segment Images, Tag Image / Regions, Image Folder,
Tag Folder, Results Viewer, Save/Load Pipeline Config и Save Result; Collect Evidence, Apply Filters, Merge Results, Inspect и Export Report.
Старый JSON-загрузчик YOLO остаётся для совместимости.

### 2. Вычислительное ядро и данные

ComfyUI принимает IMAGE [B,H,W,3/4]; прозрачность компонуется на белый фон.
WD использует существующую предобработку с BGR, регионы берутся из исходных пикселей.
Общее ядро RegionTagger переиспользуется notebook-путём и ComfyUI.

Tag Image / Regions возвращает списки tags и results_json в порядке кадров,
а также sam_regions. JSON включает image_index, full_image, detectors,
merged_tags и при файловом вводе image_path. Регион содержит source_name через
ключ detectors, region_id, bbox и принятые оценки. SAM-области дополнительно
несут геометрию маски и segmentation_score. Временные маски просмотрщика не являются
полным экспортом геометрии и вырезок.

RegionTagger.score_batch получает все оценки до порогов. Collect Evidence возвращает
неизменяемый Bundle(kind=evidence, schema_version=1) с оригинальными изображениями,
координатами, сырыми категориями и снимками источников. Apply Filters формирует
новый Bundle(kind=results), сохраняя raw_scores, локальные и итоговые decisions.
Версионированные виды model/rules/regions/report/text используют тот же JSON-контракт;
Mapping-интерфейс возвращает копии значений и не допускает записи.

Кэш raw evidence привязан к загруженному WD-ресурсу и ограничен четырьмя кадрами.
Ключ включает пиксели и размер, контрольные суммы весов и словаря, предобработку,
параметры и версии YOLO-весов, геометрию SAM. Правила не входят в ключ инференса.
При смене весов детектора его загруженный экземпляр обновляется. Отдельный SAM-кэш
содержит до двух наборов геометрии без теговых правил; смена checkpoint/config
или параметров сегментации инвалидирует его. Кэши не переживают перезапуск сервера.
Merge Results проверяет идентичность полного свидетельства и кадра, дедуплицирует
одинаковые источники и отклоняет конфликтующие версии. Данные downstream не меняют
исходный снимок. Имена источников уникальны; имя full зарезервировано.

### 3. Модели, источники и батчи

WD и YOLO находятся в models/wdv3/taggers и models/wdv3/yolo; существующие
локальные веса checkout также переиспользуются. Auto выбирает устройство
ComfyUI, явная недоступная CUDA для WD вызывает ошибку. WD/YOLO имеют явный download_missing, локальные пути и метаданные.
Перед GPU-этапом используется free_memory ComfyUI, при выходе и ошибке модели
возвращаются на CPU; прерывание проверяется между изображениями и группами вырезок.
Проверено CPU-окружение; проверка GPU требуется только при доступном устройстве.

YOLO-источники имеют независимые имена, confidence, classes и правила.
Одинаковые веса загружаются лениво и переиспользуются. Имена уникальны также
относительно SAM. Настройки SAM включают модель unsloth/sam3.1, устройство,
локальный путь и download_missing. Load SAM и Load Config только формируют
настройки; недостающие файлы скачиваются при сегментации. Сеть не нужна при
полном наборе локальных файлов. Скачивается один поддерживаемый формат весов.

Каждый SAM-источник содержит собственный prompt, пороги, лимиты, bbox/mask,
отступ и правила. Модель и кодирование изображения переиспользуются внутри
вызова сегментации, текстовые проходы независимы. Теггер принимает sam_model
и sources либо готовые sam_regions; одновременное подключение отклоняется.
Отдельная SAM Segment Images остаётся для MASK и повторного использования областей.

Image Folder только собирает пути с рекурсивностью, начальным индексом и лимитом.
Tag Folder ограничивает image_batch_size, region_batch_size и sam_batch_size
независимо; изображения разных размеров декодируются ограниченными порциями.
Это заменяет первоначальное ограничение B=1.

### 4. Правила, merge и перенос настроек

Обычные поля Tagging Settings и Region Tag Rules задают пороги, remove/add,
подтверждение полным кадром и исключения полного кадра. Теги нормализуются;
remove имеет приоритет, ручные теги маркируются manual_rule и assigned_score.
Непустые источники суммируют исключения полного кадра, общие и персонажные теги
объединяются по максимальной принятой оценке; ratings сохраняются от полного кадра.
Caption и taglist строятся из тех же словарей.

Save/Load Pipeline Config сохраняют options, detectors, sources и sam_model
с устройством, путём и download_missing. Веса и изображения не сериализуются.
Load Config выдаёт четыре выхода; старые SAM-конфиги без sam_model получают
unsloth/sam3.1, auto, download_missing=true. Защита перезаписи пресета явная.
Обычную настройку «брать тег только из выбранного источника» уже можно выразить
remove_from_full в выбранной ветви и remove_from_regions во всех остальных ветвях.
remove_from_full применяется лишь при наличии областей этой ветви; при отсутствии
областей полный кадр сохраняется. Владельцы в плане — дополнительная централизованная политика разрешённых
источников тега, а не отсутствие возможности ограничить источник существующими
списками удаления. В согласованном варианте fallback к полному кадру отсутствует.

Браузерный импорт выбранного detectors.json и ролевые пресеты меняют только поля
данной ноды; параметры YOLO показываются отдельно. Назначенные scores сохраняются
через синтаксис tag:score; неверные значения отклоняются до изменения полей.

### 4.1. Владельцы и белый список источника

Region Tag Rules содержит два независимых списка: «Теги только из этого
источника» (only_from_source) и «Разрешённые теги источника» (allowed_tags).
Оба используют существующую канонизацию и parse_tags; в конфиге сериализуются
как списки строк, отсутствующие поля старого конфига получают пустые списки.

Собрать до обработки результатов отображение canonical_tag → множество имён
владельцев из настроек всех YOLO/SAM-источников, включая источники без найденных
областей. Повтор тега у нескольких владельцев допустим. Неизвестный или пустой
источник по-прежнему диагностируется обычной проверкой настроек; повтор имени
источника не разрешается владением одним и тем же тегом.

Закреплённый тег разрешён только из областей владельцев; full и прочие источники
его не дают даже при отсутствии областей у владельцев. Владение относится ко
всем областям source_name, не к выбранному region_id. Не закреплённые теги
обрабатываются по прежним правилам. Среди разрешённых результатов владельцев
выбирается максимальная оценка с её provenance и region_source для manual_rule.
При равных оценках выбор provenance должен быть детерминирован по имени источника
и region_id, без зависимости от порядка подключений.

Непустой allowed_tags допускает из источника только перечисленные general/character
теги, включая ручные добавления. Пустой список не ограничивает источник. Список
не меняет ratings полного кадра и соседние источники. Владение, allowed_tags,
пороги, remove и require_full_confirmation должны одновременно разрешить тег.
Присутствие в любом из двух списков не добавляет тег само по себе. Например,
если eyes владеет blue_eyes, но не разрешает его своим непустым allowed_tags,
тег из eyes не проходит; второй владелец face по-прежнему может дать его.

Глобальные prefix/suffix и ручные добавления не должны возвращать закреплённый
тег из неразрешённого источника; итоговый remove имеет приоритет. Трассировка
решений различает запрет владельцами, белым списком и остальными правилами.
API и UI используют один вычислительный контракт; round-trip нескольких
владельцев и обоих списков обязателен. Точная реализация контейнеров не является
условием наличия двух обычных полей в UI.

### 5. Results Viewer и происхождение тегов

Viewer показывает кадр, список источников, теги и оценки. На canvas всегда видны
рамки; активная область подсвечивается поверх остальных. Выбор списка и клик
синхронизированы. Повторный клик переключает пересечения, SAM использует маску
при её наличии. Стрелки переключают области, Esc и клик вне областей снимают выбор.
Пустой preview_limit восстанавливается в 16, отправка нормализует INT 1..256;
лимит влияет только на отображение.

Merged tags содержит открытый Added from regions. Новым считается принятый тег,
отсутствующий в той же категории полного кадра. Происхождение берётся из
provenance: source, а для manual_rule из области дополнительно region_source.
Повышенная регионом оценка уже существующего тега не делает тег новым.
Нажатие на тег выбирает область; таблицы general/character показывают источник
победившей оценки. Сохраняются все конкурирующие свидетельства и причины решений;
поиск и страницы по 50 строк доступны в Viewer и Inspect, режимы all/accepted/rejected/raw
не требуют отображения всего вектора. Inspect принимает ровно один вход regions,
evidence или results и выдаёт IMAGE, теги и неизменяемый report.

### 6. Save Result и файловый экспорт

Отдельная output-нода WDV3SaveResult получает список results_json и необязательный
список tags; result_index выбирает ровно одну запись. Подключённый tags сохраняется
без переформатирования; иначе используется merged_tags.taglist с fallback на caption.
Выходы txt_path/json_path содержат пути, отключённый формат возвращает пустую строку.
Файлы формируются как output_directory/filename.txt и filename.json.
Имя не содержит пути или расширения; неверный индекс, несогласованные списки,
неверный JSON, выключенные оба формата и недопустимое имя отклоняются до записи.

При overwrite=false все выбранные назначения проверяются до записи, а создание
использует эксклюзивный режим. Overwrite=true явно разрешает замену. Нода отмечена
как выполняющая побочный эффект, поэтому повторный запуск сохраняет снова,
не полагаясь на кэш вывода. Она работает без Viewer и браузера. Проверки:
audit/test_comfy_export.py и успешный ComfyUI API-прогон
f9589489-ae3f-4e9a-96f6-d7a2a9422340 с проверкой содержимого TXT/JSON.

Tag Folder сохраняет TXT/JSON отдельно для каждого исходного пути, сохраняя
подпапки и исходное расширение в имени, чтобы a.jpg и a.png не конфликтовали.
Save Result сохраняет один TXT/JSON. Отдельный Export Report создаёт новый каталог
на каждый запуск, сохраняет JSON/HTML/TXT, исходные изображения, вырезки и маски,
ссылки на assets и причины решений. HTML использует textContent и экранированный JSON,
поддерживает выбор кадров/областей и поиск. Для TXT нужен результат с полным кадром.
Код отчёта и API не требуют frontend-callback; исходные файлы не перезаписываются.

### 7. Контракты и проверки

Кэш сохраняет исходные оценки до фильтров: изменение правила
пересчитывает только решения; изменение изображения, весов или детекции обновляет
соответствующие свидетельства. Проверять это счётчиками вызовов WD/YOLO и fingerprint
конфига, словаря, весов и параметров. При повторном merge дедуплицировать одинаковые
ветви и отклонять конфликтующие версии источника; владение тегом
не зависит от порядка, несколько владельцев образуют множество разрешённых источников.

Контракт новых текстовых адаптеров предусматривает tag_scores/class_label/text,
идентификатор и версию модели, настройки, привязку full/region к YOLO/SAM-источнику,
несколько адаптеров на область, необязательный score и prompt/параметры генерации
для VLM. Свободный текст не канонизируется как Danbooru; отсутствие score не
заменяется на 1.0. JSON round-trip этого расширения проверен, включая несколько адаптеров одной области
без искусственных scores и изменения пробелов/пунктуации.

Ручная разметка датасета и UI пользовательского фидбека не входят в этот change.
Их можно рассматривать после пайплайна отдельной задачей, только если появится
потребность использования в агентском пайплайне. Текущий API-отчёт не требует пометок.

## Risks / Trade-offs

- [Полные оценки увеличивают размер результатов] → ограниченные кэши, страницы таблиц и отдельные assets вместо дублирования PNG в UI JSON.
- [SAM требует много памяти на CPU] → независимые небольшие батчи, освобождение ресурсов и отдельно подтверждаемая GPU-проверка.
- [Конкурентная запись пары TXT/JSON] → предварительная проверка и эксклюзивное создание; операция пары не обещает транзакцию при внешнем сбое между записями.
- [План ошибочно принимается за готовую реализацию] → выполненные и незавершённые пункты разделены в tasks.md; change остаётся активным.
- [Frontend ComfyUI меняется] → небольшой UI, проверки восстановления значений и самостоятельный API-экспорт.

## Migration Plan

1. Установить requirements-comfyui.txt в интерпретатор ComfyUI, сохранив его PyTorch; подключить checkout как custom node.
2. При добавлении backend-ноды перезапустить свободный сервер; обновить страницу для нового каталога и frontend.
3. Подключить results_json и при необходимости tags непосредственно к Save Result; задать каталог, имя и явную политику перезаписи.
4. Сохранить notebook API и существующие configs/workflow. Откатить пакет либо отключить custom node; изображения, подписи, веса и сохранённые результаты не мигрируются разрушительно.
5. Задачи и CPU-приёмка завершены; перед архивированием проверить итоговый diff. Матрица версий и доказательства находятся в docs/verification/comfyui; фактическое GPU-исполнение не проверено из-за отсутствия устройства.
