# Design

## Context

См. proposal.md для мотивации. `extract_regions_with_detector` и `collect` сейчас работают с независимыми YOLO/SAM-источниками полного кадра. `rectangle_geometry`/`prepare_region_view` уже задают исходные координаты, bbox и фактическую вырезку, но не идентичность родителя. `collect` и кэш используют плоские source/region ID. Существующий `merge_results` пересобирает результат по evidence: дерево и маршрутизацию необходимо включить в переносимые данные, иначе они потеряются.

План `add-scope-local-tag-redundancy` отделяет локальные принятые `tag_sets` от общего merge. Этот change расширяет его модель и операции, не переписывая предыдущие planning-артефакты. Из основной спецификации сохраняется ограничение: вычислительное/геометрическое вложение не доказывает семантическую принадлежность объекта.

## Goals / Non-Goals

**Goals:** конечный каскад детекции по отдельным родителям, воспроизводимая геометрия, сохранённые локальные предсказания и управляемый вклад дочерних тегов; общий caption остаётся существующим выходом.

**Non-Goals:** отслеживание между кадрами, автоматическое сопоставление двух пересекающихся родителей одному физическому объекту, общий scene graph, новые модели, свободные VLM-тексты, автоматические подписи «слева/справа», рекурсивная генерация этапов во время исполнения. Постоянное хранилище и условные операции — отдельные changes.

## Decisions

### 1. Конечный план этапов и ленивое исполнение

Версионированный план содержит stages: уникальные `stage_id`, `parent_stage` (null = полный кадр), конфигурацию ровно одного источника YOLO либо SAM model+source, `tag_enabled=True`, `tag_route=separate`, настройки входной вырезки и ссылки на локальные правила/операции. Один этап имеет одного родителя; от родительского этапа можно ответвить несколько дочерних. Одинаковые веса разных этапов переиспользуются адаптером, имена этапов независимы от пути весов.

Компилятор проверяет весь план, строит топологический порядок, затем исполнитель обходит кадры и ограниченные рабочие порции родителей. Для каждого конкретного родителя запускается дочерний этап; его результаты не смешиваются с другими вырезками. Если родителей нет, детектор/загрузчик потомка не вызывается. Детектор можно использовать как промежуточный геометрический этап с `tag_enabled=False`; его собственные WD-оценки отсутствуют, но производный набор может принимать теги детей. Полный кадр продолжает тегироваться для прежнего глобального caption.

Загружать веса по необходимости через существующие ленивые конфигурационные адаптеры. Если пользователь сам подключил старый eager-loader upstream, исполнитель не может отменить уже выполненную загрузку; документация отличает это от ленивой ветки каскада. Ошибку детектора не выдавать за нулевое число объектов; помечать кадр как failed с stage/parent и сохранять завершённые кадры в отчёте.

Альтернатива плоскому повторному запуску всех детекторов на всём кадре отвергнута: она не реализует требуемый вход лица/глаз и допускает смешивание людей.

### 2. Геометрия и идентичность

Расширить переносимую запись `region_uid`, `parent_region_uid`, `stage_id`, `depth`, local detection index, локальный bbox/маску, исходный bbox/маску, `detector_input_transform` и фактический `crop_bbox` родителя. UID строится из image identity, stage, parent UID и стабильного локального номера после упорядочивания результатов. Одинаковый локальный region_id под разными родителями больше не является идентичностью.

Для каждого входа фиксировать преобразование его пикселей в канонические исходные координаты. Детекторный адаптер возвращает координаты именно переданной вырезки после отмены своего resize/letterbox; далее композиция преобразований переводит их в исходный кадр. Child bbox ограничивается фактической входной вырезкой, а не tight bbox родителя: padding намеренно допускает контекст. SAM-маски отображаются в исходную сетку без потерь бинарного содержимого и с документированным округлением bbox. Пустые/вырожденные результаты отбрасываются с диагностикой.

Детектор получает bbox/mask-view родителя по его настройкам из канонических исходных пикселей. Вход WD после resize не используется для следующего уровня. При mask-view сохраняется маска и фон/контекст, реально видимый детектору. WD-вход найденного ребёнка строится из исходных пикселей по собственным правилам ребёнка. Это два различных профиля входа, оба входят в provenance.

Связь фиксируется как `detected_within_parent_input`, с источником каскадного этапа. Она не назначает автоматически семантическое `part_of`. При пересечении вырезок один физический объект может появиться под двумя родителями; в первой версии записи сохраняются раздельно, без скрытого глобального NMS/переназначения.

### 3. Теги и передача снизу вверх

Разделить собственные raw_scores, локально принятые теги и производный агрегат региона. Собственные оценки не заменяются агрегатом. Сначала локальные пороги/правила/операции работают по собственному набору, затем узлы обрабатываются снизу вверх:

1. Потомок `merge_to_parent` передаёт свой разрешённый агрегат непосредственному родителю; `separate` не передаёт его родителю и остаётся самостоятельным вкладом общего merge.
2. Родитель объединяет собственные принятые теги и поступившие вклады по прежнему максимуму разрешённой оценки; равные оценки разрешаются стабильным полным путём происхождения. Character остаются отдельно, ratings не наследуются от детей и глобально остаются из full.
3. Для производного агрегата родителя можно явно задать `aggregate_operations` — отдельную цепочку после приёма детей. По умолчанию она пустая. Например, skirt родителя и black_skirt ребёнка могут пройти удаление избыточности именно здесь. Локальная цепочка по умолчанию повторно не запускается.
4. Полученный агрегат далее передаётся согласно маршруту самого родителя. В глобальный merge поступают корневые агрегаты и самостоятельные вклады separate. Узлы merge_to_parent не поступают туда второй раз напрямую.

Набор с отключённым собственным тегированием начинает с пустых собственных тегов и может собрать детей. Separate-потомок остаётся самостоятельным, даже если его предок передаёт свои теги выше; маршрутизация одного узла не поглощает автоматически separate-потомков.

До наследования применяются собственные ограничения ребёнка; родительская стадия приёма сохраняет явные remove/allowed родителя без повторного применения родительского модельного порога к score ребёнка. Идентичность происхождения остаётся дочерней, поэтому only_from_source и глобальные ограничения проверяются по исходному stage/source, не по имени получателя. Никакой маршрут не отменяет явный запрет. `remove_tags_from_full` по-прежнему относится только к полному кадру, а подтверждение full — к полному изображению, не к ближайшему родителю. Для удаления из конкретного родительского агрегата задаётся его операция, а не переопределение смысла старого поля.

История хранит origin region/source, полный путь получателей, каждое принятие/отклонение и операцию. Inspect показывает собственные и унаследованные теги раздельно. При условных правилах (если соответствующий change реализован) их область — один собственный либо явно выбранный агрегированный набор; соседи не объединяются в условия.

### 4. Границы исполнения и reuse

План содержит явные положительные `max_depth`, `max_regions_per_parent`, `max_regions_per_image`; предлагаемые defaults 8/64/4096. Структурную глубину проверять до инференса. При превышении численных лимитов сортировать кандидатов по confidence, исходному bbox и стабильному индексу, сохранять счётчики найдено/оставлено/отсечено и причины. Порядок независимых ветвей стабилизировать stage_id, не очередностью нод. Batch сохраняет карту `(frame, stage, parent, region)`.

Ключ детекции дочернего этапа зависит от входных пикселей/view родителя, stage/model identity и параметров детекции; его raw-тегирование — от геометрии, WD и профиля входа. Не включать route и операции в inference identity. Изменение правил/route пересобирает производные наборы из raw; изменение вырезки родителя инвалидирует детекцию его потомков и их оценки, но не независимых корней. Добавление ветви не пересчитывает готовые ветви при наличии пригодного кэша. В первой реализации достаточно кэша процесса; дисковый planner из отдельного change должен позднее учитывать эти зависимости, но не является обязательной частью этого change.

### 5. ComfyUI и совместимость

Предлагаемые ноды: `WDV3CascadeStage` (конфигурация stage, необязательный parent-план и существующая конфигурация детектора), `WDV3CombineCascadeStages` (объединить ветви/повторные общие предки без конфликта), `WDV3CollectCascadeEvidence` (images, wd_model, plan, options; полный кадр и иерархические evidence) и `WDV3RouteCascadeTags` (tag_sets → tag_sets с производными агрегатами). План имеет тип `WDV3_CASCADE_PLAN`; параметры моделей и rules переиспользуются через прежние типы, не копируются в Tag Image. Один stage содержит один именованный источник; для нескольких источников используются соседние stages. Конфликтующие копии одного stage_id отклоняются, идентичные дедуплицируются.

Ветка: `CascadeStage/Combine → Collect Cascade Evidence → Filter Tag Sets → локальные операции → Route Cascade Tags → Merge Tag Sets → Inspect/Export`. Aggregate-операции передаются в конфигурации своего этапа отдельно и исполняются Route Cascade Tags. Merge требует явной маршрутизации для иерархического tag_sets и не скрывает её внутри обычного плоского объединения. Исполнение повторной Route начинает с сохранённых собственных принятых наборов, не с прежнего агрегата, поэтому не удваивает наследование.

Добавить preflight постоянных полей, общий валидатор собранного плана до моделей, контекстные предложения типов, дерево Inspect и JSON-экспорт со schema version. Динамический план нельзя полностью проверить до вычисления upstream-ноды: ранняя проверка не обещает доступ к её будущему значению. Конфиги сохраняют план и route/aggregate-операции отдельно от глобальных options.

Старые evidence без parent читаются как независимые корни с separate; прежняя ветка не получает каскад автоматически. `merge_results` проверяет идентичность кадра, parent UID/геометрию, план и политики; одинаковые записи объединяются без дублей, конфликтующие отклоняются. Повторное построение идёт по сохранённым собственным наборам и той же маршрутизации; прямое уплощение дерева запрещено.

## Risks / Trade-offs

- [Рост числа вырезок и памяти] → конечный план, лимиты, рабочие батчи, явная диагностика отсечения.
- [Неверные координаты после padding/resize] → композиция фактических преобразований, тесты смещений, границ, ориентации и SAM-масок.
- [Один объект найден в перекрытии родителей] → сохранить разные вычислительные записи и неопределённость принадлежности, не назначать семантику автоматически.
- [Родительская агрегация обходит запреты/восстанавливает тег] → сохранить origin и причины, разделить собственные/агрегированные наборы и локальные/aggregate-операции.
- [Потеря дерева в повторном merge] → версионированный контракт, проверка ссылок и конфликтов, round-trip и повторная маршрутизация из собственных наборов.

## Migration Plan

Реализовать после контракта tag_sets. Сначала расширить данные и геометрию с адаптером старого формата, затем каскадное исполнение, маршрутизацию, UI/конфиги и пример body/face/eyes. Новая ветка опциональна; старые workflow и notebook-вызовы сохраняются. Откат — прежний плоский workflow; сохранённые raw не уничтожаются. Потребитель старой версии не обязан читать новый иерархический формат, что отмечается в документации.
