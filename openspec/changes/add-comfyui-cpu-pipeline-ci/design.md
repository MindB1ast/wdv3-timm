# Дизайн

## Контекст

`audit/run_saved_workflow_regressions.py` загружает и вызывает Python-ноды напрямую и использует локальные входы и веса. Это полезный эталон, но не проверка очереди, валидации и выполнения графа сервером ComfyUI. Для трёх новых сценариев использовать реальные ноды из проверяемого checkout и существующий каскад `Region Tag Rules` (`child_sam_model`, `child_sources`).

## Цели и границы

- Проверить детекции, сегментацию и перенос координат дочерней маски в исходный кадр на стандартном Linux-раннере с CPU.
- Не менять схемы нод, существующие эталоны, автоматический CI и планы прямого экспорта масок. Использовать уже доступный путь сохранения масок через отчёт; отсутствие UI не исключает выполнение backend-ноды `Inspect`, если она нужна этому пути.

## Решения

- `workflow_dispatch` принимает `all` (по умолчанию) или один из трёх идентификаторов. Каждый выбранный сценарий получает отдельный раннер и вердикт; ошибка одного не отменяет остальные. Маленький манифест в `audit/` связывает идентификаторы с API-графами, входами, весами, проверками и таймаутами. Не принимать произвольные URL и пути из формы GitHub.
- Закрепить ревизию ComfyUI, совместимые CPU-зависимости и версии/хэши модельных файлов. Использовать `unsloth/sam3.1`; YOLO выбрать из публичных весов с проверенной лицензией и классом для контрольного кадра. Если `Tag Image / Regions` или `Collect Evidence` требуют WD для выполнения графа, зафиксировать публичные веса WD как вспомогательную зависимость, не добавляя четвёртый сценарий.
- Использовать маленький контролируемый вход из Git с ожидаемым объектом. Сравнивать смысловые инварианты, а не точные float-значения или байты полного отчёта: YOLO выдаёт ожидаемый класс и bbox в кадре; SAM выдаёт непустую маску размера исходного кадра; каскад дополнительно выдаёт дочернюю SAM-маску и связь с YOLO-родителем, а ненулевые пиксели лежат в пределах входного bbox родителя. Подобрать кадр с родительским bbox меньшим полного кадра, чтобы тест различал локальные и глобальные координаты.
- Запустить ComfyUI с `--cpu` на `127.0.0.1`, проверить готовность API и регистрацию нод, отправить `POST /prompt`, дождаться терминального результата через `GET /history/{prompt_id}`. Хранить входы, выходы и логи в изолированном каталоге раннера. Ошибка API, таймаут, нехватка памяти, отсутствие весов или несоответствие результата завершают сценарий ошибкой.

## Риски и компромиссы

- Доступ к весам и совместимость версий могут отличаться от локальной установки. Проверить скачивание без токена из чистого окружения; недоступный реальный checkpoint не заменять заглушкой.
- Установка, скачивание и инференс конкурируют за время, диск и память. Для первого холодного прогона логировать этапы, время и пиковое суммарное потребление памяти ComfyUI и дочерних процессов; измерения использовать для решения о дальнейшей автоматизации.

## Публикация

Сначала проверить графы и запуск локально. После согласованного пуша в ветку по умолчанию запустить `all` через GitHub Actions и сообщить результаты по каждому сценарию. Если запуск не укладывается в ресурсы, показать этап и причину, не включать сценарии на push.
