## Purpose

Предоставлять будущим этапам тегирования и объединения описаний проверяемые сведения о ранее встреченных тегах с сохранением версий и происхождения.

## ADDED Requirements

### Requirement: Содержимое записи тега
Запись MUST содержать идентификатор и название тега, описание, инструкцию объединения, примеры изображений, направленные импликации, похожие теги и версию. Отсутствующие сведения MUST отмечаться явно, без выдуманных значений.

#### Scenario: Частично изученный тег
- **WHEN** сохранён тег с описанием, но без примеров
- **THEN** запись явно сообщает об отсутствии примеров и остаётся доступной для последующего дополнения

### Requirement: Версии и происхождение знаний
Обновление MUST создавать различимую версию записи. Потребитель MUST получать версию и происхождение используемых сведений; ранее использованная версия MUST оставаться доступной для объяснения результата.

#### Scenario: Уточнение инструкции
- **WHEN** инструкция объединения изменена после формирования описания изображения
- **THEN** прежнее описание сохраняет ссылку на использованную версию, а новый запрос может получить обновлённую запись

### Requirement: Направление импликаций и сходство
Система MUST различать отношение «конкретный тег подразумевает общий» и сходство тегов. Обратный обход импликаций MUST возвращать возможные конкретизации, не доказывая их наличие на изображении. Похожий тег MUST NOT автоматически считаться импликацией.

#### Scenario: Общий тег не доказывает частный
- **WHEN** известна связь частного тега A с общим B и изображению назначен только B
- **THEN** A доступен как кандидат для исследования, но не назначается на основании одной этой связи

### Requirement: RAG-контекст с явным отсутствием ответа
Система MUST предоставлять найденные записи как контекст для этапов получения и объединения тегов, включая описания, инструкции, примеры, связи и версии. Результат MUST отличать отсутствие подходящих сведений от ошибки поиска.

#### Scenario: Нет подходящего конкретного названия
- **WHEN** запрос об области не находит подходящих сведений
- **THEN** потребитель получает явный результат отсутствия ответа, пригодный для передачи агенту внешнего поиска

#### Scenario: Ошибка хранилища
- **WHEN** поиск не выполнен из-за недоступности хранилища
- **THEN** результат сообщает ошибку, а не утверждает, что нужного тега в базе нет
