# Версионированная база знаний и RAG для тегов

## Why

Теггер может пропускать конкретное название видимой детали. Повторно используемые сведения о ранее встреченных тегах нужны будущим этапам получения тегов и объединения описаний.

## What Changes

- Хранить название и описание тега, инструкцию объединения, примеры изображений, направленные импликации, похожие теги и версию записи.
- Предоставить RAG-доступ к записям с происхождением и версиями; отсутствие подходящего результата передавать отдельным исходом.
- Различать импликацию и сходство; поддержать поиск конкретизаций по обратному обходу импликаций.
- Детали поиска пользователь уточнит перед реализацией.

Это отложенное направление разработки. Текущий запрос оформляет планы; реализация не начата. Общая оптимизация пайплайна получения тегов и этапа объединения — контекст будущего оркестратора, а не дополнительные задачи этого change.

## Capabilities

### New Capabilities

- `versioned-tag-knowledge`: Версионированная база знаний и RAG для тегов.

### Modified Capabilities

Нет. Новая возможность дополняет целевую regional-tag-optimization, сохраняя её требования к областям, исходным свидетельствам и происхождению.

## Impact

Новый модуль знаний и интерфейс для будущих агентов. Scripts/tag_manager.py сейчас редактирует подписи, а планируемая structured-result-storage хранит результаты изображений: ни один не заменяет базу знаний. Формат БД, индексы, embeddings и интеграция с хранением assets пока не выбраны.

Не входят обучение моделей, реализация общего оптимизатора и изменение текущих тестов основных функций. Перед реализацией нужно уточнить открытые решения в design.md.
