# Design

## Context

RegionViewConfig и prepare_region_view уже поддерживают px/fraction и background_rgb, но обрезают окно по границам. В SAM mask применяется прямоугольная дилатация видимой маски, исходная маска не меняется. ComfyUI SAMSource выставляет только padding_px, YOLO не имеет общего блока. Каскад отделяет исходный bbox от WD crop и использует первый для дочерней детекции.

## Goals / Non-Goals

**Goals:** единые настройки WD-подготовки, предсказуемый размер у края, общий цвет SAM и заливки, совместимость старых графов.

**Non-Goals:** изменение детекторных bbox/исходных масок, padding дочернего поиска, автоматическое удаление фоновых тегов, изменение схемы хранения результатов.

## Decisions

### Контракт и совместимость

Добавить в Region Tag Rules optional wd_view_enabled=false, padding_unit=px/percent, padding_value=0, background_color=#FFFFFF. Включённый блок задаёт подготовку данного источника; для SAM view_mode остаётся в SAMSource. Legacy padding_px используется только при выключенном новом блоке. При включении блока подсказка сообщает приоритет новых настроек. Pixel value и percent допускают дробные числа с округлением вверх; принимать только finite>=0. Цвет строго #RRGGBB, внутри RGB uint8. Перед выделением памяти проверять целевые размеры и лимит площади, сообщать ошибку вместо обрезания пользовательского padding.

Новые параметры нормализовать в версионированный wd_view; алгоритм edge_policy=redistribute различается от legacy clip. Старые fingerprints и входные пиксели без нового блока не менять. Проверить фильтрацию служебных полей при построении SAM detector identity в comfy_cascade.py: подготовка относится к WD, не SAM-поиску.

### Геометрия окна

По каждой оси: p=ceil(value) для px, p=ceil(length*value/100) для percent; desired=length+2p, nominal_start=bbox_start-p. Если desired<=image_length, start=clamp(nominal_start,0,image_length-desired), конец=start+desired. Это переносит недостающий отступ на доступную сторону. Если desired>image_length, вставить всё изображение в полотно desired; положение вставки задаётся start=clamp(nominal_start,image_length-desired,0). Так сохраняется номинальное положение области насколько возможно, а выход за изображение становится заливкой. Осевые расчёты независимы. Сохранить signed desired window, clipped source window, destination offset, requested padding и реальные цветные поля.

В bbox-mode копируются реальные пиксели всего окна. В mask-mode сначала получить visible mask прежней дилатацией на p_x/p_y, затем перенести её и изображение тем же transform; пиксели вне visible и за исходным изображением залить одним RGB. Исходная бинарная маска сохраняется отдельно. Следовательно padding может открыть реальный контекст вокруг маски, но не превращает весь прямоугольный crop в bbox-mode.

### Пайплайн и наблюдаемость

Провести параметры через плоский YOLO/SAM и каскад, не меняя вход дочернего детектора. Геометрия переиспользуется, WD regional identity включает версию подготовки/окно/цвет/маску. При наличии сохранённых исходных пикселей/масок новая подготовка требует нового WD-прогона, но не новой YOLO/SAM-детекции. Reuse_only сообщает missing WD, не выдаёт старые оценки за новые.

Inspect сейчас может показывать обычный bbox crop; добавить отдельный WD input preview до resize/normalization модели. Он строится тем же prepare_region_view, не отдельной имитацией; при отсутствии исходных пикселей показывать недоступность вместо неверного preview. Report сохраняет его отдельным asset. Документация отличает исходную геометрию, видимую маску и подготовленный вход.

## Risks / Trade-offs

- [Слишком большой процент расходует память] → проверка размеров/площади до allocation с явной ошибкой.
- [Заливка провоцирует background-тег] → общий цвет настраивается, WD input виден; исключения тегов пользователь задаёт сам.
- [Смена padding ошибочно переиспользует WD] → отдельная identity view, проверки invalidation и legacy golden.
- [Новый preview показывается как исходная маска] → отдельные названия/метаданные и assets.

## Migration Plan

Аддитивные optional поля, новый блок выключен для старых графов. Для новой функциональности пользователь включает блок у нужного источника. Откат — выключить блок и вернуться к legacy SAM padding_px. Конфиги нового режима на старом backend должны отклоняться, а не менять семантику молча.
