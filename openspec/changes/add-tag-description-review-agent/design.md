# Предварительный дизайн

## Context

Будущая система разделяет получение тегов и объединение описаний. В проекте есть региональные свидетельства и аналитика тегов, но они сами по себе не дают описанный здесь цикл генеративной проверки. Мотивация — в proposal.md.

## Goals / Non-Goals

Цель — отдельный проверяющий с прослеживаемыми замечаниями. Не входит доказательство полноты по одной генерации, обучение генератора или автоматическая подмена исходных тегов.

## Decisions

- Сначала сопоставлять оригинал с текстом, затем использовать генерацию как дополнительное визуальное свидетельство. Альтернатива — оценка только различия двух изображений — смешивает пропуски и ошибки генератора.
- Разделить генератор, VLM-сравнение и формирование отчёта через заменяемые адаптеры.
- Сохранять исходные теги и фактический prompt, чтобы видеть потери при преобразовании описания для генератора.
- Категории вывода: предполагаемый пропуск, противоречие, ограничение генератора, неопределённость. Это основания для дальнейшей проверки, а не обещание безошибочной атрибуции.
- Возможные контролируемые проверки: несколько seeds, сравнение исходного и уточнённого prompt, контрольные примеры с известными признаками. Это варианты для будущего эксперимента, не утверждённый алгоритм или фиксированное число генераций.

## Risks / Trade-offs

- Генератор игнорирует уже указанный признак → проверка текста, контрольные прогоны и допустимая неопределённость.
- VLM ошибается или разделяет смещения генератора → проверенный набор примеров и отдельная оценка качества проверяющего.
- Стоимость множества генераций → бюджет проверки и явный статус незавершённости.
- Случайная вариативность композиции → сравнение существенных признаков, а не требование совпадения пикселей.

## Migration Plan

Добавить опциональный этап отчётности поверх сохранённого результата. Отключение проверки не изменяет исходные теги. Предложения исправлений передаются соответствующим этапам получения и объединения.

## Open Questions

Перед реализацией выбрать генератор/VLM, способ подачи областей и контекста, критерии существенных различий, контрольный набор, бюджет и метод разделения причин ошибки. Генеративная проверка — выбранное направление исследования; её надёжность ещё нужно подтвердить. План предварительный, после эксперимента уточнить спецификацию и задачи.
