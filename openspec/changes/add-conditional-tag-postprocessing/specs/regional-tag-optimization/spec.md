## ADDED Requirements

### Requirement: Условное удаление внутри выбранного набора тегов
Система MUST поддерживать необязательные правила с уникальным идентификатором, условиями `all_of`, `any_of`, `none_of` и действием `remove`. Условия MUST проверяться по принятым general/character-тегам одного выбранного набора; удаление MUST действовать только внутри него. Исходные оценки, геометрия и ratings MUST сохраняться.

#### Scenario: Фартук подавляет платье
- **WHEN** в одном регионе приняты `apron, dress` и включено правило `all_of: [apron]`, `remove: [dress]`
- **THEN** из принятого набора региона удаляется `dress`, сохраняется `apron`, а вероятность исходного `dress` остаётся доступной отдельно

#### Scenario: Признак только в соседней области
- **WHEN** левый регион содержит только `apron`, а правый только `dress`
- **THEN** правило не удаляет `dress` правого региона и не объединяет условия из разных регионов

#### Scenario: Предсказание ниже порога
- **WHEN** `apron` есть в raw_scores, но не прошёл локальный порог
- **THEN** он не активирует условие по принятым тегам

### Requirement: Буквальный синтаксис условных правил
Имена условий и удаляемых тегов MUST сопоставляться полностью, с канонизацией пробелов/`_`. Непустой `all_of` MUST требовать все перечисленные теги, `any_of` — хотя бы один, `none_of` — отсутствие всех перечисленных. Все заданные группы MUST выполняться одновременно. Операция MUST NOT выполнять regex, произвольный код или неявное сопоставление подстрок.

#### Scenario: Сочетание условий
- **WHEN** правило задаёт `all_of: [apron]`, `any_of: [dress, skirt]`, `none_of: [transparent_apron]`, `remove: [dress]`
- **THEN** оно срабатывает только при принятом apron, хотя бы одном dress/skirt и отсутствии transparent_apron в том же наборе

#### Scenario: Не связанное составное имя
- **WHEN** условие содержит `apron`, а в наборе присутствует только другое полное имя со словом apron
- **THEN** условие не считается выполненным

### Requirement: Детерминированный снимок условных удалений
Все правила одной операции MUST проверяться по одному входному снимку и применять объединение удалений одновременно, без повторения до устойчивости. Порядок правил MUST NOT менять выход. Последовательность самостоятельных операций MUST иметь явный порядок, в котором следующая операция получает результат предыдущей.

#### Scenario: Удалённый свидетель другого правила
- **WHEN** вход содержит `apron, dress, skirt`, правило A удаляет dress при apron, а правило B удаляет skirt при dress
- **THEN** одна операция удаляет dress и skirt по входному снимку независимо от порядка A/B; история B указывает dress во входе операции

#### Scenario: Противоположные удаления
- **WHEN** вход содержит a и b, а правила одной операции удаляют b при a и a при b
- **THEN** оба тега удаляются за один проход без цикла, восстановления тегов или зависимости от порядка

### Requirement: Валидация и происхождение условных решений
Ошибочная схема, повтор идентификатора, пустое действие, отсутствие непустых условий и заведомое противоречие `all_of`/`none_of` MUST отклоняться до применения операции. Для удалений MUST сохраняться все сработавшие rule ID, условия и входные свидетельства с идентичностью кадра/источника/региона. Повторная настройка MUST NOT изменять raw или запускать модели.

#### Scenario: Противоречивые условия
- **WHEN** один канонический тег указан и в all_of, и в none_of одного правила
- **THEN** конфигурация отклоняется с идентификатором правила без частичного изменения набора

#### Scenario: Несколько причин
- **WHEN** два правила удаляют один тег
- **THEN** тег удаляется один раз, а обе причины сохраняются в воспроизводимом порядке
