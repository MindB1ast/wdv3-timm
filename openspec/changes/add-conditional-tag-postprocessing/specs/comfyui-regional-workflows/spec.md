## ADDED Requirements

### Requirement: Самостоятельная операция условных правил
ComfyUI MUST предоставлять отдельную ноду условных удалений между локальной фильтрацией и merge. Нода MUST принимать и возвращать наборы тегов с региональными привязками и позволять явно выбрать full/regions/all и список региональных источников. Начальный выбор MUST быть regions; пустой список правил MUST означать отсутствие изменений.

#### Scenario: Условие для одежды
- **WHEN** правило apron/dress включено только для регионов clothes
- **THEN** отдельные регионы clothes проверяются независимо, а full и другие источники не меняются

#### Scenario: Полный кадр выбран отдельно
- **WHEN** пользователь выбирает full и в нём приняты apron и dress
- **THEN** правило удаляет dress только из полного кадра; dress в регионах сохраняется

### Requirement: Условные удаления не заменяют политику merge
После условной операции система MUST сохранять прежний формат общего caption и отдельно применять владение, композицию, подтверждение и отсечение полного кадра. Локально удалённый тег MUST NOT автоматически запрещаться во всех остальных источниках или восстанавливаться из raw той же области при merge.

#### Scenario: Платье другого персонажа
- **WHEN** dress удалён из одного региона с apron, но принят в другом регионе и разрешён его политикой
- **THEN** dress может присутствовать в общем caption с происхождением из второго региона, а история первого удаления сохраняется

### Requirement: Перенос и ранняя проверка условных операций
Workflow и конфиг постобработки MUST сохранять правила и их идентификаторы, порядок операций, scope и источники. UI и API MUST давать одинаковый результат без frontend-callback. Постоянные ошибки схемы MUST проверяться до исполнения графа. Существующие графы без условной операции MUST сохранять прежнее поведение.

#### Scenario: Ошибка до моделей
- **WHEN** нода содержит некорректный JSON или противоречивое правило
- **THEN** штатная проверка ComfyUI отклоняет проблемную ветку до загрузки моделей и сообщает индекс/идентификатор правила

#### Scenario: Повторное открытие
- **WHEN** пользователь сохраняет workflow с правилом apron/dress для clothes и открывает его снова
- **THEN** восстанавливается та же условная операция, независимо от других настроек генерации

### Requirement: Просмотр и повторное применение условий
Inspect MUST показывать входные и выходные теги операции, сработавшие условия и причины удалений отдельно для каждого набора. Итоговый JSON MUST сохранять эту историю. Изменение условий MUST пересчитывать только постобработку и merge при доступных прежних исходных оценках.

#### Scenario: Изменение правила без инференса
- **WHEN** пользователь меняет remove с dress на skirt при прежних evidence
- **THEN** модельные вызовы не выполняются, локальные наборы и общий caption пересобираются, а исходные оценки остаются прежними

#### Scenario: Совместимость ветвей
- **WHEN** Merge Results получает результаты с разными условными цепочками
- **THEN** несовместимость явно отклоняется; одинаковые цепочки воспроизводятся без потери локальных удалений
